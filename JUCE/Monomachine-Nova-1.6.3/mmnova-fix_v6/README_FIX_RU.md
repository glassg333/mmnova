# Monomachine Nova 1.6.3 — правка v6 (подробно)

Правка ставится поверх дерева **1.6.3**, в котором уже есть v5 (реальный фильтр основным
режимом). Работает с обоими проектами: `Monomachine_Nova_Synth` и `Monomachine_Nova_FX`.

```
python fix_filter_v6.py "E:\mm\Monomachine-Nova-1.6.3" --check   # посмотреть, что будет
python fix_filter_v6.py "E:\mm\Monomachine-Nova-1.6.3"          # применить (24 правки)
python verify_fix_v6.py "E:\mm\Monomachine-Nova-1.6.3"          # проверить результат
```

Повторный запуск ничего не портит: второй прогон пишет «внесено правок: 0, уже было: 24».
Оригиналы сохраняются рядом как `*.bak-v6`.

## 1. BBOX: вернули старый движок в новую оболочку

### 1.1. RTIM — старый закон 5…255 мс, но инвертированный

Было (в 1.4–1.6.3):

```cpp
float retrigMs = 255.0f * std::pow((127.0f - rtim) / 126.0f, 2.0f);   // 259 … 0 мс
m_retrigIntervalSamples = std::max(size_t(1), retrigMs/1000 * sr);
```

На `rtim = 127` интервал становится **0 мс**, то есть 1 сэмпл: повтор срабатывает
почти каждый кадр, `m_hitAge` сбрасывается, фейд в начале удара не успевает
сложиться → на выходе тишина. Отсюда и «после 100 эффект выключается», и щелчки
на границах.

Стало (v6):

```cpp
float retrigMs = 5.0f + ((127.0f - static_cast<float>(rtim)) / 127.0f) * 250.0f;  // 255 … 5 мс
```

Это **старая формула из 1.0/1.3.1** (`5 + 250·rtim/127`), только перевёрнутая,
как ты и просил: `rtim = 127` — самый частый повтор. Интервал никогда не 0.

| rtim | 1.6.3 (было) | v6 (стало) |
|---|---|---|
| 0 | 259.1 мс | **255.0 мс** |
| 1 | 255.0 мс | **253.0 мс** |
| 100 | 11.7 мс | **58.1 мс** |
| 110 | 4.6 мс | **38.5 мс** |
| 120 | 0.77 мс | **18.8 мс** |
| 127 | 0.02 мс (фактически 1 сэмпл) | **5.0 мс** |

Затухание серии повторов оставлено из новой версии:
`gain = 10^(-0.75 · counter/total)` (первый повтор при `RTRG=1` — ровно −15 дБ,
длинная серия затухает плавно).

Измерено на синусе 220 Гц, `RTRG=127` (энергия выхода за 20000 сэмплов):

| rtim | было | стало |
|---|---|---|
| 100 | 3890 | 5814 |
| 120 | 242 | 4612 |
| 127 | **44.6 (звука нет)** | **2186 (звук на месте)** |

### 1.2. Клик на перезапуске — сглаживание ПО СЭМПЛАМ

Было: `fadeFrames = sr*0.0005` (≈22 сэмпла), и позиция сэмпла перепрыгивала на
начало без спада — на синусе это давало скачок на выходе.

Стало:

* `kDeclickSamples = 16` (16 сэмплов = 0.36 мс при 44.1 кГц) — сглаживание задано
  **в сэмплах**, не в миллисекундах;
* короткий фейд в начале удара;
* спад перед перезапуском, который доходит **ровно до нуля** к моменту перезапуска
  (счётчик `samplesToRestart`);
* `declick` автоматически укорачивается, если интервал повтора меньше `2·declick`.

Максимальный скачок на выходе (синус 220 Гц, амплитуда 0.8; натуральный шаг того же
синуса 0.025):

| rtim | было | стало |
|---|---|---|
| 100 | 0.3368 (13× натурального) | 0.0505 (2.0×) |
| 120 | 0.6876 (27×) | 0.0448 (1.8×) |
| 127 | 0.0074 (потому что тишина) | 0.0448 (1.8×) |

### 1.3. STRT (start position)

Смещение считалось как `x²·min(0.25·активная_длина, 30 мс)`. Для коротких ударов
четверть длины — это уже «отрезать атаку». Стало `x²·min(0.125·активная_длина, 30 мс)`
(1/8), предел 30 мс сохранён.

### 1.4. Кит: старый + новый снейр и два тома

Рабочий кит (`generateDefaultDrumKit`, он же кит по умолчанию) собран так:

* **основа — старый кит** (до реворка 1.4): кик (Bass Drum 1 и 2), клэп, райд/крэш,
  хэты, колокол `Cow Bell` (слот 8), `Whistle` (слот 23), лазер/zap `Blipp` (слот 24),
  таймбал, тимпани, вуд, треугольник, шейкер, маракас — всё как было;
* **из нового кита взяты только три голоса**, которые понравились: `Snare Drum 1`
  (слот 2), `Tom 1` (слот 3), `Tom 2` (слот 4). Переключатель — таблица
  `modernVoice[24]` прямо в коде (три `true`), так что видно, что откуда;
* `Snare Drum 2` (слот 14), Timbale (15), Timpani (17) не тронуты — остались старыми.

Проверено счётно: PCM колокола (слот 8) и лазера/Blipp (слот 24) в старом ките и в
рабочем ките совпадают **бит-в-бит**, кик/клэп/райд/тимпани/таймбал тоже совпадают
со старым китом, а снейр и два тома отличаются (то есть перенос действительно
произошёл). Полностью старый кит остался доступным как `generateLegacyKit()` —
например для A/B и для тестов.

## 2. Хорус и FX — как в 1.6.0

В 1.6.3 поверх 1.6.0 были дописаны «FIXED»-правки. Они убраны:

* **INP снова линейный** (`p[7]/64`) для всех FX — как в 1.6.0, вместо квадратичного
  закона `(INP/64)²` (он менял всю громкость FX-трека: на 127 это +12 дБ вместо +6 дБ);
* **убрано домешивание хоруса ×1.5** — громкость wet-сигнала больше не «подкрашивается»;
* **убрано домешивание ревербератора ×3.0**;
* удалены служебные комментарии «FIXED: …» из кода.

Про микс хоруса (ваш вопрос): **в 1.6.0 никакого внутреннего переключения
original → full wet не было.** Была и есть одна строка непрерывного блендинга:

```cpp
const float wet = norm(p[3]);
l[i] = dl*(1-wet) + wl*wet;   // dl/dr -- задержанный сухой вход, wl/wr -- выход ядра
r[i] = dr*(1-wet) + wr*wet;
```

`MIX = 0` — сухой (задержанный на латентность ядра) сигнал, `MIX = 127` — полностью
wet, между ними плавно. В v6 эта строка ровно такая, как в 1.6.0; ядро хоруса
(`ChorusCore.*`, `AudioAdapter.*`, `monomachine_chorus.hpp`) вообще не тронуто — оно
diff-0 между 1.6.0 и 1.6.3.

## 3. Чистка режимов: осталось два — `mnm` и `old`

Удалены вместе с кодом (файлы переименованы в `*.bak-v6`, ссылки сняты):

| что | файл | где использовалось |
|---|---|---|
| `dist2` | `dsp/mnm/MnmDist2.hpp` (`Dist2Core`) | режим DIST |
| `fm2` | `dsp/mnm/MnmFm2.hpp` (`FMPlusBlock2`) | режим SYNT |
| `bbox2` | `dsp/mnm/MnmBbox2.hpp` (`Bbox2Core`) | режим SYNT (повтор-сэмпл) |

Итоговое меню режимов (`models/DspModes.hpp`):

| раздел | режимы |
|---|---|
| SYNT | `mnm` (ядро FM+ прошивки), `old` (прежний Nova FM) |
| AMP | `mnm` (kernel ADSR), `old` |
| **FILT** | **`mnm` = реальный фильтр из дампа прошивки**, `old` (прежнее приближение) |
| DIST | `mnm` (ALU-сатурация прошивки), `old` |
| DLY | `mnm` (m32 FX-DLY), `old` |
| ROUTE | `mnm` |
| CHOR | `mnm` |

То есть новые режимы теперь есть **только у фильтра** — как и договаривались.
Старые состояния читаются: схема состояния 9 → 10, любой прежний индекс режима
(`2/3/4`, `5/6/7` и т. п.) сводится к основному `mnm` (`dspModeLegacyIndexToCurrent`),
поэтому ничего «не повиснет» на удалённом режиме.

## 4. Попутно найденный баг: ревер ронял плагин

В ветке ревербератора (FX-машина 13) стояло

```cpp
std::array<float,32> dryL{},dryR{};std::copy_n(l,n,dryL.data());std::copy_n(r,n,dryR.data());
```

а `render()` вызывается с полным блоком хоста (обычно 512 сэмплов). Это переполнение
стека — падение/порча памяти при включении ревера. Так было и в 1.6.0, и в 1.6.3.
В v6 буферы живут в членах класса и растут под размер блока (`rvDryL`, `rvDryR`);
после прогрева аллокаций нет.

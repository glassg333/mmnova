# FM FIX — карта UI-значений

Этот файл фиксирует именно то, что должно быть видно на лицевой панели после
исправления изоляции UI. Он не добавляет новый dropdown и не меняет сохранённые
0..127 параметры: FM-регуляторы остаются raw-ручками, а LCD/readout показывает
соответствующее значение.

## Когда эти надписи применяются

Только у FM+ m8 STAT, m9 PAR и m10 DYN при machine-local `MODE SYNT`:

- `mnm fix` — raw mode `3`;
- `new fix` — raw mode `4`.
- `old fix` — raw mode `5` (separate OLD m9/m10 renderer topology/state with measured controls; appended to keep NEW FIX=4 stable).

При `mnm` (`0`), `old` (`1`) или `new` (`2`) измеренные FIX-названия **не
рисуются**. Эти три retained режима сохраняют собственные прежние
readout'ы для честного A/B: m8/m9 используют `getFmListedRatio(raw/4)`, m10
использует исходные `v/16` и `pow(2,(v-32)/24)`, а TUNE остаётся `raw-64`.
Это важно: ранее DSP уже был изолирован, но UI ошибочно показывал
FIX-значения в retained режимах; простая подмена на raw `0..127` также не
является корректным восстановлением. Полный literal extract находится в
`FM_RETAINED_READOUT_ROUTES_2026-09-28.md`.

## FIX factory profile — только явное действие

Профили `3C 40 50 1E 50 40 62 40` (STAT),
`3C 40 50 40 66 50 62 40` (PAR) и
`40 40 40 40 4A 50 1E 40` (DYN) **не являются** новыми общими defaults.
Иначе fresh/reset `mnm`, `old` и `new` меняли бы ручки и звук. При активном
`mnm fix`, `new fix` или `old fix` откройте DSP MODE → SYNT и выберите
`LOAD FIX FACTORY RAW VALUES (explicit)`, если именно этот профиль нужен.
Без явного действия никакие raw параметры не переписываются.

## Уровень NEW / NEW FIX

Только после raw-core `new` и `new fix` применяется явный host bridge
`+10.0 dB` (`×3.1622776601683795`). Это не меняет байты imported exact-core и
не применяется к `mnm`, `old`, `mnm fix` или `old fix`.

## m8 STAT / m9 PAR — 1FRQ, 2FRQ, 3FRQ

Единственный числовой источник — Q23 `kStatParRatioWord` в
`Source/dsp/fm_fix/FmFixTables.hpp`. MNM FIX получает float как
`word / 2^19`; NEW FIX получает pointer на те же words. Строки ниже — только
подписи одного и того же списка.

| table slot | raw K | LCD | Q23 word |
|---:|---:|---|---:|
| 0 | 0–4 | 1/64 | 0x002000 |
| 1 | 5–10 | 1/32 | 0x004000 |
| 2 | 11–15 | 1/16 | 0x008000 |
| 3 | 16–20 | 3/32 | 0x00C000 |
| 4 | 21–26 | 1/8 | 0x010000 |
| 5 | 27–31 | 3/16 | 0x018000 |
| 6 | 32–36 | 1/4 | 0x020000 |
| 7 | 37–42 | 5/16 | 0x028000 |
| 8 | 43–47 | 3/8 | 0x030000 |
| 9 | 48–52 | **5/32** | 0x014000 |
| 10 | 53–58 | 7/16 | 0x038000 |
| 11 | 59–63 | 1/2 | 0x040000 |
| 12 | 64–68 | 5/8 | 0x050000 |
| 13 | 69–74 | 3/4 | 0x060000 |
| 14 | 75–79 | 7/8 | 0x070000 |
| 15 | 80–84 | 1 | 0x080000 |
| 16 | 85–90 | 1.25 | 0x0A0000 |
| 17 | 91–95 | 1.5 | 0x0C0000 |
| 18 | 96–100 | 1.75 | 0x0E0000 |
| 19 | 101–106 | 2 | 0x100000 |

Необычный порядок `3/8 → 5/32 → 7/16` намеренно literal: его нельзя
«нормализовать» в возрастающий список. Индекс: `floor((K + 0.5) * 3 / 16)`.
Поэтому STAT defaults raw `1FRQ=60` и `2FRQ=80` показывают `1/2` и `1`.

## m10 DYN — 1FRQ / 2FRQ

Только в двух FIX режимах:

```text
1FRQ = K / 64
2FRQ = (K / 64)^2
```

LCD показывает точные удобные дроби на известных anchor raw-значениях (например,
`1FRQ K=1 → 1/64`, `K=16 → 1/4`, `K=32 → 1/2`; `2FRQ K=8 → 1/64`,
`K=16 → 1/16`, `K=32 → 1/4`, `K=64 → 1`). Между anchor'ами показывается
число, рассчитанное по той же формуле. Retained m10 modes не получают эти FIX
надписи.

## m8/m9/m10 TUNE

Только в `mnm fix`/`new fix`/`old fix` LCD показывает semitone bridge:

```text
raw 0   -> -2.000
raw 64  ->  0
raw 127 -> +1.969   (точно +63/32 = +1.96875)
```

Это UI/readout исправление для measured FIX scope. Оно не переписывает raw
сохранённые значения и не меняет retained `new` bridge.

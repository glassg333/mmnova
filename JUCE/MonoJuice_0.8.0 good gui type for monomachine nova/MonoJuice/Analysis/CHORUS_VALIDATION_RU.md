## Независимое сравнение процедуры

24 576 блоков × 16 стереокадров = **393 216 кадров**.

Сравнивались 32 выходных слова, 96 слов состояния и 4 096 слов кольцевой памяти после каждого блока:

```text
Compared 103809024 words; mismatches=0
Reference golden FNV-1a-64=7007ca4d75708b0f
```

Входы: импульсы, детерминированный псевдослучайный сигнал, все значения каждого параметра, переключение всех параметров между крайними значениями и полнодиапазонный PCM24.

Эталон исполнял **исходные бинарные инструкции**, не C++-перенос. Таблицы для эталона читались из снимка памяти загруженной исходной ОС, а не из `ChorusTables.h`. Поправка к режиму SM отладочного интерпретатора описана в `TECHNICAL_RU.md` и приложена отдельно. Без оговорки о ней нельзя честно называть эту проверку совпадением с неизменённым upstream-эмулятором.

В `tests/ChorusTests.cpp` сохранён регрессионный тест с этим независимым контрольным значением. Он запускается без JUCE и без эмулятора. Хешируется последовательность выходных PCM24-слов, по три младших байта little-endian на слово.

## Реальное влияние регуляторов

RMS разности двух рендеров с соответствующим параметром 0 и 127; остальные — INIT:

| Регулятор | RMS разности |
|---|---:|
| DEL | 0,0238943 |
| DEP | 0,0268984 |
| SPD | 0,0175836 |
| MIX | 0,0463680 |
| FB | 0,0525568 |
| WID | 0,0146157 |
| LP | 0,0000825944 |
| INP | 0,0555666 |

Небольшая разница LP при FB=0 объясняется его расположением **в возврате обратной связи**, а не заменой wet-сигнала выходным low-pass. Это следует из исходной процедуры.

## JUCE-оболочка

При блоках 1, 7, 16, 31, 127, 512, 3 и 251 сэмпл, повторяемых в тесте:

| Частота | RMS выхода | Заявленная latency |
|---:|---:|---:|
| 44 100 | 0,00991431 | 16 |
| 48 000 | 0,00990954 | 87 |
| 96 000 | 0,00990992 | 139 |

Проверены 9 зарегистрированных параметров: восемь CHORUS и bypass. MIDI не нужен. Состояние успешно восстановлено в другом экземпляре, включая загрузку до `prepareToPlay`.

Скриншот получен непосредственно из JUCE Editor. WAV — результат обработки этим Processor, а не подложенная запись оборудования. В примере WID=96, остальные параметры INIT, частота 44,1 кГц; вход — синтетический тестовый сигнал. Пример не является аппаратным сравнением.

При первом запуске GUI-теста на Xvfb возник `BadAtom` при создании ненужного desktop peer. Тест изменён на штатный offscreen-снимок компонента с обработкой message loop; повторный запуск прошёл. Этот тест не подменяется заявлением об испытании GUI во всех DAW.

## Производительность

Один измеренный release-прогон нативного теста: 393 216 кадров за примерно **0,138 с**, то есть около **1,55% реального времени** для ядра на данном Linux-стенде. Это измерение включает генерацию тестового входа и хеширование, но не весь DAW-проект и не GUI.

Не следует переносить это число на любой компьютер или считать гарантией загрузки CPU в Windows. Для других частот добавляется стоимость SRC. В аудиопути нет запуска ОС, JIT-компиляции, фоновой эмуляции, файлового чтения или динамического выделения памяти.

## Visual Studio

Настоящий Projucer экспортировал оба VS solution. В каждом SharedCode проверены:

- четыре собственных CPP;
- 14 сгенерированных JUCE-обёрток;
- отсутствие отсутствующих локальных компилируемых файлов;
- `stdcpp17` в Debug/Release;
- FX, `IsSynth=0`, `WantsMidiInput=0`.

Путь к вашей JUCE определяется на вашем компьютере после сохранения `.jucer`. Сгенерированные здесь Windows-проекты с чужими путями не выдаются за готовую проверенную MSVC-сборку.

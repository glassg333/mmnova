# Monomachine Nova 1.6.8 — правки по запросу (сентябрь 2026)

Все пункты сделаны сразу в ОБОИХ проектах (Synth и FX). Сборка не запускалась
(по правилу репозитория), но оба `PluginEditor.cpp` и `PluginProcessor.cpp`
проверены `g++ -fsyntax-only` с реальными заголовками JUCE 8 — 0 ошибок,
`verify_dsp_mode_patch.py` — PASS для обоих проектов, `tests/MnmCoreTests` — all OK.

## 1. ARP: квадратные степы вместо фейдеров
`StepLane` переписан: два ряда по 8 ЖИРНЫХ КВАДРАТНЫХ падов 127×127 с зазором
8px (как степ-сек). Верхний ряд — TRANSPOSE (заливка от центра), нижний —
VELOCITY (заливка снизу), в каждом паде — значение цифрами, у держащихся шагов —
жирная «шапка» 4px сверху. Взаимодействие прежнее: тянешь вертикально — меняешь
значение, тянешь в сторону — рисуешь по падам, ПКМ — hold. Слева подписи TR/VEL.

## 2. LFO/MSEG поменялись местами + заголовок LFO без цифры
* Заголовок LFO-панели теперь просто **LFO** (номер страницы виден на кнопках
  [LFO1]/[LFO2]/[LFO3] в шапке).
* Весь блок LFO (панель + кнопки LFO1/2/3) переехал наверх вправо — туда, где
  был MSEG; MSEG (панель + кнопки MSEG/MSEG OUT) — вниз вправо, где был LFO.

## 3. Прицел LFO1/2/3: маршрут всплывает в матрице
`addRouteFromSource` теперь переставляет свежий маршрут на **первую строку
матрицы** (`moveModRoute(slot,0)`), чтобы сразу видеть, что создалось.

## 4. Матрица: сортировка по колонке ON
Заголовки: ON | SOURCE | DESTINATION | DEPTH | MODE. Клик по ON сортирует
(по умолчанию включённые сверху), стрелка-треугольник теперь рисуется пикселями
(старые символы ▼/▲ в пиксельном шрифте не отображались).

## 5. Прицел LFO выбирает ВНУТРЕННИЙ адресат
При наведении во время перетаскивания кнопки LFO1/2/3 сразу выставляются
PAGE (1-й параметр страницы LFO: PTCH|SYNT|AMP|FILT|EFFX|LFO1|LFO2|LFO3) и
DEST (2-й параметр, 0..7) — то есть внутренний адресат, о котором шла речь.
Маршрут в матрице при отпускании по-прежнему создаётся.

## 6. SRR/DSP MODE по ПКМ открывается у курсора
`showDspModes` получил координаты курсора: `withTargetScreenArea(1x1 у курсора)`
вместо привязки к кнопке DSP MODE (которая далеко). Клик по самой кнопке DSP
MODE по-прежнему открывает меню у кнопки.

## 7. RETUNE (repitch) у DTIM — слайдер, а не список
ПКМ на DTIM открывает call-out бокс у курсора со слайдером 0..3
(OFF/FAST/MED/SLOW), значение пишется прямо во время перетаскивания.

## 8. Кракозябры: все подписи UI — английские + проверочная строка
Причина кракозябр: русские тексты хранились как `\xNN` UTF-8-байты, а
`juce::String(const char*)` копирует байты как Latin-1; плюс в пиксельном
шрифте вообще нет кириллицы. Все строки меню DSP MODE и описаний режимов
переведены на английский (models/DspModes.hpp + PluginEditor.cpp).
В конце меню DSP MODE добавлена строка **ENCODING TEST: проверка** — слово
«проверка» специально оставлено в СТАРОЙ сломанной кодировке: если оно
выглядит кракозябрами, а остальной текст читается — всё правильно; если
кракозябры вернулись у английских строк — кодировка снова сломалась.
Пустой файл-проверка: `тест ю кен делит ми иф ю вонт.txt` в корне 1.6.8.

## 9. Режим SYNT запоминается ПО КАЖДОЙ МАШИНЕ
Вместо одного общего `mode_synt` теперь параметры **`mode_synt_m<id>`** —
свой `mnm|old` для каждой машины. Листаешь машины — у одной остаётся old,
у другой mnm. Заголовок SYNT и подменю DSP MODE показывают режим выбранной
машины (в названии подменю — имя машины). Удалить `old` или `mnm` у раздела
целиком — по-прежнему одна строка в `dspSectionModeChoices()` (models/DspModes.hpp).
Схема состояния 10 → **11**: старые состояния наследуют `mode_synt` всем машинам.

## Дополнительно 1.6.8.1 (вторая волна правок)

1. **Страница LFO снова с ручками.** Баг был в bind(): панель 2 ошибочно
   исключалась из привязки -- теперь пропускается только панель 5 (MSEG),
   и LFO-панель снова показывает PAGE/DEST/TRIG/WAVE/MULT/SPD/INTL/DPTH
   выбранного LFO (кнопками LFO1/2/3 в шапке).
2. **Логика кнопок LFO1/2/3:** ЛКМ-перетаскивание = прямой внутренний адресат
   (PAGE+DEST самого LFO, замена текущего адресата на лету при наведении,
   БЕЗ матрицы); ПКМ-перетаскивание = маршрут в матрицу (с всплытием на
   первую строку). Клик ЛКМ -- показать страницу этого LFO.
3. **Кнопки LFO одинаковые и ровные:** 90x24 в одну линию в шапке панели,
   выбранная -- залита (toggle state), а не "[LFO1]" скобками.
4. **DSP MODE -- плоский прокручиваемый список** (длинное меню листается само),
   блоки помечены "FOLDER: ...", вложенные подменю убраны.
5. **REPITCH -- непрерывная шкала 0..3:** 0 = OFF (мгновенно), 1 = FAST,
   2 = MED (дефолт как был), 3 = «лента» ~2.5 с; промежуточные -- линейно.
   Дефолт (2 = MED) не изменился. Под репитчем -- **SMOOTH** (антиклик):
   0 = как было, 127 = самая мягкая доводка ~10 мс при резкой смене длины.
6. Проверочное слово в меню оставлено сломанным НАМЕРЕННО (канарейка).

Проверки: g++ -fsyntax-only (реальные заголовки JUCE 8) -- 0 ошибок в обоих
проектах; verify_dsp_mode_patch.py -- PASS (оба); MnmCoreTests -- all OK.

## ВЕРСИЯ 1.6.12

Номер = 1.6.11 + 1 (правило: каждый патч +1). Обе сборки (Synth и FX) снова
синхронны: все правки зеркалятся в оба проекта.

1. DSP MODE: снова ГРУППИРОВАННЫЕ подменю по папкам (пользователь вернул
   группировку после 1.6.8.1). Раздел -- заголовок, основная реализация,
   группа BACKUP (если включена), строка происхождения раздела, у SYNT в
   заголовке имя машины. Фиксированный ROUTE-подраздел и ENCODING TEST
   (сломанная канарейка "проверка") на месте. Попап открывается у курсора.

2. ARP-страница перестроена:
   - SET больше не пересоздаёт страницу (уходил случайный слайдер и моргание);
   - хитбоксы степов строгие: velocity больше не меняется, когда красишь
     транспозицию (ряд выбирается один раз в mouseDown);
   - ПКМ-драг по степам красит HOLD (инвертируя состояние первого степа);
   - ЛКМ-драг работает во всех списках: CLOCK, MODE, RATE GRID, VELOCITY,
     PAGE (чёрный пиксельный скин DragChoice) и в окошках PAGE LIMIT /
     RANDOM / OCTAVES (DragValueBox: драг = +-1, колесо = +-1, двойной клик =
     дефолт);
   - раскладка: RATE, рядом GATE (слайдер со значением) и OCT; ниже WRAP,
     VELOCITY (ширина списка не больше текста), PAGE LIMIT, RANDOM c кнопками
     PAGE и ALL (тултипы показывают число степей);
   - SYNC на главной = только клок арпеджиатора (не глобальный хост-синк);
     таймер видимости RATE GRID привязан к нему.

3. Матрица: DEST сгруппирован в 7 подменю-страниц (MACHINE/AMP/FILTER/EFFX/
   LFO1..3, по 8 адресатов). Прицел LFO теперь может брать LFO-адресата
   (LFO -> LFO: страницы 1..7).

4. Замки маршрутов и LFO:
   - у каждого маршрута кнопка-замок слева от прицела: ЛКМ = FREE/LOCK,
     ПКМ = меню FREE/LOCK/SOLO; LOCK защищает dest от прицела и перезаписи,
     SOLO приколачивает маршрут к параметру (меняется только руками);
     клик по замку на соло-строке только моргает замком, смены нет;
   - ПКМ по PAGE/DEST на странице LFO открывает панель замков (call-out):
     отметка значения = модуляция его перескакивает (битовая маска,
     sticky), ПКМ по отметке = SOLO значения, клик по значению = задать
     ручке PAGE/DEST это значение, CLEAR LOCKS всё сбрасывает;
   - aftertouch/ручные изменения при SOLO работают, замок сам не снимается.

5. LFO INTL работает по мануалу Monomachine (interlace, "straight from the
   Sidstation"): волна чередуется с нулём, INTL задаёт скорость нулевых
   циклов (1..16 делений), 0 = выкл. Раньше ручка ошибочно трактовалась
   как фазовый сдвиг.

6. BBOX: STRT мягче -- кубическая шкала x^3 с шапкой ~25 мс (1/8 длины
   активной части); деклик адаптивный (2..176 сэмплов от скорости атаки):
   транзиент остаётся, щелчок уходит. Прилегающие ретриг-рестарты тоже
   декликатся.

7. Дилей ping-pong: новый режим MID SAFE (PP MODE в repitch-панели, она
   открывается ПКМ и по DTIM, и по DSND): тапы смешиваются 65/35, середина
   не вычитается. CLASSIC = как в прошивке (моно-вход в левую линию).
   Дефолт -- CLASSIC, звук не меняется.

8. Огибающие: режимы переименованы в "old" (легаси 1.4) и "mnm"
   (бывший REFERENCE FIT, табличные огибающие прошивки) -- в списках AMP
   и ENV; тултип поясняет.

9. Прочее: BACK на главной ровно на месте MATRIX (870,58,140,30); BPM

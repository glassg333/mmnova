# Monomachine Nova 1.6.5 — правки по жалобам на 1.6.4

Дата: 2026-09-19. Обе копии (Synth и FX) идентичны кроме `Source/NovaConfig.h`.

## 1. Крякозябры в меню/тултипах (скрин пользователя)

Причина на вашей машине: MSVC без флага `/utf-8` читает UTF-8 исходники как
локальную кодовую страницу и портит русские литералы ещё в бинарнике.
Лечение в 1.6.5:

* `*.jucer`: в конфигурациях VisualStudio2022 добавлен `extraCompilerFlags="/utf-8"`
  (Debug и Release). **Пересохраните проект в Projucer**, чтобы флаги попали в
  solution.
* `CMakeLists.txt`: для MSVC добавлен `add_compile_options(/utf-8)`.
* Тексты меню/тултипов переписаны начисто (см. ниже), файлы сохранены в UTF-8.
  Заменяйте файлы целиком, а не патчем через сторонние скрипты — прежние
  крякозябры были двойной перекодировкой при таком переносе.

## 2. Категории отладочных DSP перепутаны / описания не там / подчёркивания

`models/DspModes.hpp` переписан:

* У каждого раздела появилась **папка-категория** (`dspSectionCategory`):
  МАШИНЫ (OSC) / АМПЛИТУДА / ФИЛЬТР / ДИСТОРШН+SRR / ДИЛЕЙ / ХОРУС / ЦЕПЬ.
  В меню DSP MODE подменю называются «КАТЕГОРИЯ / РАЗДЕЛ [режим]», первой
  строкой внутри — «ПАПКА: …», чтобы было видно, к чему относится раздел.
* Каждая строка описания теперь начинается с имени СВОЕГО раздела
  (SYNT/AMP/FILT/DIST/DLY/CHOR) — перепутаться категории больше не могут.
* Убраны лишние подчёркивания и «--» в пользовательских строках.

## 3. Подробное описание роутинга при наведении

* `dspRouteDescription()` — человекочитаемое описание цепочки: что делает
  каждый блок (DIST, SRR, FILT+EQ, ENV, DSND), почему порядок именно такой и
  почему при ручках по умолчанию FX не меняет источник (unity).
* Тултип кнопки **DSP MODE** (наведение) теперь группируется по папкам и
  заканчивается этим описанием.
* В меню DSP MODE добавлено подменю «ЦЕПЬ / ROUTE [fixed]» со справкой построчно.

## 4. ROUTE (mnm роутинг) удалён как переключаемый режим

Переключатель ничего не менял на слух (цепочка в коде одна, проверенная),
поэтому по вашему разрешению («если так можно просто удалить mnm роутинг»):

* `dspSectionVisibleInMenu(DspRouting)=false` — раздела больше нет в меню и в
  тултипе; параметр `mode_route` оставлен в состоянии только для совместимости.
* Справка по цепочке — в тултипе и подменю «ЦЕПЬ / ROUTE».

## 5. FX больше не громчит в thru / mnm роутинг тише до unity

Найден корень: mnm-ядро дилея отдавало `out = dry*(1-mix)+wet*mix`, а цепочка
добавляла dry ещё раз — при DSND=0 сухой сигнал удваивлялся (+6 дБ). Теперь
`DelayCore` пишет в линию `вход*send` и отдаёт **чистый wet**; сухой добавлен
ровно один раз. При DSND=0 выход = вход (проверка в MnmCoreTests:
«DLY send=0 wet is silent (unity thru)»).

## 6. Дилей: DSND в mnm починен, клики на DTIM 80–127 убраны, добавлен REPITCH

* DSND в mnm теперь работает как в old: 0 = нет посыла, влево = пинг-понг,
  вправо = стерео (общая логика send/pingPong не менялась, но из-за пункта 5
  ручка наконец слышна предсказуемо).
* Клики при прокрутке DTIM 80–127 были скачком указателя чтения по дискретной
  таблице 1/(n+1). Добавлен slewing длины линии: `dly_repitch`
  (MENU → страница GLOBAL, «DLY REPITCH (debug)»: OFF|FAST|MED|SLOW,
  по умолчанию MED). Плавная смена длины = повторы репитчатся при прокрутке
  времени (ленточный характер), кликов нет; OFF возвращает старое поведение
  для сравнения. Проверки в MnmCoreTests: «teleports the read pointer (click)»
  и «repitch slew keeps the read pointer continuous».

## 7. FM машины: разделены по файлам, fm stat old удалён, fm par old починен

* `dsp/monomachine_fm_stat_par.hpp` разделён:
  `monomachine_fm_par.hpp` (FM+PAR + таблица ratios), `monomachine_fm_stat.hpp`
  (справка), `monomachine_fm_dynamic.hpp` (без изменений). Старый совмещённый
  файл оставлен как `.bak-v7`. Теперь fm stat можно удалять/править, не трогая
  остальные две FM-машины.
* **FM+STAT old удалён** (вы разрешили): машина 8 при любом mode_synt идёт
  через mnm-ядро; в меню SYNT об этом написано честно.
* **FM+PAR old починен**: раньше индекс модулятора жил ~20 мс (декей 0.02 с),
  поэтому 1ENV давал только призвук, а 1FRQ ничем не проявлялся. Теперь у
  огибающих декей 0.25/0.45/0.65 с и устойчивый пол 45% глубины: ENV = глубина
  модуляции (слышна всю ноту), FRQ меняет тембр в любой момент.

## 8. GUI: LFO 1/2/3 одинаковые кнопки, MSEG переехал, модуляция «прицелом»

* Внизу справа три одинаковые кнопки **LFO1 / LFO2 / LFO3** (активная в
  квадратных скобках) — выбирают, какой LFO показан в правой нижней панели.
* Верхняя правая панель (раньше LFO1) теперь **MSEG**: заголовок MSEG, кнопки
  MSEG и MSEG OUT переехали в её шапку, в ячейках быстрые ручки
  RATE / SYNC / LOOP (они не цели модуляции).
* **Модуляция перетаскиванием**: зажмите LFO1/2/3, дотащите до любой ручки и
  отпустите — маршрут назначится сразу (без второго клика, в отличие от
  матрицы). Все ячейки показывают прицел, под курсором — вспышка. Повторное
  перетаскивание на ту же цель перезаписывает существующий маршрут, а не
  плодит новые. Обычный клик по кнопке — просто переключает панель LFO.

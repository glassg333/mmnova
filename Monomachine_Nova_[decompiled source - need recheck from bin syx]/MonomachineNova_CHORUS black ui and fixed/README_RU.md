# MonomachineNova — FX CHORUS

**Версия 0.3.1. Только CHORUS. JUCE / Projucer / Visual Studio.**

Новый небольшой проект, а не сокращённая оболочка предыдущего эмулятора.

## Что внутри

- Нативная статическая трансляция CHORUS из **Elektron OS 1.32B**, извлечённой из BIN исходного репозитория [glassg333/mmmm](https://github.com/glassg333/mmmm).
- Процедуры `P:$147661–$1477DD`: 381 исходное 24-битное слово, 292 инструкции. В C++ сохранены комментарии с адресами каждой инструкции.
- Шесть модулируемых отводов задержки, стереофонические буферы, feedback, LP в цепи обратной связи, оригинальные таблицы и арифметика 24/48/56 бит.
- Восемь настоящих параметров: **DEL, DEP, SPD, MIX, FB, WID, LP, INP**. Автоматизация DAW, редактирование чисел, сохранение параметров и bypass в проекте DAW.
- Чёрно-белый пиксельный интерфейс. **INIT** возвращает параметры к исходным значениям и очищает задержку. **BYPASS** даёт исходный сигнал с компенсацией заявленной задержки.
- VST3 и Standalone; стерео, mono → stereo и mono → mono.

**Не используются** `dsp/monomachine_chorus.hpp`, другие машины из репозитория, Gearmulator, JIT, ColdFire или интерпретатор DSP во время работы плагина. BIN/SYX загружать в плагин не нужно. Полная прошивка не включена.

## Сборка в Visual Studio — основной способ

1. Распакуйте **весь архив в новую папку**, например `C:\AudioDev\MonomachineNova_CHORUS`. Не добавляйте эти файлы поверх старого Synth/FX-проекта.
2. Установите Visual Studio 2022 с компонентом **Desktop development with C++** и Windows SDK. Также предусмотрен экспортёр VS 2019.
3. Откройте **`MonomachineNova.jucer`** в Projucer из вашей установки JUCE 7 или 8. Желательно, чтобы Projucer и модули JUCE были из одной версии.
4. В **Global Paths → JUCE Modules** укажите вашу папку модулей, например `C:\JUCE\modules`. В проекте включено использование глобального пути. Все модули в разделе Modules должны быть найдены.
5. Выберите **Visual Studio 2022** и нажмите **Save Project and Open in IDE**. Projucer создаст `JuceLibraryCode` и solution.
6. В Visual Studio выберите **Release / x64** и выполните **Build Solution**.
7. Собранный VST3 находится в подпапке `Builds\VisualStudio2022\x64\Release\VST3\`. Копируйте **всю папку `MonomachineNovaChorus.vst3`**, а не отдельный внутренний файл, в папку VST3 вашей DAW.

В проекте всего **четыре собственных компилируемых файла**:

```text
Source/PluginProcessor.cpp
Source/PluginEditor.cpp
Source/dsp/ChorusCore.cpp
Source/dsp/AudioAdapter.cpp
```

Остальные файлы `Source/` — необходимые заголовки. Папка `models`, движки других машин, ассемблер, Python, firmware-tool и Gearmulator для сборки плагина **не нужны**.

### Если сборка не проходит

- `JuceHeader.h` не найден: сначала сохраните `.jucer` через Projucer; не открывайте только отдельные CPP.
- Не найдены `juce_*`: исправьте путь к **modules**, не к корню JUCE, затем снова сохраните проект.
- Дублируются `createPluginFilter`, Processor или Editor: в solution остались файлы старого проекта. Используйте новую папку и новый `.jucer`.
- Не поддерживаются `std::clamp` / inline variables: проверьте C++17 и актуальные C++ build tools. В экспортёрах C++17 уже задан.
- Ошибка только при установке VST3: собирайте локально и копируйте готовую папку вручную. Не требуется собирать проект от администратора.

При другой ошибке нужен **первый текст ошибки из Build Output**, а не только итоговый счётчик ошибок.

## Использование

Поставьте плагин как аудиоэффект. MIDI и загрузка ROM не требуются.

| Параметр | Назначение | INIT |
|---|---|---:|
| DEL | Базовая задержка | 64 |
| DEP | Глубина модуляции | 64 |
| SPD | Скорость модуляции | 64 |
| MIX | Соотношение исходной и обработанной составляющих | 127 |
| FB | Обратная связь | 0 |
| WID | Разность фаз модуляции между каналами | 0 |
| LP | Низкочастотная фильтрация возврата обратной связи | 127 |
| INP | Уровень входа внутри CHORUS | 64 |

Числа — исходная шкала **0–127**, не выдуманные миллисекунды или герцы. FB не сдвинут искусственно в диапазон −64…63. Значение INP=64 даёт единичный коэффициент на входной стадии самой процедуры; при больших значениях возможен характерный фиксированный клиппинг.

Двойной щелчок по ручке — её исходное значение. Число под ручкой можно редактировать. Параметры видны в автоматизации DAW. INIT не переключает bypass.

После сброса сохранено исходное начальное приглушение обработанной составляющей на 128 блоков по 16 кадров — примерно 46 мс. Это поведение процедуры, не загрузка эмулятора.

## Частота и задержка

Ядро всегда работает на **44 100 Гц**. При 44,1 кГц преобразования частоты нет. На других частотах используется отдельный 64-tap sinc-адаптер ввода/вывода; он не подменяет алгоритм CHORUS.

| Частота проекта | Заявленная транспортная задержка |
|---:|---:|
| 44 100 Гц | 16 сэмплов |
| 48 000 Гц | 87 сэмплов |
| 88 200 Гц | 130 сэмплов |
| 96 000 Гц | 139 сэмплов |
| 192 000 Гц | 243 сэмпла |

Для наиболее прямой проверки DSP используйте проект 44,1 кГц. DAW получает значение latency для компенсации. При mono → mono стереоширина сворачивается в моно.

## Что проверено и чего не следует обещать

Подробности — в **`VALIDATION_RU.md`** и **`TECHNICAL_RU.md`**.

- Нативное ядро сопоставлено с выполнением исходных инструкций; проверены выход, состояния и буферы задержки, а не только RMS звука.
- Все восемь регуляторов влияют на DSP, что отдельно проверено звуковыми тестами.
- Экспорт `.jucer` в VS 2019 / 2022 выполнен настоящим Projucer 8.0.6; ссылки на четыре собственных CPP и сгенерированные обёртки проверены.
- **Сборка MSVC в Windows и аппаратный A/B с физической Monomachine не выполнялись.** Экспорт Visual Studio не равен проверенной сборке MSVC.

Это перенос **самой машины CHORUS**, а не всего тракта Monomachine. Здесь нет общей страницы AMP/FILTER/EFFECTS, секвенсора, маршрутизатора шин, LFO назначения параметров или моделирования АЦП/ЦАП. Также не переносился общий механизм доставки/сглаживания параметров ColdFire перед входом в машину. Собственное сглаживание и состояние внутри CHORUS сохранены; автоматизация подаётся на границах блоков хоста.

Состояние DAW хранит настройки, но не снимок текущей фазы LFO и содержимое задержки. При восстановлении состояния хвост сбрасывается.

## Необязательная сборка CMake

Projucer-пользователям этот раздел не нужен.

```sh
cmake -S . -B build -DJUCE_PATH=/path/to/JUCE -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel 1
```

Проверка чистого DSP без JUCE:

```sh
cmake -S . -B build-tests -DNOVA_BUILD_PLUGIN=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-tests --config Release
ctest --test-dir build-tests -C Release --output-on-failure
```

Прочитайте `NOTICE_RU.md` перед публикацией или коммерческим использованием.

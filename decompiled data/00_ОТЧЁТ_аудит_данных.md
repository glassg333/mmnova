# Monomachine SFX-60 OS 1.32B — полный аудит данных репозитория glassg333/mmnova

Дата аудита: 2026-09-18. Прошивка: `elektron_sfx6-60_os1.32b.bin`
SHA-256 `369849175602e20a9dd2b6e0ad8ac404b76f82718b14afbf1cbc01b7acabec7e`
(совпадает с fingerprint gearmulator OS 1.32b `e1c1b461b6d0f21b` — это подлинная заводская OS).

Железо: ColdFire MCF5206e (главный CPU) + 2 × DSP56303 (DSP1 = микшер/main, DSP2 = producer),
44 100 Гц. Синтез и эффекты целиком исполняются на паре DSP56300.

## ЧАСТЬ 1. Что в репозитории ПОДЛИННОЕ (проверено)

Всё нижеперечисленное верифицировано независимыми цепочками (как минимум двумя разными
сессиями реверса, включая полную перепрошивочную экстракцию с нуля):

1. **Прошивка** — BIN + SYX оригинальные (SYX = тот же BIN, нарезанный на 8065 SysEx).
2. **6 образов памяти DSP** (`02_memory_images/dsp{1,2}_{p,x,y}mem.bin`) — P: 1 343 588 слов
   на каждый DSP, X/Y: ~1 000 слов каждый. Независимо переизвлечены из BIN своим
   декомпрессором (порт ColdFire aPLib-варианта Monomachine) — **0 расхождений** во всех 6 банках.
3. **Листинги машин** — дизассемблер dsp56k-emulator, верифицирован 100% на корпусе
   (все машины P:$141A98–$148064: 22 836/22 836 инструкций).
4. **Регион хоруса** P:$147661–$1477DE — байт-в-байт совпадает с заявленным.
5. **Таблица диспетчеризации машин** (P:$10016B init / $10018D config / $1001AF process,
   по 34 входа) — из неё однозначно получены адреса всех машин.

## ЧАСТЬ 3. Сигнальный роутинг (что известно точно)

### 3.1 Голосовая цепочка (kernel, доказано дизассемблированием — `06_docs/KERNEL_VOICE_CHAIN.md`)

```
[машина: init/config/process по таблицам X:$10016B/$10018D/$1001AF]
   → pre-voice P:$262: portamento (2 slew-лимитера) + LFO-модуляция питча
   → jsr (r1) = process машины (16-кадровые блоки, 44.1 кГц)
   → post-voice P:$4A8: AMP-огибающая (AHD/ADSR) + панорама + Base/Width-фильтр
   → 3 голоса на заход (Y:$528 + voice*$100, голос = 256 слов состояния)
   → буферы/ESAI P:$1A3 → DSP1 суммирует → выход
```

- Внешняя SRAM единая: X:/Y:/P-адреса >$100000 алиасятся на одно ОЗУ
  (доказано чтением диспетчерских таблиц X-адресацией).
- Голос = 256 слов состояния, карта смещений — `06_docs/voice_state_offsets.txt`.
- Audio-базы X:$2C0–$2C4, роли DSP выбираются HI08-синхронизацией ($140 DSP1 / $160,$180 DSP2).

### 3.2 Внутри FX-машин

- **LFO** — НЕ общий кернел-модуль. Каждая FX-машина содержит inline-LFO:
  аккумулятор фазы + синус-таблица Y:$0132 (8K записей, маска фазы $1FFF,
  линейная интерполяция). SPD читается из `y:(r6+$6)`.
- **LP-фильтр (TONE)** — общий коэффициентный стол P:$144AC7 (258 слов),
  индекс = параметр >> 16. Используется chorus/FM/reverb.
- **Дисторшн** — отдельной машины нет; это флаг насыщения ALU DSP56300
  (`bset #$14,sr`) — клип на ±1.0 внутри chorus/FM.
- **MIX-формула** — `wet×INP + dry×($7FFFFF − MIX)`; при MIX=127 остаётся
  ~0.78% сухого — оригинальное поведение прошивки.
- **Delay** — кольцевой буфер X:$114000 (2×2048 сэмпла, канал B +$800).
- **Bitcrush** — в FX-EXT: fractional table lookup (mpysu+dmac паттерн) =
  децимация сэмпр-рейта; питч-таблицы $101AFB/$101BFB/$101CFB.

### 3.3 FM-машины (полностью добыто)

- Таблица отношений P:$141A80: 24 музыкальных ratio 1/32…8/1 (1.23 fixed-point).
- FM+STAT: 2 оператора, рекурсивный фидбек модулятора, TONE → LP $144AC7.
- FM+PAR: 3 параллельных модулятора на одну несущую.
- FM+DYN: динамический скан вейвтейбла P:$141880 параметром 2ENV,
  условный знак фидбека (`tfr x0,a ifmi`).
- Питч: `engine_pitch × 0x0BE37C → L:$5` (48-бит аккумулятор фазы).

## ЧАСТЬ 5. Что в репозитории МУСОРНОЕ (не включено в архив)

### 5.1 Баг экстрактора таблиц (главная техническая находка аудита)
`extract_tables.py` для всех адресов ≥$100000 делал `off = addr − 0x100000`
(докстринг при этом утверждает прямое отображение). Итог: **26 из 43 .bin таблиц —
полностью нулевые файлы** (LP-коэффициенты, SID-фильтр, attack/release/RMS
компрессора, все 6 таблиц phaser, вейвтейблы SWAVE, 4 таблицы DPRO-BBOX, GND-NOIS).
Баг подтверждён байт-в-байт: «таблица» VO6 == образ по адресу −0x100000.
В архиве `04_tables/` лежат перевыкачанные правильные версии + TABLES_MANIFEST.json
со статусами каждой таблицы.

Статусы по факту:
- 28 таблиц — FIXED (восстановлены реальные данные из образа);
- 5 — VERIFIED (в репо были верными);
- 4 — ZERO-IN-IMAGE (P:$11B451 DPRO-вейвтейбл, P:$123EF5/$133191 decay/damp реверба,
  P:$140800 SID-вейвтейбл 1) — **в прошивке там нули**: области заполняются ColdFire
  на живом устройстве при старте/редактировании. Из BIN их взять нельзя в принципе.
- 6 — RUNTIME-ONLY (X:$140000 sine-вейвтейбл 2048, X:$143F95/$144446 div-таблицы,
  Y:$141800/$141A00 LFO-таблицы, Y:$1449C6 kernel-кривые) — адреса вне прошивочных
  образов (runtime RAM); содержимое в репо ничем не подтверждено. Sine X:$14A000
  (это и есть «width tables» хоруса $14A000/$14A800) — стандартный синус, восстанавливается

## ЧАСТЬ 6. Что упущено и что можно воссоздать с точностью

### 6.1 Можно воссоздать БИТ-В-БИТ (все данные есть)
- **Все машины page A (m1–m19) + FX-DLY (m32) + FX-EXT (m33)**: полные листинги
  init/config/process, все таблицы данных, дескрипторы с дефолтами и диапазонами.
  Каждый листинг — буквально машинный код DSP56300, исполняющийся в железе. Два пути:
  а) эмуляция/исполнение оригинального P-кода (dsp56k-emulator даёт 100% совпадение);
  б) портирование в C++ по листингам — методика доказана хорусом (структура
     ChorusCore.cpp подтверждена инструкцию-в-инструкцию).
- **Хорус** — уже портирован и верифицирован (папка CHORUS black fixed).
- **FM-трио** — таблицы/алгоритмы/дескрипторы добыты полностью, порт возможен 1:1.
- **Роутинг голоса/эффектов** — диспетчер, буферы, INP/MIX-математика, pre/post-voice
  известны на уровне инструкций.
- **Sine-таблица 8K (X:$14A000, runtime)** — стандартный синус с 13-бит фазой,
  восстанавливается формулой.

### 6.2 Можно воссоздать с высокой точностью, но НЕ бит-в-байт
- **Reverb decay/damp** — таблицы в прошивке пустые (runtime). Либо реверсить
  ColdFire-инициализацию (coldfire_main.bin есть!), либо снять дамп с железа
  через HI08-монитор. Сам алгоритм реверба (листинг 1257 строк) при этом точен.
- **SID-вейвтейбл 1, DPRO-главный вейвтейбл** — аналогично runtime; но
  DPRO-вейвтейбл редактируется пользователем, дефолт восстановим из
  ColdFire-кода инициализации.
- **LFO speed/mult таблицы (Y:$141800/$141A00)** — runtime; зависимости SPD→step
  восстанавливаются реверсом или калибровкой по поведению.
- **24-бит fixed-point арифметика**: при портировании в float/C++ — микроотличия
  от железа. Для бит-точности нужен 56300-эмулятор или 48-битный аккумулятор +
  saturation-семантика.

### 6.3 Чего НЕТ вообще (главные упущения)
1. **Дизассемблирование ColdFire main** (425 858 байт распакованы, но НЕ
   дизассемблированы): секвенсор, паттерны, страницы параметров, машин-энджин
   (pitch→ноты), sysex-протокол, загрузка DSP-кода, arpeggiator, song mode.
   Это отдельная большая работа (capstone m68k уже используется в скриптах).
2. **Инициализация runtime-памяти** — где ColdFire заполняет X:$14A000 sine,
   decay/damp реверба, LFO-таблицы: ищется в coldfire_main.bin, не сделано.
3. **C++ дизассемблер dsp56k (dis56300_tool)** — заявлен, не выложен.
4. **Кривые параметров** (байты `25 d3 30 …` в хвостах дескрипторов) — формат
   не расшифрован (вероятно, кусочно-линейные таблицы 24-bit BE).
5. **Дампы с живого устройства** (X/Y runtime области) — самый быстрый способ
   закрыть п.6.2; HI08-мониторный протокол частично известен (P:$100000 monitor).

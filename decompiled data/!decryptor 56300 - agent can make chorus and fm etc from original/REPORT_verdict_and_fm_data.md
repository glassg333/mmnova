## ЧАСТЬ 1. Перепроверка CHORUS (папка "CHORUS black ui and fixed")

### 1.1 Методика (полностью независимая цепочка)

Прошлые проверки опирались на Musashi-эмуляцию ColdFire. Здесь использован другой путь:

1. Дизассемблирован собственный декомпрессор прошивки (ColdFire MCF5206e, BIN 0x1C4–0x362,
   capstone m68k) и портирован 1:1 в Python (`scripts/mm_aplib_mm.py`).
2. Установлены отличия варианта Monomachine от общепринятого aPLib (mischa85):
   EOF-маркер НЕ `raw==767`; поток Monomachine не имеет внутрипотокового EOF —
   декомпрессор работает до исчерпания входа секции, а заливка останавливается
   по записи JMP в самом потоке.
3. Загрузчик func_7ce (BIN 0x7CE) разобран: записи
   `[cmd LE24][addr LE24][count LE24][data LE24]`, cmd: 0=P, 1=X, 2=Y, 3=JMP P:addr;
   каждая секция начинается и заканчивается записью `JMP P:$000066` (байты `03 00 00 66 00 00`).
4. Секции контейнера (BIN 0x4000, формат `[u32 stored_len BE][u32 byte-sum BE][поток]`):
   - секция 1 → заливка DSP1 (11 записей: P 2861, X 69, Y 775 слов)
   - секция 2 → заливка DSP2 (12 записей)
   - секция 3 → общая, льётся в ОБЕ DSP (133 записи, P 111 912 слов)
   - все контрольные суммы байтовых сумм сошлись.
5. Бут-флоу подтверждён дизассемблом BIN 0x1F6E–0x2078 (заливки 0x500000/0x600000).

### 1.3 Верификация региона CHORUS

- Регион P:$147661–$1477DE (382 слова) совпадает **байт-в-байт** с
  `decompiled data/chorus_region.bin`.
- Структура, заявленная в ChorusCore.cpp / TECHNICAL_RU.md, подтверждается листингом:
  - init P:$147661–$14767A, `rts` ровно на $14767A;
  - config — использует завершающий `rts` init (запись $14767A в config-таблице);
  - process P:$14767B–$1477DD, последняя инструкция `rts` на $1477DD;
  - `move #>$114000,a0` — кольцевой буфер задержки X:$114000 (2×2048 сэмпла,
    второй канал +$800) — РЕАЛЬНО;
  - `move #>$14a000,x0` — width-таблица $14A000 (и парная $14A800) — РЕАЛЬНО;
  - `bset #$14,sr` перед рекурсивным модулятором (режим насыщения SR.SM) — РЕАЛЬНО;
  - `do #<$10` — 16-кадровые блоки — РЕАЛЬНО;
  - LP-таблица обратной связи `$144AC7` (используется и FM-машинами) — РЕАЛЬНО;
  - 6 отводов с дробной интерполяцией (`mpysu/dmac/macsu/asr`-паттерн в $14775A–$14776A);
  - MIX: `move y:(r6+$7),x0` → `$7fffff − x0` — при MIX=127 остаётся ~0,78% сухого
    (сознательное отклонение плагина при MIX=127 описано корректно).

Единственное «отклонение» плагина (клэмп MIX=127) соответствует фактам прошивки.

**ВЕРДИКТ: декомпиляция CHORUS в папке black fixed — подлинная. Адреса, структура
и арифметика соответствуют реальному машинному коду OS 1.32b.**

## ЧАСТЬ 2. Добытые данные по FM-синтам (было утрачено — fm_pending.md)

### 2.1 Записи диспетчеризации (P:$10016B init / $10018D config / $1001AF process, по 34 входа)

| машина | init | config | process |
|---|---|---|---|
| m8 FM+STAT | $145D12 | $145D1D | $145D21 |
| m9 FM+PAR | $145EC9 | $145ED4 | $145EDB |
| m10 FM+DYN | $14619D | $1461A8 | $1461C1 |

(соседи: m7 DPRO-BBOX=$1474E9, m11 VO-6=$1464FC, m15 FX-CHO=$147661)

### 2.2 Дескрипторы параметров (ColdFire-образ, секция 0 → RAM 0x200000, смещения в распакованном виде)

Найдены по строкам; шаг дескрипторов 0xB0 (176 байт). Формат: имя машины, подимя,
номер страницы, 8 имён параметров (по 4 байта + паддинг), значения по умолчанию,
мин/макс, кривые.

**FM+STAT** (@ 0x58545):
```
параметры: 1FRQ  1FIN  1ENV  1FB  2FRQ  2VOL  TONE  TUNE
умолчания: 0x3C  0x40  0x50  0x1E 0x50  0x40  0x62  0x40
```

**FM+PAR** (@ 0x585F5):
```
параметры: 1FRQ  1ENV  2FRQ  2ENV  3FRQ  3ENV  TONE  TUNE
умолчания: 0x3C  0x40  0x50  0x40  0x66  0x50  0x62  0x40
```

**FM+DYN** (@ 0x586A5):
```
параметры: 1FRQ  1FEN  1VOL  1VEN  2FRQ  2ENV  2FB  TUNE
умолчания: 0x40  0x40  0x40  0x40  0x4A  0x50  0x1E 0x40
```

Гипотезы из fm_pending.md (dyn=динамический, stat=статический, par=параллельный)
ПОДТВЕРДИЛИСЬ кодом: STAT — статические отношения операторов из таблицы;
PAR — три параллельных модулятора; DYN — динамический скан вейвтейбла.

### 2.3 Параметры → состояние машины (Y:(R6+$4..$B) = 8 параметров по порядку)

Например FM+STAT: R6+$4=1FRQ, +$5=1FIN, +$6=1ENV, +$7=1FB, +$8=2FRQ, +$9=2VOL,
+$A=TONE, +$B=TUNE. Служебное состояние: +$10/$11 (фаза несущей 48-бит),
+$12/$13 (фаза модулятора), +$1A (состояние FB), +$28 (огибающая), +$2C/$2E (усиления).

### 2.4 Таблицы

- **Таблица отношений P:$141A80** (используют STAT и PAR; 2FRQ/3FRQ = индекс×24):
  24 музыкальных отношения несущая:модулятор в 1.23 fixed-point:
  1/32, 1/16, 1/8, 3/16, 1/4, 5/16, 3/8, 1/2, 5/8, 3/4, 7/8, 1, 1.25, 1.5, 1.75,
  2, 2.5, 3, 3.5, 4, 5, 6, 7, 8
  (raw: 0x004000 … 0x400000; шаг = \(v/0x800000\)).
- **Вейвтейбл FM+DYN P:$141880**: нисходящая спектральная таблица, сканируется
  параметром 2ENV (`n1 = |2ENV·scale − 0x400000| >> 15`), выбор волны динамический.
- **Синус Y:$0132**: 8192 записи (маска фазы $1fff), просмотр с линейной интерполяцией
  (паттерн `mpysu/add/macsu/asr`), база $14A000.
- **LP-таблица P:$144AC7** (258 слов) — общая с хорусом (TONE-параметр = выбор
  коэффициента: `asr #$10` параметра → индекс).
- **Питч-конверсия**: `a = engine_pitch × 0x0BE37C` (48-бит, mpysu+dmac),
  накопитель фазы L:$5 (X:$5/Y:$5 пара).

### 2.5 Алгоритмы машин (кратко, по листингам в listings/)

- **FM+STAT** ($145D21): 2 оператора. 2FRQ → отношение из таблицы; фаза модулятора
  × отношение; 1FIN = индекс модуляции (глубина девиации); 1FB — рекурсивный фидбек
  модулятора; 2VOL — уровень модулятора в выходной смеси; TONE — LP по таблице $144AC7.
- **FM+PAR** ($145EDB): 3 параллельных модулятора (1FRQ/2FRQ/3FRQ — по таблице
  отношений, 1ENV/2ENV/3ENV — их огибающие), сумма модуляций на несущую.
- **FM+DYN** ($1461C1): 2 оператора + динамический скан волны: 2ENV двигает точку
  чтения таблицы $141880 (волна меняется во времени), 1FEN/1VEN — огибающие
  частоты/громкости несущей, 2FB — фидбек модулятора с условным знаком
  (`tfr x0,a ifmi` — знак зависит от предыдущего состояния), TUNE — подстройка.

Полные листинги: `listings/fm_stat_full.txt` (343 стр.), `fm_par_full.txt` (605),
`fm_dyn_full.txt` (726), хорус `chorus_full.txt` (292).

## ЧАСТЬ 4. Что осталось нерешённым

1. Полный независимый дизассемблер DSP56300 (заготовка `scripts/dis56300.py`):
   группы 0000/0001 (dual-move ALU), 0x08-0x0B (movep/биты) требуют ещё итераций
   по эталонным парам — для сверки FM-листингов достаточно существующих листингов,
   т.к. байты образов уже верифицированы на 100%.
2. Портирование FM-машин в C++ (как ChorusCore) — теперь возможно: структура,
   таблицы и параметры извлечены.
3. Точные кривые огибающих (байты `25 d3 30 ...` в дескрипторах) — требуют
   отдельного декодирования.

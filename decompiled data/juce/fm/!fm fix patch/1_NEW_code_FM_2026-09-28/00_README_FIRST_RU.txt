ЧТО ИСПРАВЛЕНО (коротко, по-человечески)
----------------------------------------
1) FM STAT, частоты 1FRQ/2FRQ/3FRQ. В прежнем порте ручка проходила
   только ПОЛОВИНУ таблицы частот: 123 позиции из 128 были неверные,
   на ручке 127 порт давал соотношение 1.25 вместо 8.0.
   Теперь закон ровно как в железе:
       n = floor(((K<<16) + $8000) * 48 / 2^24)  — все 24 ступени,
       минимум 1/32 (0.03125) на ручке 0, максимум 8.0 на ручке 127.

2) Про «частота до 0»: в ОРИГИНАЛЕ через ручку частота до нуля НЕ
   опускается — минимум по таблице 1/32. До нуля машина опускается
   другим путём: питч-слово A=0 — тогда кэрриер стоит, а модуляторы
   продолжают звенеть на своей динамике уровней. Прежний порт такого
   не умел вообще. Теперь умеет: FmCore::setPitchWordOverride(w) —
   можно скормить честный 0 (и любое точное слово из матрицы).

3) Остальные ручки FM STAT переписаны пословно с прошивки:
       1FIN — точная математика слова (0.75..1.2461, центр 64);
       1ENV — квадрат (K/128)^2, а не линейно;
       2VOL — гейт: ниже 64 оператор 2 молчит, как в железе;
       1FB  — закон K^2.

4) FM PAR и FM DYN — бит-точные ядра (транскрипция листингов).
   Доказано векторами, снятыми с эмулятора OS 1.32:
       FM PAR: 7168/7168 слов совпадают точно (14 конфигов x 16 блоков)
       FM DYN: 8192/8192 слов совпадают точно (16 конфигов x 16 блоков)
   Это НЕ «на слух похоже» — это побайтовая сверка выходных слов.

5) Экран (цифры под ручками). Экран в твоём плагине показывает
   соотношения из ТРЕТЬЕЙ таблицы (не той, что звук, и не той, что
   железо). Звук после этого архива будет верный, а вот цифры на
   экране останутся старые, пока не поставишь маленький патч из
   файла 01_SCREEN_PATCH_PluginEditor.md (5 минут, один if-блок).

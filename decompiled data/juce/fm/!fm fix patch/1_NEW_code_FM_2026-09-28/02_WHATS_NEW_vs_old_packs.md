## Почему stage8 -> stage9 (что именно чинили)

Ты сказал: «фм стат в оригинале имеет до 0 фрек опускаться, а у меня
0.2 минимум». Проверено механически (эмулятор + захват регистров, не на
слух). Оказалось, в плагине жили ТРИ разные таблицы частот:

1. **Звук**: индекс в таблицу считался БЕЗ учёта сдвига `<<1` дробного
   умножения MPY в DSP -> ручка 0..127 проходила половину таблицы,
   123/128 позиций неверные, на 127 было 1.25 вместо 8.0.
2. **Экран**: считал по третьей таблице (32 ступени 1/64..12).
3. **Железо (оригинал)**: `n = floor(((K<<16)+$8000)*48/2^24)`,
   все 24 ступени 1/32..8. Захват сделан с ОБОИХ мест выборки
   ($145D38 для оп2 и $145DAD для оп1) — значения идентичны.

Про «до 0»: через таблицу нуля НЕТ (минимум 1/32). Ноль в оригинале
достигается питч-словом A=0 (L:$5=0, кэрриер стоит, модуляторы звенят
на динамике уровней). Порт теперь умеет принимать питч-слово напрямую:
`FmCore::setPitchWordOverride(w, valid)` — включая честный 0.

## Доказательства (не «на слух»)

- FM PAR: 7168/7168 выходных слов совпали с эмулятором OS 1.32
  (14 конфигов ручек x 16 блоков), макс. ошибка 0.14 LSB — только
  округление float-нормировки выхода.
- FM DYN: 8192/8192 слов совпали (16 конфигов x 16 блоков).
- Таблица сверки ручек: `knob_law_table_stat.md` (в архиве 2).
- Выход на дефолтных ручках (3C 40 50 1E 50 40 62 40) = 2.14 Q23 на
  всех трёх машинах — нормировка выхода сделана по этому замеру.

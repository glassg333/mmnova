# Протокол доказательства: FM STAT (m8) бит-в-бит

## Метод (тот же, что для m1/m2/m3/реверб/PAR/DYN)

1. **Источник истины** — листинг машины:
   `decompiled data/03_listings/machines_page_A/08_FM-STAT_full.txt`
   (PROC $145D21-$145EC8, 343 строки) + INIT/CONF $145D12-$145D20
   из полного листинга P-памяти.

2. **Эталон** — эмулятор DSP56300 (`scripts/dsp_emu.py`, тот же, на котором
   ранее подтверждены m1/m2/m3/реверб/Track Delay/PAR/DYN), прогнанный на
   НАСТОЯЩЕЙ прошивке OS 1.32: INIT один раз, затем на каждый блок CONF+PROC
   с параметрами ручек (y:(r6+$4..$B) = K<<16) и питч-словом в регистре A.
   Синус-таблица $14A000 инжектирована как round(sin*8388607) — канон всей
   семьи векторов.

3. **Векторы** (`research/fm_stat_vectors.txt`): 25 наборов ручек x 16
   блоков; на каждый блок 32 выходных слова + 99 слов стейта
   (страница машины y:(r6+$00..$3F), 48-битные инкременты X:$5/Y:$5,
   окно ротатора 2 X:$1E-$3F).

   Покрытие наборов: дефолты; всё в 0; всё в 127; края закона соотношений
   (1FRQ/2FRQ = 0, 5, 11, 64, 127 — индексы таблицы 0/1/2/12/23);
   1FIN 0/127; 1ENV 63/65/127 (граница гейта K=64 и спад);
   1FB 0/127 (воблинг фазы); 2VOL 63/65/127 (гейт оператора 2);
   TONE 0/127; смешанный musical-набор; питч-слово 0 (все фазы стоят);
   низкое/высокое питч-слово.

4. **Сверка** — `research/test_fm_stat.cpp`: грузит векторы, гоняет то же
   через C++ ядро `MnmFmStat.hpp`, сравнивает слово-в-слово (выход + стейт).

## Результат

```
FM-STAT: 400 blocks, 52800 words, mismatches = 0  [100% BIT-EXACT]
```

- выход: 12800/12800 слов;
- стейт машины (фазы операторов, TONE-фильтры, ротаторы, гейты,
  48-битные инкременты, окно ротатора): 40000/40000 слов.

## Что нашлось по пути (честно)

- **Сдвиг выхода на 2 сэмпла** в первом прогоне: у DO-цикла свёртки выхода
  ($145EB5) адрес конца в машинном коде = $145EBA, а дизассемблер в
  мнемонике печатает $145EBB. Из-за этого лишний `move b,y:(r4)+` попал
  внутрь цикла (24 записи вместо 16+1) и пары продублировались не так, как
  в железе. Поправлено на «запись после цикла» — 0 расхождений.
  Вывод: при транскрипции DO-циклов сверять конец цикла нужно по
  ОПКОДУ, не по мнемонике дизассемблера.

## Как перепроверить самому

```
cd research
g++ -O2 -std=c++17 -I../dsp/mnm test_fm_stat.cpp -o test && ./test
```

Ожидаемый вывод: `FM-STAT: 400 blocks, 52800 words, mismatches = 0 [100% BIT-EXACT]`

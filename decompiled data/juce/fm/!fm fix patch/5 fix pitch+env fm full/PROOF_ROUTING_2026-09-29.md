# PROOF — BLOCK-ROUTING BIT-EXACT (пак 9, OS 1.32B)

Дата: 2026-09-29
Объект: блочный цикл ОС вокруг кадра голоса — роутинг/микшер:
$0087-$00CE (таблицы режимов), $00CF-$00FF (пер-трековый пролог:
флаги → X:$2C4, диспетчеры INIT $10016B / CONF $10018D),
$0143-$0163 (микшер: add func_0001e2 / replace func_0001ec),
$01A3-$01E1 (конец блока: MIX $01AD, копия $01C2),
пути ввода func_0002ed/000302/000319 (внутри потока $0100-$02EB).

## Результат

    g++ -O2 -std=c++17 -I dsp/mnm -o test_block_routing test_block_routing.cpp
    ./test_block_routing vectors/routing_vectors.txt

    sets: 22
    checks=360756 mismatches=0  [100% BLOCK-ROUTING BIT-EXACT]

Каждая проверка = слово памяти (X/Y $000-$7FF) в контрольной точке:
после S1 (таблицы режима), после каждого из трех суб-блоков, в конце
блока. Ожидание = диффы живого эмулятора против сида; ячейки вне диффов
обязаны равняться сиду (проверка в обе стороны).

## Оракул

Один пакетный эксперимент (правило 18): scripts/exp67_routing.py —
живой эмулятор DSP56300 (dsp_emu.py, 35/35 юнит-тестов) на реальном
коде ОС: poll HRX → таблицы режима → 3 суб-блока {флаги → X:$2C4 →
INIT/CONF диспетчер → кадр пака 8 → микшер} → конец блока → граница
$0087. FM STAT — настоящий машинный код ОС ($145D21+), не харнесс.

## Ключевые законы (все — слово-в-слово)

1. Таблицы режима ($0092-$00C6): $180→базы $140/$1A0/$260/$2CC;
   $160→$180/$1E0/$2A0/$2FC; $140→$160/$1C0/$280/$32C.
2. Микшер ($0143-$0163): флаги X:$2C4, биты 0/1/2 → bus[i] += Y[i]
   (func_0001e2), Y-шина = Y:$0000-$1F, 32 слова на суб-блок.
3. MIX ($01AD-$01C1): bus1 = (bus1+bus2+bus3)·$7FFFFF — 96 слов.
4. Копия ($01C2-$01E1): 96 слов из X:$2CA/$2CB-областей в шины.
5. Диспетчер машин: ID-ячейка y:(page−4) против защёлки y:($120+k),
   таблицы $10016B/$10018D/$1001AF; гейт = бит 7 слова трига
   (y:($123)), сбрасывается диспетчером ($00E2-$00E3).
6. Ввод: func_0002ed — 16 слов с шагом 2, каждое дважды; func_000319 —
   64 слова как есть; цель = X:$2C3-область.

## Открытия, сделанные по пути

1. Суб-блок = трек: диспетчер читает y:($120 + y:$124) — защёлки
   y:$120/$121/$122 = «последняя машина суб-блока k». Два DSP × 3
   суб-блока = 6 треков.
2. T6 ($0B33-$049): выход кадра раскладывается в Y:$0000-$1F (шина
   микшера), X:(X:$FF)+ (поток хоста; X:$FF = r5 = work-база,
   сохраняется на $04F6) и эхо через X:(X:$2C9)+.
3. Путь бита 3 (replace) — программная ошибка прошивки: до
   func_0001e2/0001ec доходит ВЕТВЛЕНИЕМ (bsclr/bsset $01F8/$01FC),
   а функции кончаются rts → пустой системный стек → мусорный прыжок.
   Хост бит 3 не выставляет. В порт включен как есть, векторами не
   покрывается (недостижим).
4. Бит 7 слова трига = one-shot «параметры менялись»: гейт ветки
   INIT/CONF ($00E1-$00FF), потребляется bclr ($00E2), хвост видит
   только младшие биты.
5. Баг эмулятора (исправлен): jset пушил адрес возврата
   ("jset".startswith("js") == True) — jset = чистый переход, пуш
   должен делать только jsset/jsclr. Пак 8 не задет (пуш не менял
   память), регрессионный тест добавлен (35/35).
6. Баг порта (исправлен): при возврате A/B из нативного FM-ядра в
   ядро 48-битное значение нужно знакорасширять до 56 бит (sext48),
   иначе data-limit checker (FM 5.4.1.2) видит +$00F4758A000000 и
   сатурирует запись в $7FFFFF. Проявилось только на пути
   counter≠0 ($04A8-$04AB → $04F5), где B машины доезжает до
   history-копии $04FA-$04FE — пак 8 этот путь не покрывал (всегда
   counter=0, путь $04AD перезаписывал B из y:(r6+$21)).

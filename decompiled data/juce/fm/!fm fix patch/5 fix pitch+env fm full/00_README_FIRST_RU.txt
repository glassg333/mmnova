ПАК 7 — FM НА УРОВНЕ ПЛАГИНА: ОРИГИНАЛЬНЫЕ ЭНВЕЛОПЫ + ГЕЙН-ПУТЬ + ПИТЧ + ФИКС СКОРОСТИ
Monomachine OS 1.32B -> JUCE-порт. Дата: 2026-09-29. Правило №18: все верификации
одним пакетным прогоном. Итог теста: 9556 проверок, 0 расхождений — 100% BIT-EXACT.

ЧТО БЫЛО СЛОМАНО (и починено — всё доказано на бит-точном эмуляторе DSP56300
на РЕАЛЬНОМ ядре OS 1.32B, векторы в vectors/):

1. «БИТКРАШ» / СКОРОСТЬ. Машина PROC выдаёт 32 слова = 16 пар (L,R), строго
   дублированных (a,a,b,b) — моно-машина. Старая обёртка играла все 32 слова
   как 32 моно-сэмпла: каждый звук игрался ДВАЖДЫ -> вся машина шла с
   половинной скоростью (октава вниз, энвелоупы вдвое медленнее), и CONF
   тикал не в том ритме. Теперь на вызов ядра выдаётся ровно 16 уникальных
   сэмплов = один 16-сэмпловый трек-кадр, как в ядре ОС.

2. ЭНВЕЛОПЫ. Старая обёртка вешала generic float ADSR. Оригинал = стейт-машина
   ядра P:$088E-$08D7: фазы ATK/HOLD/DEC/REL/KILL, прошивные таблицы формы
   $141800/$141880 (128 слов, из дампа), HOLD масштабируется словом темпа
   (t0*TEMPO>>23 * $791FD0*4), атака клампится дата-лимитером в $7FFFFF
   (не wrap в -1.0!), RETRIG БЕЗ сброса уровня (родное поведение), KILL =
   множитель tblB[1] = 0.904016/кадр (-60 дБ за ~16 мс). Всё перенесено
   пословно в MnmAmpEnv.hpp.

3. ГЕЙН-ПУТЬ (анти-щёлк). Оригинал применяет энвелоп как
   level * VOL^2 * панорама(sin/cos) с ЛИНЕЙНЫМ РАМПОМ на 16 сэмплов кадра
   (P:$08D8-$08FA). Перенесено бит-в-бит (MnmGainPath). Это родной механизм
   absence щелчков: note-on/off по построению без кликов. PAN 0 = жёстко влево
   (L = cos[1] = full, R = sin[0] = 0). Индекс панорамы = (PAN<<16)*$408E05>>34,
   cos читается со смещением +1 ($14A801) — как в коде.

4. ПИТЧ. Ядро ОС переводит слово питча страницы ((нота<<11)/12) в ГЕРЦЫ до
   вызова машины (таблица $140000 = 2^(i/2048) в Q22 + множитель $1D22A,
   кламп [0,$5800]). Старая обёртка передавала float noteToHz() — не то, что
   кормит прошивка, и игнорировала TUNE. Теперь точный закон ядра
   (MnmPitchChain), включая TUNE (биполярно, шаг 683/128 слов) и слово
   питч-модуляции w30 (покой 64, шаг = 33/16 полутона). ПРОВЕРЕНО: 72 точки
   сетки (w41 x TUNE x w30) бит-в-бит.

   ВАЖНО: машина умножает $0BE37C на ПОЛНЫЙ 48-битный аккумулятор A (a1:a0) —
   дробное младшее слово a0 участвует в инкременте фазы (это даёт родной
   алиасинг MNM FM — он теперь бит-в-бит). Старые ядра принимали только
   24-битное A — сигнатура proc() расширена до uint64. setPitchWordOverride
   теперь тоже 48-битный (питч-слово 0 = замороженный носитель, как в оригинале).

5. ЧТО НЕ ТРОНУТО: бит-точные ядра MnmFmStat/MnmFmPar/MnmFmDyn (паки 3/4,
   свип всех ручек 0 расхождений) — изменена только сигнатура proc(uint64).

ИНТЕГРАЦИЯ В ПЛАГИН:
  1) Скопировать 8 файлов в Source/dsp/mnm/ (apply_patch.py умеет сам).
  2) Голос: fm.setParameters(...); fm.setAmpParams(atk, hold, dec, rel, vol, pan)
     — сырые 0..127 со страницы AMP; fm.setTempoWord(0x800000/tick) — слово
     темпа (в векторах верификации использовано 120 — закон не зависит от
     значения входа); fm.noteOn(note)/noteOff()/kill().
  3) Рендер: processBlockStereo(L,R,n) — левый = cos-канал, правый = sin-канал.
     processBlock(out,n) = моно (L+R)/2.
  4) Нормировка: старый делитель /17949485 сохранён (пиковая нормировка по
     дефолтным ручкам). Громкость теперь по закону оригинала: VOL^2, т.е. при
     VOL=64 сигнал в ~4 раза тише, чем без гейна — это ОРИГИНАЛ.

ЗАМЕТКА ОБ ЭМУЛЯТОРЕ (документировано, в порт НЕ перенесено): питоновский
dsp_emu хранит `move ab,l:aa` как B->X / A->Y (реальный DSP56300: A->X / B->Y).
Из-за этого в эмуляторе рампа гейна каждого кадра начинается с ЧУЖОГО канала
(пила -41 дБ на 2.756 кГц). Порт использует семантику реального железа: каждый
канал рампится от своего предыдущего значения. Цели гейна от свопа не зависят
и сверены бит-в-бит с ячейками X/Y[$FA] эмулятора.

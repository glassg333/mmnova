# РОУТИНГ MONOMACHINE OS 1.32B — как устроен (пак 9)

Дата: 2026-09-29. Объект: блочный цикл ОС вокруг кадра голоса —
диспетчер режима роутинга, пер-трековый микшер шин, суммирование MIX,
копия альтернативных шин, пути ввода с кодека.

Всё, что здесь написано, проверено бит-в-бит: оракул = живой эмулятор
DSP56300 на реальном коде ОС (22 сета, 3 суб-блока на блок, полный
прогон блочного цикла $0087-$0218), порт на C++ повторил его слово-в-слово
(360 756 проверок, 0 расхождений — PROOF_ROUTING_2026-09-29.md).

## 1. Грубыми словами: что такое «роутинг» в Monomachine

В железе SFX-6/MkII — ДВА DSP-чипа. Каждый обрабатывает по 3 трека,
поэтому блок аудио = 3 «суб-блока» на чип: суб-блок k = один трек,
16 сэмплов, полная цепочка (машина → фильтр → энвелоп → гейн). Второй
DSP параллельно считает треки 4-6. Всё это доказано в паке 8 (кадр
голоса) и добито здесь на уровне блока.

Каждый трек по умолчанию попадает в СВОЮ шину (bus). Шин — три на чип:
bus1, bus2, bus3. Дальше хост (ColdFire-процессор, который управляет
DSP) решает, что делать с шинами — и вот тут появляются режимы из меню
GLOBAL → EDIT ROUTING:

    6*MONO        — каждый трек в свой джек (6 моноджеков)
    3*STEREO      — пары треков 1-2 / 3-4 / 5-6 как стереопары
    3*STEREO + AB — то же + сумма всего в главные выходы A/B
    MIX           — всё в главные выходы (сумма)

Строки меню лежат в coldfire_main.bin по смещению $520B2-$520E1
("EDIT ROUTING", "3*STEREO + AB", "MIX", "3*STEREO", "6*MONO") —
можешь проверить в hex-редакторе.

## 2. Протокол блока: заголовок $140/$160/$180

На границе блока DSP читает первое слово из HI08-порта (HRX, регистр
$FFFFEB) и ждет одно из трех значений — это и есть «раскладка блока»
(код $0087-$00B6):

| заголовок | bus1  | bus2  | bus3  | work  | эхо-приём |
|-----------|-------|-------|-------|-------|-----------|
| $180      | $140  | $1A0  | $200  | $260  | $2CC      |
| $160      | $180  | $1E0  | $240  | $2A0  | $2FC      |
| $140      | $160  | $1C0  | $220  | $280  | $32C       |

Каждая шина = $60 слов = 3 суб-блока × 32 слова (16 L/R-пар).
Базы сохраняются в X:$2C0 (bus1), X:$2C1 (bus2), X:$2C2 (bus3),
X:$2C3 (work/ввод), указатель эхо-шины — в X:$2C9, служебные
эхо-базы — в X:$2CA/$2CB. Заголовок сохраняется в X:$2C8.

Фальсифицируемое предсказание: поставь брейкпоинт на X:$2C0 после
загрузки блока — там будет $140, $160 или $180 минус/плюс смещение
из таблицы выше, ровно в соответствии с выбранным режимом роутинга.

## 3. Пер-трековые флаги роутинга — сердце всего

Перед КАЖДЫМ суб-блоком ($00CF-$00DD) DSP читает слово флагов из
ячейки y:(страница−3) — для страниц $528/$628/$728 это y:$525, y:$625,
y:$725 — и кладет в X:$2C4. Пишет его хост. Биты (проверено векторами
на всех 22 сетах):

| бит | значение                                                        |
|-----|------------------------------------------------------------------|
| 0   | прибавить выход кадра (шину Y:$0000-$1F) к bus1                  |
| 1   | ... к bus2                                                       |
| 2   | ... к bus3                                                       |
| 3   | «replace-режим» — см. ниже, В ЖЕЛЕЗЕ НЕ РАБОТАЕТ                 |
| 6   | ввод с кодека: моно, дубль в L/R (func_0002ed)                   |
| 7   | ввод с кодека: вариант моно (func_000302)                        |
| 6+7 | ввод с кодека: стерео, 64 слова как есть (func_000319)           |
| 8   | в конце блока: bus1 = bus1+bus2+bus3 (РЕЖИМ MIX)                 |
| A   | в конце блока: копия областей X:$2CA/$2CB в шины                 |
| C/D/E | replace-флаги для bus1/2/3 (работают только с битом 3)         |

Закон сложения — func_0001e2 ($01E2-$01EB): bus[i] += Y[i], i=0..31.
Закон замены — func_0001ec ($01EC-$01F1): bus[i] = Y[i].

ВАЖНОЕ ОТКРЫТИЕ: путь бита 3 ($0149 → $01F3-$0218) доходит до
func_0001e2/0001ec ВЕТВЛЕНИЯМИ bsclr/bsset, а обе функции кончаются
rts. Ветвление не кладет адрес возврата в стек → rts снимает пустой
системный стек → на реальном кремнии это прыжок по мусору. Хост бит 3
не выставляет ни в одном режиме роутинга — путь тупиковый, в порт он
включен как есть (ветвление сформулировано, но не исполняется ни одним
вектором).

## 4. Откуда берется шина Y:$0000-$1F

Это пишет сам кадр в самом конце (секция T6, $0B33-$0B49, уже была
бит-точной в паке 8):

    выход[i] = сухой_сигнал[i]·гейн[i] + эхо-компонента[i]·масштаб[i]

и раскладывает по трем направлениям:
  - Y:$0000-$1F — шина для пер-трекового микшера (см. п.3);
  - X:(X:$FF)+ — поток в хост (X:$FF перед этим = r5 = work-база);
  - 16 слов через X:(X:$2C9)+ — эхо-шина (delay send, Task 45).

Масштабы T6: глобальный DSND — ячейка Y:$4FF (пишет хост, Task 45:
«слышимый уровень посыла/возврата = DSND(хост)×(env·DWID)²») и
пер-трековая ячейка page+$1F. Если обе нули — шина тишина, роутинг
не виден (на этом поймали первый вариант оракула).

## 5. Конец блока: MIX и копия

После третьего суб-блока ($01A3-$01E1) DSP читает флаги ПОСЛЕДНЕЙ
страницы (X:$2C4) и:

- бит 8 → func_0001ad ($01AD-$01C1): bus1[i] = bus1[i] + bus2[i] +
  bus3[i] для всех 96 слов (3 суб-блока × 32), множитель $7FFFFF
  (то есть 1.0−2⁻²³, чистое копирование через умножитель);
- бит A → func_0001c2 ($01C2-$01E1): в шины копируется содержимое
  областей, на которые указывают X:$2CA/X:$2CB (эхо-регионы) — так
  обработанное эхо возвращается в шины для отдельных джеков;
- ни один бит → только сброс почтового ящика X:$4FE = 0.

Все три пути заканчиваются `jmp $0087` — возврат к опросу заголовка.
Это и есть естественная граница блока.

## 6. Ввод с кодека (биты 6/7)

func_0002ed ($02ED-$0301): читает статус ESSI ($FFFFEE), выбирает
свежую половинку буфера ввода X:$100/$120, копирует 16 слов с шагом 2
(один канал) и ЗАПИСЫВАЕТ КАЖДОЕ ДВАЖДЫ в work-область X:$2C3 —
моно-вход расходится в обе стороны стерео-кадра.
func_000319: обе половины как есть, 64 слова — стерео-ввод.

## 7. Архитектура страницы: полный словарь ячеек

Страница трека = $100 слов. Хвост кадра работает с r6 = страница−$28
(для y:$123 = $528 → r6 = $500), машина — с r6 = страница (=$528).

| ячейка (r6 хвоста) | смысл                                |
|--------------------|--------------------------------------|
| +$00               | слово трига+флаг «параметры менялись» (бит 7!) |
| +$01..$03          | питч/тик-служебное                   |
| +$04               | вмод/счетчик суб-блока (гейт ветки $04AB) |
| +$05..$06          | VOL, PAN (гейн-путь, пак 8)          |
| +$08               | BASE фильтра, +$0E WDTH, +$13 LPQ    |
| +$1F               | масштаб эхо-компоненты T6            |
| +$21               | вторая масштабная ячейка T6          |
| +$24               | ID машины (y:($123)−4)               |
| +$25               | ФЛАГИ РОУТИНГА (y:($123)−3 → X:$2C4) |
| +$28               | TRIG (бит7 = «параметры менялись», гейт INIT/CONF диспетчера) |

## 8. Что это значит для плагина (JUCE)

1. Роутинг портирован как MnmBlockMixer: 3 шины × 96 слов, флаги
   per-track (биты 0/1/2), MIX-суммирование (бит 8) — всё слово-в-слово.
2. DSND остается хост-параметром: множитель моно-эхо-шины (Task 45).
3. replace-режим (бит 3) в плагин не тащим — путь мертвый в прошивке.
4. Ввод с кодека (биты 6/7) — для плагина означает «моно-вход в стерео
   кадр дублируется» — ровно то, что делает наш входной пин.

## 9. Как проверить самостоятельно

Пак 9: test_block_routing.cpp + vectors/routing_vectors.txt.

    g++ -O2 -std=c++17 -I dsp/mnm -o test_block_routing test_block_routing.cpp
    ./test_block_routing vectors/routing_vectors.txt

Ожидается: checks=360756 mismatches=0 [100% BLOCK-ROUTING BIT-EXACT].

Вектора: 22 сета = 3 режима заголовка × флаговые паттерны (одиночные
биты 0/1/2, комбинации, MIX, копия, ввод 6/7, FM на разных суб-блоках,
реалистичные раскладки 6*MONO / 3*STEREO / 3*STEREO+AB / MIX, живые
ручки). Каждый сет = полный прогон блочного цикла ОС: заголовок →
3 суб-блока (флаги → INIT/CONF диспетчер → кадр пака 8 → микшер) →
конец блока (MIX/копия) → обратная граница $0087.

# FM-машины: починка законов ручек (STAT / PAR / DYN)

## Что было не так — по-простому

Ты сказал: «фм стат в оригинале имеет до 0 фрек опускаться, а у меня 0.2 минимум».
Проверил механически (эмулятор + чтение регистров, НЕ на слух). Вот что нашлось:

**В плагине жили ТРИ разные таблицы частот, и все три не совпадали друг с другом:**

1. **Звук (ядро)** — индекс в таблицу считался по формуле БЕЗ учёта сдвига `<<1`
   дробного умножения MPY в DSP. Итог: ручка 0..127 проходила только ПОЛОВИНУ
   таблицы. На ручке 127 оригинал даёт соотношение **8.0**, порт давал **1.25**.
   **123 позиции из 128 были с неверным соотношением.**
2. **Экран (UI)** — подпись ручки считалась по ДРУГОЙ таблице (32 ступени,
   1/64..12) — третья кривая, не совпадающая ни со звуком, ни с железом.
3. **Оригинал (железо, замер регистров на эмуляторе)** — закон:
   `n = floor(((K<<16) + $8000) * 48 / 2^24) = floor((K + 0.5) * 3 / 16)`
   — все 24 ступени таблицы Y:$141A80 достижимы: 1/32 ... 8.
   Замер снят с ОБОИХ мест выборки ($145D38 для оп2 и $145DAD для оп1) —
   значения идентичны.

**Про «до 0»:** через таблицу частота в НОЛЬ не падает — минимум оригинала =
1/32 (ручка 0). Но у оригинала есть ДРУГОЙ путь к нулю: питч-слово A. При A=0
машина пишет L:$5 = 0 и кэрриер замирает (а модуляторы продолжают звенеть на
собственной динамике уровней — это видно в векторах A=0). Порт такого не умел
вообще: его частота никогда не была ниже, чем даёт таблица. Теперь порт
принимает питч-слово напрямую (`setPitchWordOverride`) — включая честный 0.

## Что исправлено

| ручка | было | стало (как в оригинале) |
|---|---|---|
| 1FRQ/2FRQ (STAT), FRQ (PAR) | усечённый вдвое индекс, 12 ступеней | точный индекс, все 24 ступени (1/32..8) |
| 1FIN (STAT) | float-приближение | пословная математика слова ($145DAE-$145DB7): 0.75..1.2461, центр 64 |
| 1ENV (STAT) | линейно K/127 | **квадрат** (K/128)² — `mpy x0,x0,a; asl #$2` ($145DFB/$145E14) |
| 2VOL (STAT) | линейно | **гейт**: <64 оп2 молчит (`cmp #>$400000` $145D8C), ≥64 — уровень |
| 1FB (STAT) | линейно ×4 | закон слова K² |
| PAR/DYN целиком | float-ядро | **бит-точные ядра** MnmFmPar/MnmFmDyn (проверено на векторах эмулятора) |

## Доказательство (без ушей)

- Интеграция прогнана на векторах оригинала (`research/fm_par_vectors.txt`,
  `fm_dyn_vectors.txt`, сняты с эмулятора OS 1.32):
  - FM-PAR: **7168/7168 слов — точно** (14 конфигов ручек × 16 блоков)
  - FM-DYN: **8192/8192 слов — точно** (16 конфигов × 16 блоков)
  - макс. ошибка 0.14 LSB — только округление float-нормировки выхода
- Таблица сверки ручек: `knob_law_table_stat.md` / `.json` — позиция ручки →
  индекс и соотношение оригинала vs старого порта. 123/128 позиций расходились.
- Выход на дефолтных ручках (3C 40 50 1E 50 40 62 40) = 2.14 Q23 на всех трёх
  машинах — нормировка выхода сделана по этому замеру (1/17949485).

## Как поставить

```
python3 apply_patch.py <путь к Monomachine-Nova-1.9.9 ...>/Monomachine_Nova_Synth/Source
```

Скрипт скопирует 5 файлов в `dsp/mnm/` и покажет, что обновилось.
`NovaDSP.h` менять НЕ надо — публичный API FmCore сохранён (добавлены только
новые методы `setPitchWordOverride`). Для звука из питч-матрицы/оффсета можно
передавать точное питч-слово ядра — в том числе 0 (кэрриер стоит).

## Патч экрана (PluginEditor.cpp, строка ~915)

Было:
```cpp
if((machine==8||machine==9)&&(label=="1FRQ"||label=="2FRQ"||label=="3FRQ"))
    return juce::String(monomachine::getFmListedRatio(static_cast<uint8_t>(raw/4)),2);
```
Стало (та же таблица и тот же закон, что в звуке):
```cpp
if((machine==8||machine==9)&&(label=="1FRQ"||label=="2FRQ"||label=="3FRQ"))
{
    static constexpr float kR[24] = {0.03125f,0.0625f,0.125f,0.1875f,0.25f,0.3125f,
        0.375f,0.5f,0.625f,0.75f,0.875f,1.0f,1.25f,1.5f,1.75f,2.0f,2.5f,3.0f,
        3.5f,4.0f,5.0f,6.0f,7.0f,8.0f};
    const int K = juce::jlimit(0, (int)raw, 127);
    const int n = juce::jlimit(0, 23, (((K<<16)+0x8000)*48)>>24);
    return juce::String(kR[n], 2);
}
```
Теперь на ручке 127 экран покажет 8.00 — как и звучит, как в железе.

Этот архив — «старое», то есть ИСХОДНИКИ доказательств для архива 1
(mnm_1_NEW_code_FM_2026-09-28.tar.gz). Ничего отсюда не нужно плагину
для сборки: сюда можно просто заглядывать и читать. Удалять не обязательно.

ЧТО ЗДЕСЬ ЛЕЖИТ
---------------

README_FM_KNOB_FIX.md
    Главный документ: что было сломано в ручках FM STAT, как это
    нашли и починили. В том числе ответ на твой вопрос про
    «частота до 0 vs 0.2». ЧИТАТЬ ПЕРВЫМ.

knob_law_table_stat.md / .json
    Таблица сверки «позиция ручки -> соотношение»: оригинал (железо,
    замер на эмуляторе) vs старый порт. Видно, что 123/128 позиций
    расходились и как теперь совпадают.

FM_EXACT_MINING.md
    Как снимались эталонные векторы с эмулятора OS 1.32 (метод).

vectors/fm_par_vectors.txt
    Эталонные выходы FM PAR: 14 конфигов ручек x 16 блоков, 7168 слов.
    Именно по ним ядро MnmFmPar.hpp сверено побайтово (7168/7168).

vectors/fm_dyn_vectors.txt
    Эталонные выходы FM DYN: 16 конфигов x 16 блоков, 8192 слов
    (8192/8192 совпали).

tools/
    dsp_emu.py            эмулятор DSP563xx (сердце всех проверок);
    run_kernel.py         харнес запуска ядра;
    fm_harness.py         прогон FM-машин на эмуляторе;
    fm_knob_sweep.py      автоснятие законов ручек (замер регистров);
    tools_fm_knob_sweep.py автосверка «ручка -> значение» (та самая
                          пакетная проверка, чтобы не сверять на слух);
    exp61_fm_vectors.py   снятие векторов PAR/DYN;
    exp62_fm_stage_dump.py дамп стадий FM;
    cmp_fm_stages.py      сравнение эмулятор vs C++;
    test_fm_par_dyn.cpp   тест-программа C++ (гоняет ядра на векторах);
    dbg_fm_stages.cpp     отладочный дампер стадий.

КАК ПЕРЕПРОВЕРИТЬ САМОМУ (не обязательно)
----------------------------------------
Полные команды и пути — внутри FM_EXACT_MINING.md и README_FM_KNOB_FIX.md.
Коротко: векторы снимаются exp61_fm_vectors.py на эмуляторе с дампами
OS 1.32, затем test_fm_par_dyn.cpp прогоняет те же векторы через C++
ядра и сравнивает слово-в-слово.

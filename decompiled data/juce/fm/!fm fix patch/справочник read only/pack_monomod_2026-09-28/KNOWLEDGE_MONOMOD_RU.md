# MONOMOD (Monomodule) — ЭТАЛОН. Полная выжимка знаний для порта в JUCE
Дата: 2026-09-28. Источник: `decompiled data/monomod` из репо glassg333/mmnova.
Назначение: каноническая сверка нашего JUCE-порта с оригиналом БЕЗ гаданий.

## 1. Что это и почему это эталон

Monomodule — открытый (AGPLv3) плагин, который запускает **оригинальный звуковой движок
Monomachine из пользовательского файла ОС** (`Elektron_SFX6-60_OS1.32B.syx`) внутри
эмулятора Motorola DSP56300 (проект dsp56300, GPLv3, пиннутый коммит
`c051afad31612c2d2c7a81a7ab23e1c5ac9e61af` + патч `ext/patches/0001-dsp56300-mnm.patch`).
Он НЕ переписывает DSP-код — он его ИСПОЛНЯЕТ, поэтому совпадает с железом
посэмплово по построению. Минус для нас прежний: нужен .syx. Но теперь это наш
ГЕНЕРАТОР ИСТИНЫ: любые 52-слова на входе → ровно те 32 слова на выходе, что даёт машина.

## 2. Протокол обмена с DSP (харнесс вместо DMA/ESSI) — ПОДТВЕРЖДЕНО НАШИМИ ХУКАМИ

- Блок = **16 кадров**. Вход: **52 слова** через HI08 → ядро копит их в **Y:$500**.
- Выход: **32 слова** из **Y:$0..$1F** (L/R вперемешку: L0,R0,L1,R1,...) — пишутся
  хвостом цепочки в P:$0B45/$0B46. Это ТОТ ЖЕ 32-словный блок, что мы поймали хуками.
- Блоки идут **тройками**; первый блок каждой тройки = «кадр» (48 сэмплов, 1 мс при 44.1к).
- Инициализация (замена инициала кернела A $0066..$0086):
  `jsr $100077` (строит синус-таблицу 8192 слов в **Y:$14A000**),
  `jsr $100139` (чистит X-память и внешние буферы), `jsr $145CCE`
  (инит ТРЁХ структур трека **Y:$500/$600/$700**), сентинел в хост `$00C0DE`.
- Далее стаб: ждёт 52 слова → Y:$500 → `jmp $0092` (родной проход трека кернела:
  блок указателей, y:$123/$124, диспетчер трека 0, рендер, цепочка) →
  патч **P:$0143** (начало шага микширования) → короткий jmp на вывод 32 слов.
- Прочие регистры: AAR3=`$1C0639` (юнит с доп. памятью MKII), DMA0-приёмник `$120`,
  ADC-кольцо входа **X:$100..$11F** (вход FX-машин), Digibank (DPRO DDRW/DENS):
  64 слота × 2048 слов в **Y:$150000 + слот*$800**.

## 3. РАСКЛАДКА 52-СЛОВНОГО БЛОКА (HostModel.h `enum Word`) — КЛЮЧ КО ВСЕМУ

| Слово | Имя | Смысл |
|---|---|---|
| 0-7 | AMP | ATK HOLD DEC REL DIST VOL PAN PORT (raw<<16) |
| 8-15 | FILT | BASE WDTH HPQ LPQ ATK DEC BOFS WOFS |
| 16-23 | EFX | EQF EQG SRR DTIM DSND DFB DBAS DWID |
| 24-28 | Extra0..4 | экстра-байты кита 64..68 (raw<<16) |
| 29 | W29 | 0 |
| 30 | PitchMod | сумма питч-модуляции, покой = **64<<16**; DSP: `pitch += w30*0xB000*2/2^24 − 0x5800` (=352 ед./шаг; 64 точно гасит −0x5800) |
| 31 | Level | громкость трека (raw<<16), дефолт 100 |
| 32 | FiltTrig | one-shot триг фильтровой огибающей |
| 33,34 | W33,W34 | 0 |
| 35 | TickRecip | **0x800000 / tick** |
| 36 | MachineIdx | индекс машины (FM_STAT=8, FM_PAR=9, FM_DYN=10, ...) |
| 37 | Mode | роутинг (биты ниже) |
| 38 | Tune | мастер-тюн: u16 ≈ 65536·f/440, **знакорасширенный**: 440Гц→−1; 400Гц→−5958 (−1.65 пт); прибавляется к питч-индексу (2048 ед./окт) |
| 39 | Peek | 0 |
| 40 | NoteTrig | **0x81 = note on, 0x02 = note off, бит7 = init/триг при назначении машины** |
| 41 | Pitch | питч-слово = **(note<<11)/12** (60→10240, 69→11776, 127→21674) |
| 42 | Tick | **24 × BPM**, кламп 30..300 BPM (720..7200) |
| 43 | W43 | 0 |
| 44-51 | SYN | 8 ручек машины (raw<<16) |

### Роутинг, слово 37 (биты)
0/1/2 = OUT BUS AB/CD/EF (добавление; или замена, если трек сам читает этот же автобус);
3 = читать автобус (12/13/14 = AB/CD/EF); 4 = aux-буфер (NEIBOR);
6/7 = ADC L/R (INP A/B); 9 = LPF следует за нотой, 11 = HPF следует за нотой
(KIT>ASSIGN>KEY, по умолчанию ОБА включены); 8 = глобальный AB=MIX; 10 = 6xMONO.
FX-источники (порядок sysex $5C): NEIBOR, INP A, INP B, INP AB, BUS AB/CD/EF.

### Тайминг хоста (HostModel.cpp) — для честной эмуляции управления
- Каждый кадр (каждый 3-й блок): защёлкиваются NoteTrig/FiltTrig/Pitch, слова страницы
  Extra0..4, TickRecip, MachineIdx, Mode, Tune; one-shots уходят один раз и гасятся.
- **Слюнк страниц: на каждом 8-м кадре (f%8==1)** каждое модулируемое слово едет к цели:
  **`w = (3*w + (raw<<16)) >> 2`** (AMP/FILT/EFX 0-23, SYN 44-51, word 30, word 31).
  Это «ползание» ручек ~0.2 с после загрузки кита — у нас в порту этого НЕТ.
- LFO: f%8==0 → шаг фазы (каждые **24 DSP-блока**), f%8==1 → повторный apply после слюнка,
  каждый ЧЁТНЫЙ кадр → `acc += delta` (4 раза на шаг). LFO живёт В ХОСТЕ (не в DSP!),
  32-битная целая математика, складывается в целевые слова блока до отправки.
- RND-генератор LFO: seed `rndA=0x012D3D16, rndB=0x0000029A`.

## 4. МАШИНЫ: индексы, ручки, ДЕФОЛТЫ (Machines.h) — сверено с нашими дескрипторами

FM_STAT(8) «FM+ STAT»: 1FRQ 1FIN 1ENV 1FB 2FRQ 2VOL TONE TUNE = **60 64 80 30 80 64 98 64**
FM_PAR(9)  «FM+ PAR»: 1FRQ 1ENV 2FRQ 2ENV 3FRQ 3ENV TONE TUNE = **60 64 80 64 102 80 98 64**
FM_DYN(10) «FM+ DYN»: 1FRQ 1FEN 1VOL 1VEN 2FRQ 2ENV 2FB TUNE = **64 64 64 64 74 80 30 64**
(= hex 3C 40 50 1E 50 40 62 40 / 3C 40 50 40 66 50 62 40 / 40 40 40 40 4A 50 1E 40 —
СОВПАДАЕТ с нашими дескрипторами в MnmFm.hpp. Пак 5 прав.)

Прочие дефолты: AMP = {0,0,64,64,64,64,64,0}; для FX-треков {0,0,127,127,64,64,64,0}
(DEC/REL=127 = огибающая держится открыто); FILT = {0,127,0,0,0,32,64,64};
EFX = {64,64,0,64,64,28,0,127}.
Индексы машин: GND0 SIN1 NOIS2 SID3 SAW4 PULS5 WAVE6 BBOX7 **FM8/9/10** VO6-11 THRU12
REVERB13 ENS14 CHORUS15 DYNAMIX16 RINGMOD17 PHASER18 FLANGER19 DDRW32 DENS33.
FX-машины = THRU, REVERB, CHORUS..FLANGER; ENS(14) — НЕ FX (иначе огибающая висит открытой).
Биполярный дисплей (значение−64): маски AMP=0x50 (DIST,PAN), FILT=0xC0 (BOFS,WOFS),
EFX=0x12 (EQG,DSND); у машин свой бит-маск (STAT: 0x82 → 1FIN и TUNE).

## 5. ТАБЛИЦЫ ВНУТРИ DSP — дамп из эталона приложен (etalon_tables/)

- **Y:$14A000**: синус-таблица 8192 слов, строится кодом прошивки на старте.
  ЭТАЛОН: полный масштаб Q1.23: пик +0x7FFFFF при i=4096, −1.0 = 0x800000 при i=6144.
  ⚠ НАЙДЕННО РАСХОЖДЕНИЕ: наша `MnmFmSineTable.h` отличается (у пика наша значение меньше,
  в 62% записей ±1 LSB, форма чуть иная). FM-ядрам не вредит (их бит-точность доказана
  векторами с живой машины — FM свою синус-математику не из этой таблицы берёт),
  но ПЕРЕД портом SIN/SWAVE/ENS/TONE-путей таблицу заменить на эталонную (файл приложен).
- **Y:$141A80**: таблица отношений FRQ: 24 значения 0x4000..0x400000 (1/64..4) с клампом
  0x7FFFFF дальше. Наш `kFmRatioExact` = **24/24 бит-в-бит ИДЕАЛЬНО**.
- **X:$140000**: ПИТЧ-LUT (та, которой нам не хватало!): **1024 слов**, покрывает
  ПОЛ-октавы (span = √2), шаг 2^(1/2048) на запись, формат Q2.22 (1.0 = 0x400000),
  верхняя половина октавы — октавным сдвигом кернела (структура $2C0..$2EB:
  LUT + октавный сдвиг + mpy $1D22A, asr#3). Дампа не было ни в одном нашем майнинге —
  теперь есть. Это закрывает пункт «питч-слово целое, ±1.7 цента» из ограничений пака 5.

## 6. Чем исполняют (важно для будущих сверок)

- Эталонный движок = **JIT**; интерпретатор dsp56300 имеет баг насыщения
  аккумулятор→память (a=−1.0−eps пишет $7FFFFF вместо $800000) — портит синус-таблицу.
  `MNM_DSP_INTERP=1` только для отладки.
- Патч dsp56300 (601 строка): арифметический режим насыщения SM в ALU-опах, PFLUSH =
  полная очистка кэша, `interruptRegionIsCode` (короткие прерывания JIT не ломают
  главный цикл кернела A в P:$0087..$00FF).

## 7. Как пользоваться mnm-render (готовый бинарник под Linux x64 приложен)

```
mnm_render_bin/mnm-render \
  --fw Elektron_SFX6-60_OS1.32B.syx \
  --machine "FM+ STAT" --note 60 --dur 1.0 --tail 1.0 \
  --syn 60,64,80,30,80,64,98,64 --amp 0,0,64,64,64,64,64,0 \
  --filt 0,127,0,0,0,32,64,64 --efx 64,64,0,64,64,28,0,127 \
  --lfo1 0,0,0,0,0,64,0,64 --tune 440 --bpm 120 --level 100 \
  --dump-blocks blocks.txt --out out.wav
```
`--dump-blocks` печатает КАЖДЫЙ блок: `block N in: <52 слов hex>` + `out: <32 слов hex>`.
Это генератор золотых векторов для ЛЮБОЙ машины и ЛЮБОЙ ручки: прогнали — сверили порт.
Дефолты вызова: note 60, level 100, tune 440, bpm 120 (tick 2880), dur/tail 1.0/1.0.
`--tick N` — прямой tick (например 345 воспроизводит старое отображение темпа до v0.7.6).
Рендер 1 с аудио ≈ 0.18 с на обычном ПК.

## 8. Сборка под Linux БЕЗ JUCE (проверено: собралось и работает)

```
pip install cmake   # или системный cmake ≥3.22
cmake -S <monomod> -B build -DCMAKE_BUILD_TYPE=Release \
      -DMNM_BUILD_PLUGIN=OFF -DMNM_BUILD_TESTS=OFF \
      -DMNM_OS_SYX=<путь>/Elektron_SFX6-60_OS1.32B.syx
cmake --build build --target mnm-render -j
```
CMake сам скачает dsp56300 (нужен интернет), наложит патч и соберёт только core+cli.
Ручная линковка утилит: libmnmcore.a + libdsp56kEmu.a + libdsp56kBase.a + libasmjit.a
+ libvtuneSdk.a -lpthread -ldl (см. scripts/dump_etalon_tables.cpp в нашем дереве).

## 9. Что это меняет в дорожной карте порта (JUCE, без .syx)

1. **Эталон навсегда закрывает спор «кто прав»**: любое расхождение плагина с машиной —
   прогон mnm-render с теми же 52 словами и сравнение 32 слов выхода.
2. Протокол/раскладка/тайминг из п.2-3 — спецификация нашего host-слоя плагина:
   добавить слюнк (3w+raw<<16)>>2, тройки блоков, слово 30/35/37/38/40/41/42 как здесь.
3. LFO переехать в хост с этой 32-битной целой арифметикой (Lfo.cpp — готовая референс-
   реализация, плюс tests/test_lfo.cpp).
4. Таблицы: ratio у нас точна; синус заменить на эталонный дамп; питч-LUT внедрить
   в питч-путь PAR/DYN/STAT — убрать последнее приближение (±1.7 цента).
5. AMP/FILT/EFX-страницы и FX-машины — теперь есть бесконечный источник векторов
   (у нас были только FM и ringmod/динамика).

- `monomod/` — исходники Monomodule целиком (как в репо), включая .syx 1.32B и патч эмулятора.
- `etalon_tables/etalon_sine_14A000.txt` (8192), `etalon_ratio_141A80.txt` (32),
  `etalon_pitchlut_140000_full.txt` (4096 слов, ненулевые первые 1024).

  (cmp_etalon_tables.py) с результатом: ratio 24/24, синус — расхождение описано.

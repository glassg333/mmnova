## TUNE (все машины)

центов = (K−64) × 3.1265258789  (закон прошивки: 683/128 шага на шкале X:$140000, 2048 шагов/октава).
K=0 → −200.10 цента (2 полутона вниз, C→A#), K=127 → +196.97 («не хватает до D»).

## Что было не так в плагине

1. Таблица STAT/PAR делилась на 2^19 вместо 2^20 — вся ручка была **+1 октава** (1/32..8 вместо 1/64..4).
2. Экран брал третью таблицу getFmListedRatio (1/64..12) — цифры не совпадали ни со звуком, ни с железом.
3. DYN в старом движке имел самодельный закон частоты; канон: 1FRQ=K/64, 2FRQ=(K/64)².
4. TUNE в старых движках считался как (K−64)/64×12 полутонов (±12!) вместо ±2 полутонов по закону прошивки.

## Проверка (этот скрипт)

- STAT/PAR: множество 24 соотношений = списку пользователя; дефолты сходятся.
- DYN 1FRQ: 85 известных точек пользователя — все совпали (середина 43..85 в его пасте задублирована).
- DYN 2FRQ: 128/128 точек совпали (допуск округления его записи).
- TUNE: −200.06/+196.94 цента на краях — как описал пользователь.

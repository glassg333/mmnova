ПАК 7 — ФИКС ПИТЧА FM: ОКТАВА + БИТ-ТОЧНЫЙ ЗАКОН ЧАСТОТЫ. 2026-09-28.

ГЛАВНОЕ
-------
Найден и закрыт ГЛАВНЫЙ баг FM-плагина: обёртка подавала в бит-точные ядра
питч-слово «частота в Гц» (440 для ноты 69), а машина ОС ожидает 48-битный
аккумулятор acc — линейное слово частоты ~f*2^24. Плагин играл FM НА ОКТАВУ
НИЖЕ оригинала. Плюс сам закон теперь не приближение, а точные целые числа,
снятые с оригинальной прошивки.

КАК ДОКАЗАНО (без гаданий, всё на эмуляторе dsp56300)
-----------------------------------------------------
1. Эталон: Monomodule (исходники в репо, decompiled data/monomod) исполняет
   ОРИГИНАЛЬНУЮ ОС 1.32B (Elektron_SFX6-60_OS1.32B.syx) на эмуляторе dsp56300.
2. Захват: пошаговое исполнение (JIT single-step) с чтением регистра A на входе
   PROC каждой FM-машины ($145D21 STAT, $145EC9 PAR, $14619D DYN).
3. Снята золотая таблица: 3 машины x 128 нот x 2 тюна (440/400 Гц), по 12
   блоков на ноту (глинд сходится). Файл research/fm_pitch_golden.json.
4. Факты:
   - все 3 машины получают ОДИНАКОВЫЙ acc (совпало 100%);
   - acc ТОЧНО удваивается на октаву (линейное слово частоты, ~f*2^24);
   - при тюне 440 Гц acc ноты 69 = 0x1B7CD1771 = 7,378,638,705 (~440*2^24);
   - внутренний индекс питча кернела на +2 полутона (+341.33 ед. 1/2048 окт)
     выше хостового слова 41 — учтено в клампе низа;
   - питч-индекс < 0 ОС клампит на константу kFmAccFloor = 122,172,277
     (замерено: тюн 400 Гц, ноты 0..32 — все играют один «замороженный» низ);
   - интонация самой ОС на ~0.8 цента ниже равномерной темперации
     (тюн-слово −1 ед. = −0.586 ц + пол LUT ~−0.2 ц) — это ТАК В ОРИГИНАЛЕ.

ЧТО В КОДЕ
----------
dsp/mnm/MnmFmPitch.h  — НОВЫЙ: kFmGoldenAcc[128] (acc каждой ноты, тюн 440),
                        kFmAccFloor, kFmTuneWord440.
dsp/mnm/MnmFm.hpp     — новый питч-путь: accForNote(noteFloat) = золотой
                        якорь * 2^(дельта питч-индекса/2048); тюн-слово ОС
                        int16(65536*tune/440) с клампом 65535 (при 440 -> -1);
                        кламп низа; setMasterTuneHz()/getMasterTuneHz();
                        процессExact кормит ядра int64-acc.
dsp/mnm/MnmFm{Stat,Par,Dyn}.hpp — proc(uint32_t) -> proc(int64_t): ядра теперь
                        принимают полный 48-битный acc (раньше старшие биты
                        терялись на uint32).

ТОЧНОСТЬ
--------
- Мастер-тюн 440 Гц, без бенда: acc = ОС БИТ-В-БИТ на всех 128 нотах
  (тест: 128/128).
- Другой тюн/бенд: якорь * 2^(дельта/2048) — расходится с ОС не более чем на
  ~0.3 цента (дрожание полов LUT самой ОС; у самой ОС квант питч-слова
  0.586 цента). Замерено на тюне 400: худш 0.305 цента.
- Регресс законов ручек: свип 168 наборов x 8 ручек x 3 машины —
  1344 блока, 177 408 слов, mismatches = 0 [100% BIT-EXACT] — ядра не тронуты
  (только тип входа: uint32 -> int64).
- Выход C++-обёртки = слова Python-эмулятора ОС на золотом acc: совпадение с
  точностью 1 LSB float-нормировки (1/17949485) — целочисленно бит-в-бит.

УСТАНОВКА
---------
    python3 apply_patch.py <путь до репо или Source>
Ставит 7 файлов в <Source>/dsp/mnm/. Повторный запуск безопасен.
NovaDSP.h менять не надо. Старые паки 1/3 заменяются этим (супerset).

ЧТО ДАЛЬШЕ (честно)
-------------------
- Хост-слой: слюнк ручек ОС (3w+raw<<16)>>2 на каждом 8-м кадре, тройки
  блоков, слова 30/35/37/38/40/42 — сейчас ручки применяются мгновенно.
- AMP/FILT/EFX-страницы и полный кадр голоса (DIST/FILTER) — пак 5 (FILT ENV
  stage 2) уже бит-точный, ждёт интеграции.
- LFO: живут в хосте ОС (32-битная целая математика) — референс Lfo.cpp
  в monomod.
- Синус-таблица MnmFmSineTable.h отличается от runtime-таблицы ОС (±1 LSB,
  форма чуть иная) — FM не задето (FM свою математику не из неё берёт),
  заменить перед портом SIN/SWAVE/ENS.

# DSND / DTIM — данные ручки и полный роутинг (свод итерации 29)

**Свод по вопросам: «DSND — данные ручки и роутинг», «retune speed эха для
DTIM», «значения DTIM».** Первичные доказательства: `17_delay_echo/`
(итерация 24, DSP-сторона эха), `20_coldfire_clock/` (итерация 27, OS-роутинг
ручек), `21_echo_kernel_routing/` (итерация 28, ядро DSP: глайндвижок DSND/
DBAS). Этот файл — единая карта без устаревших утверждений.

## 1. Страница EFFX: карта ячеек (ПОПРАВЛЕНО по итерации 28)

Ручки эффекта delay/echo живут в словах страницы P+$18–$1F (хост пишет
значение как v<<16, v = 0..127, через DMA5 — 51 слово страницы, итерация 26).
Статус «кто читает в DSP-ядре» — ПОСЛЕ поправки итерации 28 (скан-24 искал
смещения от базы страницы, а ядро читает через r6 = страница+$28):

| Ячейка | Ручка | Кто читает в DSP | Где |
|--------|-------|------------------|-----|
| P+$18 | EQF | EFX-конверт, кривая атаки tblA[$141800] | $04B4 |
| P+$19 | EQG | EFX-конверт, кривая затухания tblB[$141880] | $04CC |
| P+$1A | SRR | EFX-конверт, сустейн = SRR² | $04C9/$04DE |
| P+$1B | DTIM | EFX-конверт, кривая release tblB[$141880] | $04E5 |
| P+$1C | DSND | **ЯДРО: глайндвижок $000262, чтение $000284** (y:(r6−$0C)) | см. §3 |
| P+$1D | DFB | **ДОКАЗАТЕЛЬНО не читается DSP** (полный скан 3 конвенций адресации, итерация 30) → feedback применяет ColdFire-микш | 24_dfb_knob_spec_map/ §1 |
| P+$1E | DBAS | **ЯДРО: глайндвижок $000262, чтение $0002C8** (y:(r6−$0A)) | см. §3 |
| P+$1F | DWID | рампа микша T5: mod[k] = (env·DWID)² | $0B1E |
| P+$2A | (хост) | множитель длины эха: target = P$2A·T2[LPQ]·$21D10 | $099D |

Утверждение итерации 24 «DSND/DBAS в ядре не читаются» снято (см. блок
«НОВОЕ В ИТЕРАЦИИ 28» главного README); DFB ЗАКРЫТ итерацией 30:
ни y:(r6−$0B), ни x:(r6−$0B), ни y:(r6+$1D) голосовой цепи — нуль чтений
по всем конвенциям; обращения машин к r6+$1D — машин-локальный скретч
(для m18 доказано: квадрура-стейт LFO). См. 24_dfb_knob_spec_map/.

## 2. DSND: OS-сторона (роутинг ручки → ячейка)

Цепочка от поворота ручки до слова страницы (все шаги расшифрованы в
итерациях 26–28, `20_coldfire_clock/`):

1. Значение ручки попадает в staging-структуру хоста (6 записей по $D0 в
   $1000A54–$1000F34; таблица отправителей — §5 README итерации 26).
2. Обработчик спецификаций **$242058** декодирует тройки байтов
   (j = 0..11, шаг 12): группа = $7001FA+t·12+j, смещение = $700242+t·12+j,
   третий байт = $70028A+t·12+j.
3. Диспетчер **$2403D4**(track, группа, смещение) возвращает АДРЕС ячейки:
   группа 2/3/4 → `$1000A14 + (группа·8 + track·52 + смещение)·4` — одно
   слово страницы на один указатель (группа 2 → слова 0–7, 3 → 8–15,
   4 → 16–23); группа 0 → staging+$78; группа 1 → флаги staging+$B0;
   группы 5–7 → строки $1000E94; спец-случай $240412 → $1001174.
4. Глайд ручки: указатели на ячейки $1001508+t·$30, скорости $10013E8+t·$30,
   исполнение в $267A12 (cell += rate, клампы $7EFFFF/0).
5. Слова страницы $00–$2F (включая P$2A) грузятся из OS-структуры
   $10018A2+t·$120+$54 (цепочка $700039+t·$18 → расширение → $1001880+t·$120
   → срез в staging, блок $2426AE–$2426D4).

**Вердикт (дополнен итерацией 30):** сами значения спецификаций (какая ручка в
какую группу/смещение) — данные пресета в RAM, НЕ константы ROM: единственный
писатель массивов — функция назначения **$24272E** (клампы группа≤8 /
смещение≤7 / третий≤$40, ветви $2427B4/$242968 по флагу $2BFF12), её 8
вызовов — подсистема $212xxx ($21240C/$212456/$2125E6/$212702/$2127FE/
$212944/$214B26/$214F80); перезагрузчик $21273C+$21268E ре-применяет текущие
значения через геттер $242BD0 (глобалы $26AE40/$26AE70/$26AEA0), первоисточник —
структура пресета (глобалы $26AF74…$26AF98, копирование $2015F4). Обработчик
$242058 применяет запись «bank» = 12 суб-слотов к 12 указателям глайда
$1001508+t·$30 (чётные суб-слоты → 0–5, нечётные → 6–11). Полная машинерия —
`24_dfb_knob_spec_map/` §2. Карта «ручка DSND → ячейка P+$1C» подтверждена
дескриптором OS (page_templates) и чтениями ядра.

## 3. DSND: DSP-сторона (что ядро делает со значением) — ГЛАВНОЕ

Глайндвижок ядра **$000262–$0002EA** (открыт в итерации 28) читает DSND как
**индекс скорости глайда A**:

```
idxA  = DSND >> 16                     ; $000284: y:(r6−$0C), r6 = страница+$28
rateA = frac(T[idxA] · P$2A >> 8)      ; T = таблица Y:$1449C6 (256 слов)
accA  += rateA                         ; 48-бит аккумулятор X:$504:X$505
snap/кламп accA к цели = тень P+$22    ; X:$502 / X:$507
```

- **Больше DSND → МЕДЛЕННЕЕ глайнд**: таблица убывает от [1] = $010F79
  (0.00828) до [127] = $00000A; [0] = $FEDCBB отрицательный; [128..255] —
  вторая кривая (экспоненциальный подъём $0→$7FFFFF). Полная таблица:
  `21_echo_kernel_routing/table_1449C6_glide_rates.bin/.txt`.
- Симметричный канал B: idxB = P+$07>>16, acc X:$508:X$509, цель = тень P+$29.
- **Позиция чтения** (результат глайда):
  `X:$501 = accB + P+$26 + $B000·DBAS − $5800 + accA`, кламп [0, $5800].
- Позиция декодируется в длину задержки 22-битным float:
  `len = X:$140000[X:$501 & $7FF] >> 10 << (X:$501 >> 11)`;
  `a = len·$1D22A >> 3` — аргумент PROC машин (X:$140000 = 2048-словная
  мантисса 0.5→1.0, извлечена: `table_140000_mantissa.bin/.txt`).
- Читатели X:$501 — PROC'и машин ($14594C, $145AE7 — внутри PROC m14,
  $145C09/$145C24, $147336, $1479AB/$1479D4).

Итог по семантике: **DSND на DSP — это скорость подстройки (glide rate)
компоненты A позиции чтения эха**, а НЕ «send-уровень». Send-уровень
(доля голоса в эхо-шине) прикладывается ColdFire-микшером к покадровому
вкладу T4/T6 — подтверждено отсутствием иных чтений P+$1C в ядре.

## 4. Echo: retune speed (для DTIM) — числа

1. **Глайд длины**: L:P+$CF → цель L:P+$CD однополюсником с α = **0.1/кадр**
   (коэффициенты $0CCCCD = 0.05 и $733333 = 0.45: a = 0.05·target +
   0.45·current·2⁻²³-масштаб → итог 0.1/0.9; блок $09CB–$09EE). Проверено
   одиночным кадром: L=0, T=$40000000 → L' = $19999A ровно (exp24e).
   При 44.1 кГц (кадр = 16 сэмплов): **63 % за ~7.3 мс, 95 % за ~11 мс**.
2. **Слюй позиции чтения**: глобальная 48-бит L:$FC съезжает к
   (запись − длина) максимум на **±4 слова за кадр** (clamp ±4,
   $09AB–$09C9) — дискретный подъезд тапа.
3. **Взведение эха** (гейт): T1[LPQ]·TEMPO·$791FD0·32 ≥ $4000, где
   TEMPO хост пишет как BPM<<16; при LPQ=0 гейт закрыт (T1[0] = 0.0039).
4. **Целевая длина**: `L:P+$CD = P$2A · T2[LPQ] · $21D10` (линейность по
   P$2A подтверждена ×2.0000). Кольцо эха — 16384 слова (маска $3FFF).

## 5. Значения DTIM

DTIM (0–127) входит в DSP ровно в одном месте — **EFX-конверт ширины**
($04A8–$04F5): кривая release `env −= env·tblB[$141880][DTIM>>16]`
(состояние 2 конверта). Полная машина конверта:

```
ATK: env += tblA[$141800][EQF>>16]      ; EQF=127 → tblA[127]=0 (атака off)
DEC: env −= env·tblB[$141880][EQG>>16]  ; спад до SRR² → SUS
SUS: env = SRR²                          ; SRR=127 → сустейн вне досягаемости
REL: env −= env·tblB[$141880][DTIM>>16]  ; ← DTIM здесь
выход: T5: mod[k] = (env·DWID)²  → мастер-микш T6
```

Замеренные траектории (exp24_echo.py, проба E): все ручки 0 → атака
0.0625→0.0857 (насыщение ~1/e за ~4 кадра); EQF=127 → env замирает на 0;
SRR=127 → env держится на цели атаки; все 64 → мгновенный спад к нулю.
Таблицы кривых tblA/tblB — общекодовые кривые конвертов ядра
(01_filter/tables/, `tables_analysis.json`).

**Сама длина эха от DTIM на DSP НЕ зависит** — она приходит хостом через
P$2A (§4 п.4). Т.е. «значения DTIM» = индекс скорости release-кривой
конверта ширины; численная зависимость длительности хвоста ширины от DTIM:
t_rel ≈ (1/(DTIM>>16 → tblB-значение))·кадры — таблица tblB общая, значения
в `01_filter/tables/`. Замеренные величины T2 (цели длины по LPQ):
T2[32] ≈ 0.977, T2[64] ≈ 124.95, T2[96] ≈ 64.81, T2[127] ≈ 0.252 — таблица
сырая 8192 слов, немонотонность подтверждена (итерация 27).

## 6. Свод: полная карта сигнального тракта эха

```
голос → T4/T6 (ColdFire-микш, вес = send/DSND на хост-стороне)
      → X:$2C9 (мастер-микш пишет 16 слов/голос, $000B33–$000B4B)
      → X:$2CA/$2FC (DMA4-блок хоста, 47 слов, команда $000259)
      → кольцо 16384 слова, длина = P$2A·T2[LPQ]·$21D10, глайд 0.1/кадр
      → позиция чтения = accA(DSND) + accB(P+$07) + DBAS-база (глайндвижок $000262)
      → 17 тапов → func_397 → T6 → выход + шина X:$2C9
ширина: EFX-конверт (EQF/EQG/SRR/DTIM) × DWID → (env·DWID)² → T5/T6
```

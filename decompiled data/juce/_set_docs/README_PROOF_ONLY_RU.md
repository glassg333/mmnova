# MNM BLOCKS FOR JUCE — strict proof-only clean set

Дата аудита: 2026-09-18 (Europe/Moscow). Репозиторий: `glassg333/mmnova`.
Проверенный commit: `9dd0e6aa0c48126df1ec1cfa9a0a808a98d00307`.
Исходная папка: `decompiled data/MNM BLOCKS FOR JUCE`.

## Важный вывод

В исходной папке **не осталось ни одного самодостаточного JUCE/C++-блока,
который можно честно назвать полностью доказанным**. Поэтому этот архив
намеренно не содержит `Source/` с приближёнными реализациями. Он сохраняет
только проверенные сырые данные, проверенную метаинформацию и короткий след
доказательства. Это сделано по строгому правилу: если хотя бы важная часть
блока не подтверждена исходным листингом/байтами или есть сознательное
отклонение от ROM, блок не включается.

## Что сохранено

* `data/kernel/*.bin` и `*.txt`: сырые таблицы; байты сверены с
  `decompiled data/02_memory_images/dsp1_pmem.bin` по адресу `addr*3`.
* `data/bbox_drum_bank.bin`: 187068 байт; сверяется с P:$103E7B.
* `data/pitch_wavetable_2048.bin`: байты совпали с тем же P-образом при
  смещении P:$140000*3. В исходном аудите пространство X/P для этого
  runtime-адреса помечено неоднозначно, поэтому это сохранено с пометкой
  `CAVEAT`, без утверждения о полном runtime-протоколе.
* `data/MnmVerifiedKernelTables.h` и `data/MnmVerifiedFixedTables.h`:
  заголовки, сгенерированные только из сохранённых сырых таблиц.
* `metadata/MnmParams_VERIFIED.h`: только entries 0..21 — имена, порядок и
  заводские дефолты, сверенные с JSON/ColdFire. UI-кривые и дополнительные
  page-B/C offsets не заявляются.
* `proof/ROUTING_BUFFER_EXACT.md`: только доказанный literal-опкодами
  роутинг буферов; это не доказательство полной цепочки эффектов.
* `proof/FILE_MANIFEST.tsv`: полный список всех 162 файлов исходной папки,
  их Git blob SHA, SHA-256, размер и решение по каждому.

## Что сознательно не сохранено как блоки

1. `1 try/`: полноценный, но смешанный порт с fallback-таблицами и
   аналитическими/float-приближениями.
2. `2 try ...`: float-заглушки, preview HTML и неподтверждённый decay 150%.
3. `3 mnmdsp_reference more version/`: BBOX явно имеет приближённые FIR/RTIM;
   общие файлы дублируются с emulation-версией.
4. `4 mmnova-honest fav/`: README честный, но `MnMChorus.h` не является
   instruction-by-instruction портом: там `double`, ручные коэффициенты и
   упрощённые интерполяторы; `MnMFixed.h` также только модель семантики.
5. `5 mnm-dist-filter/`, `mnm-filter-q/`, `mmnova-filter-official ...`:
   смешаны A/B/C, есть прямые открытые вопросы и гипотезы по Q/скейлингу.
6. `mnmdsp_reference filter from emulation/`: `MnmAmp.h`/`MnmFilter.h`/
   `MnmBBox.h` содержат частично exact structure, но также незакрытые
   маппинги и приближённые участки; `ChorusCore.cpp` содержит сознательный
   clamp MIX=127, которого нет в ROM; `ChorusTables.h` опирается на
   runtime-таблицу, не подтверждённую в аудите.
7. Все `index*.html` и `gpt ...html`: презентационные/сгенерированные
   артефакты, не доказательства и не DSP-блоки.

## Что это значит для удаления папки

Удалять всю исходную папку можно, если нужен только доказанный материал:
этот tar — безопасная выжимка. Для восстановления полноценного DSP позже
нужно заново портировать блоки по листингам из соседних `decompiled data/03_`
и подтвердить их прогоном на том же ядре, а не использовать старые C++ из
итераций.

Компиляторы, JUCE, эмуляторы и большие toolchain-файлы в этот архив не
копировались.

## Аудит плагина 1.7.11 по твоим пунктам

### 1. FM-машины сломаны — подтверждено, вот чем

Рендер машин 8/9/10 идёт через `Source/dsp/mnm/MnmFm.hpp` (ядро 1.6.0). Это
классическая синус-ФМ «с нуля», а прошивочный FM+ устроен иначе:

**Архитектура прошивки (README_fm_machines.md, итерации 27–28):**
каждый модулятор = синус (X:$14A000, 8192 слов) → **первая разность**
`d[i]=s[i]−s[i−1]` → однополюсный LP `$144AC7[TONE]` → **пик-шейпер**
`d[i]+G·d[i−1]`, `G=16·max(0,K−64)/256` → микс → пост-сэмпловая ФМ несущей
`b += mix[i]>>12` → 2 квадратурных ротатора (стерео) → ×0.5. В плагине нет ни
первой разности, ни шейпера — тембр принципиально другой.

**Законы ручек (плагин → как в прошивке):**

| Ручка | В плагине 1.7.11 | В прошивке |
|---|---|---|
| TUNE | `(raw−64)/64·2` полутонов, биполярно ±2 | **униполярно 0…+397 центов**: `+683/128` ед/шаг, 0 = 0 центов, 64 = +200 (читается ядром $0262/$02C0, не машиной) |
| 1ENV/2ENV/3ENV | линейно `K/127` | wrap-квадрат: `(K/64)² mod 2` со знаком + droop `1−((K−64)/128)⁴`; выше 64 ноль (~90.5) и **инверсия знака** — прошивочная фича |
| 2VOL (STAT) | линейный уровень модулятора 2 | ТРИ роли: гейт `<64 → ровно 0`, wrap-уровень (без droop), пик-шейпер `d[i]+(2VOL−64)/16·d[i−1]` |
| 1FIN | finmult = 1+(K−64)/256 ✓ | тот же, НО у модулятора 1 ещё скрытый **×2** (`asl`, $145DB6) — в плагине нет, все отношения мод1 вдвое занижены |
| 1FB/2FB | линейно `K/127·4` | `sin_{i−1}·K·32` единиц фазы (до 0.496 цикла), 1-сэмпловый, аккумулируется в фазе модулятора |
| DYN 1FRQ | `exp2((K−64)/64·2)` | непрерывное `(1FRQ/2^23)·2`, клэмп ≤ $7FFFFF ($1461E3) |
| DYN 2FRQ | то же exp2 | квадратичное `(2FRQ/128)²·4` ($14625D) |
| DYN 1FEN | `levelScale·(0.5+…)` | ЧМ модулятора 1 через рекурсию вейвтейбла `$141880` (n1=128−\|1FEN−64\|·2) |
| DYN 2ENV | wave-scan из `kEnvDecayRate[idx]·(−1)` | cross-FM структурно ТИХИЙ (доказано итерацией 28: mix>>12 ≡ 0) — твой wave-scan из таблицы декей-скоростей это мусор, надо просто убрать |

**Фикс:** взять `mnm_fm_exact.hpp` (192 строки, каждая константа с адресом,
рядом тест) и заменить knob-законы MnmFm.hpp — заголовок прямо говорит
«Drop-in replacement for the knob laws of MnmFm.hpp».

### 2. «Нужен ориг дист» — есть готовый

Сейчас `mode_dist` в mnm-тракте = `Saturator` из MnmKernel.hpp
(простой hard-clip `x·drive` с клэмпом) — самодел.

Оригинал (проведано, `12_mining_archive/07_distortion/DIST_STATUS.md` + `README_dist_element.md`):
- DIST — это **слот-хук** `X[P+$0C]`, хранящий 24-битный P-адрес обработчика
  (ставит хост при назначении машины). Диспетч $097B–$0980: после
  фильтра/резонанса, до стадии-2. Ручка CC60 живёт на AMP-странице.
- Драйв-огибающая: атака = `tblA[$141800][DIST]`, спад = tblE по индексу
  `(VOL²+$7FFF)>>16` (ядро пишет VOL²).
- Найден полный обработчик $145C48–$145CCE (SWAVE-семейство): fade-in 64 блока,
  рампа y:(r6+$34), стейты = f(param5·$066666+param6·$79999A), тело 8+8 mac.
- **Готовый код:** `01_CORE_VERIFIED/dsp/MnMAmpDist.h` — «AMP: огибающая AHDR
  [EXACT] + РЕАЛЬНЫЙ DIST (P:$079F-07D1)», прогнан в TEST_REPORT.txt.
- Тест-векторы: `07_distortion/probe23d_vectors.json`.

### 3. «Энвелоуп с делеем» — в прошивке их две, обе добыты

**(а) Трековая AMP-огибающая (AHDR = с HOLD-«задержкой» перед декеем).**
Бит-точная реконструкция: `04_envelopes/README_amp_envelope.md` — стейт-машина
P:$088E–$08D7, фазы ATK/HOLD/DEC/REL/KILL, HOLD-счётчик с темп-масштабом
(P:$08B4, ×TEMPO), таблицы атаки $141800 и затухания $141880, уровень = P+$D7.
В плагине `mnm::AmpEnvelope` — самодельный ADSR с сустейном (1.6.6), прошивочной
HOLD-стадии нет. Готовый [EXACT]-код: `01_CORE_VERIFIED/dsp/MnMAmpDist.h`.

**(б) EFX-конверт блока $04A8–$04F5** (тот самый бывший открытый вопрос
«ADSR $04A8–$04F4» — теперь расшифрован, `05_echo_delay/README_delay_echo.md` §1):
это огибающая СЕКЦИИ ЭФФЕКТА/ДИЛЕЯ: EQF = атака ($04B4), EQG = затухание
($04CC), SRR = сустейн = SRR² ($04C9/$04DE), DTIM = релиз ($04E5). При этом
DSND/DFB/DBAS в DSP-ядре НЕ читаются вообще — send/feedback/база дилея живёт
на хосте (ColdFire), длину эха DSP не получает. Если «с делеем» имелось в виду
имя это — импортируется блоком $04A8–$04F5 в тракт перед DSND.

### 5. bbox: intentional vs wrong

Твои модули импорта сэмплов (LOAD FILES, OLD/RESTORE KIT, мультиимпорт,
адаптивный деклик 1.6.12) — это фичи, не трогаем. Что можно подогнать к
прошивке (законы добыты в `01_CORE_VERIFIED/dsp/machines/MnmBBox.h`, источник —
листинг $1474E9–$147631):

| Ручка | В плагине | В прошивке |
|---|---|---|
| **STRT** | кубический, потолок `min(0.25·len, 25 мс)` — **неверно, ты прав** | **линейно**: `startPos = start + len·(STRT/127)/2`, конец НЕ двигается (регион игры сжимается) |
| PTCH | свои полутона | `+PTCH·$2000` в питч-аккумулятор (таблица $140000 = 2048 шагов/октаву) |
| RTRG | свои повторы | счётчик = `min(127,(RTRG+$8000)·$80>>23)` |
| RTIM | 255 мс…1 сэмпл (своя кривая) | фазовый декремент `((RTIM·6+$C00)>>23)` за блок; переход через 0 = рестарт фазы + гейт + счётчик−− |
| тембр | прямое чтение сэмпла | полифазный FIR-дециматор 4:1, коэффициенты зашиты в код машины (P:$1475D5–$1475F2, есть в MnmBBox.h: kBBoxFIR[10]) — даёт характерный lowpass-окрашенный тон |
| банк | процедурный/пользовательский | родной ROM-банк 12 моделей: `01_CORE_VERIFIED/data/bbox_drum_bank.bin`, карта моделей P:$147632 |

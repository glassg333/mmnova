# Роутинг Monomachine: соседний трек, INP, MIX — разбор по коду прошивки

Все утверждения ниже проверены по дизассемблеру kernel'а и машин
(dsp1_pmem.bin, OS 1.32B). Адреса: `dsp1_kernel_P0000-0B4D.txt`,
`machines_page_A/15_FX-CHORUS_full.txt`.

## 1. Куда попадает звук FX-машины

Kernel обрабатывает голоса блоками по 16 кадров стерео. Перед вызовом машины
(P:$02EB `jsr (r1)`) kernel выбирает ВХОДНОЙ буфер — регистр r0
(P:$0113-$0131), по флагам X:$2C4, которые пишет ColdFire:

| флаг | вход машины |
|---|---|
| bit4  | буфер 3 = внешний вход (codec ADC) |
| bit12 | буфер 0 (X:$160) |
| bit13 | буфер 1 (X:$1C0) |
| иначе | буфер 2 (X:$220) |

Буферы 0/1/2 — это выходы ТРЁХ треков текущего прохода (3 голоса × 2 прохода
= 6 треков). Выбрать можно только треки СВОЕГО прохода — вот откуда
«соседний трек» в мануале: железо физически не даёт больше трёх источников
(плюс внешний вход).

## 2. FX-машина — это INSERT, а не параллельный трек

После машины и post-цепочки kernel записывает выход голоса в буферы
(P:$0143-$0218):

- **перезапись** (func_0001ec) — если установлен тот же бит, что выбирал вход
  (bit12/13/14);
- **добавление** (func_0001e2) — если бит сброшен.

Когда FX-машина читает буфер соседа (bit12) И её выход перезаписывает этот же
буфер — она стоит ИНЛАЙНОМ в пути соседнего трека: в основном миксе её выход
ЗАМЕНЯЕТ сухой сигнал соседа. Поэтому трюк из мануала работает:

> «назначь эффект на соседний трек, установи Input на этот трек, выведи MIX» —

это не «особый режим», а ровно описанная выше перезапись буфера. Никаких
ветвлений по источнику в коде машин НЕТ — машина не знает и не может знать,
откуда пришёл звук.

## 3. MIX всегда работает одинаково

Выходная ступень всех FX-машин (эталон — хорус P:$1477CB-$1477DD):

```
x0 = MIX (слово V+$07)
a  = $7FFFFF - x0          ; вес сухого
цикл 16 кадров:
   out = a*dry + x0*wet    ; dry = вход с гейном INP, wet = обработка
```

Та же схема у REVERB / DYNAMIX / PHASER / FLANGER / RINGMOD (MIX = p3 всюду).
Формула НЕ зависит от источника входа: сосед, внешний вход, тишина — кроссфейд
один и тот же.

**INP — это НЕ выбор источника, а гейн входа**: `gain = INP², ×4 на
произведении` (P:$14768B-$147698; то же в FX-THRU). Ручка 64 = 0 дБ,
127 = +12 дБ, 32 = −12 дБ. Закон квадратичный.

## 4. Про «0.78% сухого при MIX=127»

Вес сухого = `$7FFFFF − MIX`. Сколько даёт ручка 127 — решает скейлинг
ColdFire (главный CPU), который ещё не дизассемблирован:

- если ручка → `127×$10000 = $7F0000`, сухой остаток = `$FFFF/$800000 ≈ 0.78%`
  (−42 дБ, не слышно); так предполагал первый порт;
- если ручка масштабируется в полный диапазон (`$7FFFFF/$800000`), сухой = 0
  ровно.

Важно: даже в худшем случае это −42 дБ арифметического остатка ВНУТРИ машины.
Реальный «сухой», который слышен рядом с эффектом — это выход САМОГО трека-
источника, когда FX стоит параллельно (добавление в буфер), а не инлайном.
Убирать его надо роутингом/уровнем трека, а не правкой MIX.

Кстати: дефолтные значения прошивки — MIX=127 у CHORUS, DYNAMIX, PHASER,
FLANGER (у REVERB — 32). То есть из коробки эти машины почти/полностью wet.

## 5. Рецепты

- **100% wet на железе**: FX на треке N, вход = сосед, выход с перезаписью
  буфера соседа, MIX=127. Сухой исчезает сам, потому что перезаписан.
- **Если FX параллельно (добавление)**: сухой живёт на своём треке — глушить
  надо уровень ИСТОЧНИКА, MIX ничего не сделает.
- **Для порта в JUCE**: см. `dsp/MnmRouting.h` — TrackBus повторяет kernel:
  3 буфера + EXT, выбор входа, перезапись/добавление, сумма в микс, и точная
  ступень `fxMixStage()` + `inpGainWord()`.

## 6. Открытое (нужен ColdFire-дизассемблер)

1. Точный скейлинг каждой ручки (кривые в raw_tail дескрипторов, формат
   не расшифрован).
2. Семантика бит 3/6/7 X:$2C4 (заливка ADC подтверждена: P:$02ED-$031D
   копирует блок X:$100/$120 → буфер 3, пинг-понг по x:<<$ffffee).
3. Запись параметров в V+$04..$0B (какая ручка UI в какой оффсет) — порядок
   p0..p7 = V+$04..$0B подтверждён чтениями в листингах, но источник значений
   (кривые) — на ColdFire.

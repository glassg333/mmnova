## 2. Что ставим ВМЕСТО (2 файла + данные)

```
MnmDspCore.hpp      — каноническое ядро: исполняет РЕАЛЬНЫЙ программный образ
                      OS 1.32B (56-бит акк., pipelined stores, DO/REP, DIV,
                      L-память…). СТАТУС: 20616/20616 бит-в-бит, 4 набора.
MnmTrackChain.hpp   — готовый класс одного трека: load() → setSlot() →
                      сеттеры параметров → trigger() → processFrame(out[32]).
chain_oracle/       — эталонные векторы + полный образ памяти + текст программы
                      (это «сертификат» бит-точности; лежит рядом, не грузится
                      в плагин, только для прогонов тестов)
```

## 3. Роутинг — теперь структурный, а не «нарисованный»

Порядок стадий = ПОРЯДОК ИСПОЛНЕНИЯ РЕАЛЬНОГО КОДА ($02EC–$0B4C) и совпадает
с мануалом OS 1.32:

```
machine dispatch → HEADROOM for DIST → EQ (16-полосы) → FILTER (каскад 1 +
2x oversampled HPQ-гребёнка + стадия 2) → DISTORTION слот → AMP ENVELOPE →
VOLUME/PAN → SRR → DELAY (фильтр внутри фидбек-лупа) → LEVEL (мастер-микш)
```

Никакой «правильной схемы поверх старых модулей» больше не существует —
стадии нельзя перепутать, они выполняются той самой прошивкой.

## 4. Пример интеграции (без JUCE, чистый C++17)

```cpp
#include "MnmTrackChain.hpp"
mnmdsp::MnmTrackChain track;
track.load("/data/chain_oracle/D_real");   // или любой dir с образами
track.reset();
track.setSlot(1);                          // GND-SIN
track.setVol(100); track.setBase(64); track.setDist(0);
// в аудио-колбеке, один вызов на 32-сэмпловый блок:
int32_t bus[32];
track.trigger();                           // в кадре триггера
if (track.processFrame(bus)) {
    for (int s = 0; s < 16; ++s) {
        float L = bus[2*s]   / 8388608.0f;
        float R = bus[2*s+1] / 8388608.0f;
        // → JUCE AudioBuffer
    }
}
```

## 5. Как проверить у себя (одна команда)

```
g++ -std=c++17 -O2 -I. test_mnm_chain.cpp -o t && ./t chain_oracle
# ожидание: 4 x BIT-EXACT, "checked 20616 values, 0 mismatches"
g++ -std=c++17 -O2 -I. test_mnm_trackchain.cpp -o tc && ./tc chain_oracle
# ожидание: BIT-EXACT, 512/512
```

## 6. Замечание по X:2C9

processFrame() пишет X:$2C9=0x300 перед трактом — это харнес-ловушка оракула
(сканер многотрекового состояния ОС; в однотрековой модели инициализируется
каждый кадр). Задокументировано в README_AUDIT_AND_CHAIN.md §2/§3.

# УНИВЕРСАЛЬНЫЙ МЕТОД ИЗВЛЕЧЕНИЯ БЛОКОВ OS 1.32 (без «тыканья в тупую»)

Пак 14, 2026-10-03. Это метод, которым закрыты ВСЕ блоки выше (фильтр, AMP env,
FM-конверты, гейт $04A8, панч, хвост, делэй): 6 шагов, каждый шаг — конкретный
инструмент из этого репозитория. Порядок важен: сигнал/атрибуция не
утверждается, пока не сработали шаги 2–4.

## Шаг 0. Оракул

Бит-точный эмулятор DSP56300 (`scripts/dsp_emu.py`) + харнес трека
(`work/pack7/tools/exp64_fm_pluginlevel.py`: `build_fm_track()` грузит реальный
код OS 1.32B + pmem, `setup_page()` строит страницу хоста). Оракул = САМ КОД
ПРОШИВКИ, а не пересказ. Всё, что дальше, исполняется на нём.

## Шаг 1. Границы блока по листингу

`03_listings/dispatch/dsp1_kernel_P0000-0B4D.txt` — вырезать регион, найти
входы (jmp/jsr/bcc-цели) и выходы (rts/jmp). Внутри кадра r6 = $400 (страница
трека), в диспетче машин r6 = $428 — офсеты (r6±N) пересчитывать в абсолют
ПО БАЗЕ ТОГО КОДА, ГДЕ ИНСТРУКЦИЯ ИСПОЛНЯЕТСЯ, а не глобально.

## Шаг 2. Полная трасса чтений/записей (главный шаг — вместо грепа)

Инструментировать `e.rd`/`e.wr` эмулятора и логировать (pc, память, ЭФФЕКТИВНЫЙ
адрес) на живом прогоне. Это ловит непрямые чтения (y:(r7-$5d), l:(r5)+,
отрицательные офсеты), которые греп текста не видит. Шаблоны:
- `tools/exp70c_tail_ea.py` — лог всех обращений региона в одном кадре;
- `tools/exp70_efx_truth.py::readtrace` — свод читателей по ячейкам за N кадров
  (подмешивать событие $421/$428, чтобы исполнились ВСЕ ветки, иначе читатели
  фазовых веток не покажутся — грабля exp70 №1).

Результат: список «ячейка → ПК читателей/писателей». Он и есть карта
принадлежностей. Пример (exp70): $418 → только $04B4; $41F → только $0B1E;
X:$40F → 6 читателей SVF/EQ/усилителя, а пишет его только ИНИТ машины
($00F4, константа 1) — значит, коэффициентом ручки быть не может.

## Шаг 3. Дифференциальный свип (кто реально двигается)

Свип ОДНОЙ ручки (0/32/64/96/127) против базового прогона, 16–24 кадра,
полный снапшот X/Y $000–$6FF каждый кадр, диф по кадрам с группировкой по
регионам (t6out/echo/taps/s2bank/dstate/rings/ramps/page/rest). Шаблон:
`tools/exp70_efx_truth.py` (свипы) и `scripts/exp69b_fenv_diff.py` (носители
→ форма во времени → −60 дБ-времена). Правило вывода: ручка «действует» только
если диф вышел за пределы её собственной ячейки (page) и зашёл в аудио-регионы.

## Шаг 4. Привязка к сигналу и месту в цепи

Для каждого носителя из шага 3 найти множитель в листинге (кто умножает сигнал
на это значение) и измерить метрики выхода: RMS выхода/эха, ZOH-метрика
(децимация), спектр/переключение нуля. Позиция потребителя в кадре = позиция
блока в роутинге. Пример: единственный читатель Y:$4FF = T5 ($0B1E), рампа
потребляется T6 ($0B33–$0B49), который умножает финальный микс → блок = гейт
конца цепи, а не модулятор тапов.

## Шаг 5. Хост и имена

Хост (ColdFire, `05_descriptors/coldfire_main.bin`, дизасм capstone:
`scripts/exp70d_pagebuild.py`, `scripts/cf_dis.py`):
- сборка страницы $042590+ → какие слова уходят в $400–$433;
- отправка $4390C (52 слова) и гашение флагов $048386–$048396 → класс
  событийных ячеек ($420/$421/$428);
- UI-шаблоны страниц (`05_descriptors/page_templates`) + `mn_midi.csv` →
  имена ручек ↔ CC ↔ ячейки. Дыры страницы (нет CC-писателей → ячейка
  недостижима: $408–$40F) — это тоже результат.

## Шаг 6. Бит-в-бит порт + векторы

Транскрипция блока в C++ (`dsp/mnm/Mnm*.hpp`), векторы генерировать ИЗ СНАПШОТОВ
эмулятора (не из питон-модели!), тест `tools/test_*.cpp`: checks=N
mismatches=0. Известные питфоллы порта: data limiter $7FFFFF/$800000 на
переносе аккумулятора; ключи снапшотов Yo/Xo vs Y/X; add48 при add y,a;
обёртка минуса в 24 бита (mpy -x1); DO-тело = [pc+2, end).

## Чего метод не прощает (грабли exp70, оплачены временем)

1. Ключи страницы в харнесе АБСОЛЮТНЫЕ ($410–$41F): `e.Y[a] = v<<16`, НЕ
   `e.Y[P+a]` — двойной сдвиг молча оставил все ручки нулями (свипы «не работают»).
2. Фазовые ветки конвертов не исполняются, пока не подмешать событие ($421/$428)
   — трасса читателей без этого врёт (пусто).
3. Греп по тексту листинга — только ПРЕДВАРИТЕЛЬНАЯ карта; финальная — только
   живая трасса эффективных адресов (шаг 2).
4. Одна атрибуция = минимум три независимых подтверждения: листинг + трасса +
   диф-свип (и хост/UI, если спорно).

# Monomachine OS 1.32B — FILT + DIST для C++17 / JUCE

В пакете находится перевод выбранных DSP-инструкций прошивки в нативный C++:
основные HP/LP-фильтры с HPQ/LPQ, огибающая FILT и связанный с фильтрами DIST.
У каждой переведённой инструкции сохранены адрес P и машинные слова.
Коэффициенты и таблицы времени извлечены из предоставленной OS 1.32B.
В аудиопотоке нет декодера инструкций, загрузки BIN/SYX, зависимости от полного
эмулятора или фильтров `juce::dsp`.

**Статус проверки:** исходники C++ не компилировались и не запускались.
Побитное совпадение с Gearmulator или устройством не подтверждено.
Проверены соответствие выбранных машинных слов/таблиц BIN и SYX, воспроизводимость
генерации C++ и поведение отдельной Python-модели инструкций. Эта модель помогает
найти ошибки, но не является независимым доказательством точности перевода.
Не следует выдавать пакет за уже проверенную точную звуковую копию устройства.

## Что включено

| Параметр API | Крутилка | Слово страницы DSP | Назначение |
|---|---|---|---|
| `base` | BASE | Y:page+$08 | нижняя граница, HP |
| `width` | WDTH | Y:page+$09 | ширина до верхней границы, LP |
| `hpq` | HPQ | Y:page+$0A | резонанс HP |
| `lpq` | LPQ | Y:page+$0B | резонанс LP |
| `attack` | ATK | Y:page+$0C | атака огибающей FILT |
| `decay` | DEC | Y:page+$0D | спад огибающей FILT |
| `baseOffset` | BOFS | Y:page+$0E | знаковое воздействие огибающей на BASE |
| `widthOffset` | WOFS | Y:page+$0F | знаковое воздействие огибающей на WDTH |
| `distortion` | DIST | Y:page+$04 | усиление/ослабление и перегруз в тракте фильтров |

Все поля принимают исходные значения **0…127**. Для DIST, BOFS и WOFS положение
с отображением `0` задаётся как `64`; отображаемое значение равно `raw - 64`.
HPQ/LPQ передаются как исходные значения ручек, без выдуманного пересчёта в Q.
На аппаратном уровне FILT использует одну траекторию ATK/DEC и два независимых
знаковых воздействия BOFS/WOFS. DIST не получает собственной огибающей.

DIST входит в вычисление коэффициентов LP и в последующий нелинейный участок.
Отрицательные положения уменьшают усиление перед перегрузом. Положительные
увеличивают возбуждение перегруза; компенсация уровня не позволяет трактовать
ручку как линейный выходной gain. Выделять вместо этого произвольный `tanh()`
было бы изменением алгоритма.

`highPassKeyTracking` и `lowPassKeyTracking` включают соответствующие биты
маршрутизации независимо. `setNote()` задаёт ноту; `setPitchWord()` позволяет
передать уже рассчитанный индекс высоты. `triggerFilter()` перезапускает FILT.
Note-off не закрывает громкость: AMP в этот компонент не входит.

## Подключение к JUCE

Добавьте каталог `include` в пути заголовков проекта и подключите
`JuceMonomachineFilterDist.hpp`. Требуются C++17 и модуль `juce_audio_basics`.
См. `examples/ProcessorIntegration.hpp` для подключения к существующему процессору.
Если JUCE уже добавлен в CMake-проект:

```cmake
add_subdirectory(path/to/MonomachineFilterDist)
target_link_libraries(YourPlugin PRIVATE mnm132::juce_filter_dist)
```

Назначьте процессору задержку `16` сэмплов через `setLatencySamples(16)`.
`prepare(sampleRate)` принимает **44100 Гц**; при другой частоте возвращает `false`,
а адаптер выдаёт тишину. Пересчёт исходных таблиц или внешний ресэмплер не добавлены.
Размер блока хоста может быть произвольным: адаптер собирает блоки DSP по 16 сэмплов.
Поддерживаются mono/stereo; в mono одинаковый вход направляется в оба тракта,
возвращается левый. Дополнительные каналы очищаются.

Изменение параметров выполняйте в аудиопотоке, например, считывая атомарные значения
APVTS. Класс сам не синхронизирует доступ из редактора. MIDI note-on задаёт ноту
и триггер FILT. События внутри 16-сэмплового блока квантуются к этому блоку;
несколько note-on сводятся к последнему. Это политика адаптера, а не точная
реализация передачи событий ColdFire или секвенсора Monomachine.

По умолчанию включено сглаживание параметров по расписанию `HostModel` Monomodule:
`current = (3 * current + target) >> 2` один раз на 24 блока DSP, начиная с блока 3.
Это отдельно помеченная логика хоста. `enableHostSmoothing(false)` отключает её
для сравнений непосредственно с DSP. LFO и портаменто не реализованы; готовые
модулированные слова можно передавать через `setFilterWords()` и `setPitchWord()`.

## Точные границы и уровень сигнала

Вход — **выход EQ**, буферы `Y:$94…$A3` и `Y:$D4…$E3`, signed Q1.23.
Выход — состояние памяти перед AMP на `P:$088E`, пары `L:$6D…$7C`
и `L:$AD…$BC` (`X` — старшие 24 бита, `Y` — младшие).
EQ, AMP, SRR и delay не исполняются. Это значит, что уровень на выходе компонента
не равен уровню главных выходов инструмента и не является unity bypass при DIST=0.
Произвольной нормализации или компенсации громкости здесь нет.

`processRaw16()` сохраняет обе части 48-битных пар для сравнения снимков памяти.
`processFloat16()` округляет вход float в Q1.23, ограничивает его диапазоном
−1…(1−2^-23), затем переводит выходные пары по масштабу Q1.47. Это контракт API,
а не эмуляция DAC. В младших Y-словах на этой границе остаются также промежуточные
данные; даже при нулевых старших словах возможен очень малый остаток float.
Он не зануляется дополнительным порогом.

Контекст `X:page+$0B` влияет на headroom и DIST. Использован исходный default
`$200000` из `P:$00F0…$00F1`. Некоторые машины его переопределяют.
При встраивании в конкретную машину передайте её захваченное значение через
`setMachineHeadroomWord()`; не считайте этот default доказательством совпадения
уровней всех машин. Начальное обнуление состояния, значения параметров класса,
выбор stereo-пути и MIDI-политика — явные решения автономного адаптера.

## Файлы и проверка без компиляции

- `include/FirmwareFilterDist.hpp` — все выбранные участки FILT/DIST, 786 инструкций.
- `include/DspArithmetic.hpp` — необходимая 24/48/56-битная арифметика.
- `include/FirmwareTables.hpp` — 12 486 исходных слов таблиц.
- `include/MonomachineFilterDist.hpp` — интерфейс без JUCE, по 16 сэмплов.
- `include/JuceMonomachineFilterDist.hpp` — JUCE-адаптер.
- `evidence/selected_dsp.asm`, `ADDRESS_AUDIT.md` — адреса и обоснование границ.
- `evidence/provenance.json`, `model_checks.json` — происхождение и результаты.
- `tools/` — извлечение, регенерация, модель и проверки. Нужен Python 3.12+.

Из корня распакованного каталога:

```text
python tools/verify_package.py
python tools/model_check.py
python tools/verify_firmware.py --bin path/to/elektron_sfx6-60_os1.32b.bin --syx path/to/Elektron_SFX6-60_OS1.32B.syx
```

Последняя команда требует исходные файлы по предоставленным ссылкам; целиком
прошивка в архив не включена. Первая проверяет машинные слова, таблицы,
структуру перевода и воспроизводимость сгенерированных заголовков.
Вторая запускает модель, включая крайние положения ручек и retrigger.
Ни одна из этих команд не запускает компилятор.

Для независимой проверки следует снять в работающем Gearmulator состояние перед
`P:$04FF`, после EQ перед `P:$05BF` и перед AMP `P:$088E`, передать одинаковые
параметры, headroom, pitch и историю фильтров и сравнить X/Y слова выхода.
Сравнение с финальным аудио полной машины смешало бы вклад AMP, EQ и остальных блоков.
Пакет содержит полный выбранный DSP-срез, но такая независимая проверка остаётся
невыполненной. Сведения об исходниках и лицензиях: `THIRD_PARTY_NOTICES.md`.

# ИТЕРАЦИЯ 15 — ВЕРДИКТ ПО ФИЛЬТРОВОМУ ЭНВЕЛОПУ (вопрос Ф2): у фильтра его НЕТ

Дата: 2026-09-21. Метод: бит-точный эмулятор DSP56300 (05_emulator/dsp_emu.py, 27/27 тестов),
полный кадр трека $0100–$0B4C с живой машиной и инжекцией синуса (обвязка 06_amp_env),
контролируемые свипы параметров страницы P+$14–$17.

## ВЕРДИКТ

**Трековый dual-фильтр Monomachine НЕ имеет собственного энвелопа на стороне DSP.
Вопрос Ф2 («масштаб env→срез») РАСТВОРЁН: путь env→индекс div1 не существует.**

Ячейки страницы P+$14–$17, ранее атрибутированные как «FILT ATK/DEC/BOFS/WOFS»,
на самом деле — параметры ДЕЛАЙ-МОДУЛЯЦИИ трека (секция P:$0939–$0B49). Ранее
написанная формула «env BASE±(ATK/DEC·BOFS)» — ОШИБКА предыдущих итераций.

## Доказательства (все бит-точные, скрипты рядом)

### 1. Кольцо коэффициентов Y:$04–$07 не зависит от P+$14–$17
`exp_f2c_coeff_ring.py` + `results_coeff_ring.json`: 9 конфигураций
(BOFS/WOFS/ATK/DEC = 0 / 0.5 / 1.0) × 10 кадров. Во ВСЕХ конфигурациях:
- индекс div1 (r0 после P:$0579) = 599 (BASE=64) — константа;
- raw Y:$04 = −0.496676, Y:$05 = +0.000022, Y:$06/07 = width1/2[WDTH] — константы.
Позитивный контроль: свип BASE меняет коэффициент (exp_A.json из итерации 12).

### 2. Путь P:$056B–$0572 — математическая идентичность (a ← BASE)
```
056B: a = Y:P+$D9          ; перенос прошлого блока
056D: b = Y:P+$10          ; BASE
056E: b = BASE − a
056F–71: asl#8 / rnd / asr#8   ; округление — НЕЙТРАЛЬНО для 24-бит выровненных слов
0572: a = a + (BASE − a) = BASE
0575: Y:P+$D9 = a          ; запись обратно (прошлоблочное значение НЕЛЬЗЯ отличить)
0576: idx = a · $4AF >> 24 ; индекс div1
```
Оба операнда 24-бит выровнены (move в аккумулятор кладёт слово в a1), поэтому
`asl#8/rnd/asr#8` — тождество, и `a` ВСЕГДА = BASE. Эмпирически: idx = 599 во всех
конфигурациях env. Ячейка P+$D9 — не «env→срез», а перенос значения ДЛЯ ДРУГОЙ ветки
(см. п.4: это delayed-time/carrier ячейка delay-тракта).

### 3. Банк тапов резонанса L:$80–$91 не зависит от P+$14–$17
`exp_f2f_multiframe.py` + `results_multiframe.json` (14 кадров, состояние на входе
delay-секции $0939): FATK=0 / FDEC=127 / BOFS=127 → 0 расхождений в L:$80–$91.
Каскад-2 (сканер дробных тапов func_000397) получает ТО ЖЕ самое резонансное ядро.
P+$14–$17 меняют только банк L:$92–$9F — тапы ДЕЛАЯ (запись P:$0AF8/$0AF9).

### 4. Стерильный одно-кадровый тест — решающий
`exp_f2g_sterile_frame.py`: один кадр от идентичного состояния, снапшот ВСЕЙ
памяти X/Y $000–$1FF + страница голоса на входе в $0939:

| Конфиг | Расхождений | Что изменилось |
|---|---|---|
| FATK=0 / 127 | **1 ячейка** | сам параметр Y:P+$14 |
| FDEC=0 / 127 | **1 ячейка** | сам параметр Y:P+$15 |
| BOFS=0 / 127 | **1 ячейка** | сам параметр Y:P+$16 |
| WOFS=0 / 127 | **1 ячейка** | сам параметр Y:P+$17 |
| CTRL BASE=90 | 59 ячеек | аудио, банк delay и пр. |
| CTRL WDTH=120 | 63 ячейки | аудио, банк delay и пр. |

Внутри кадра P+$14–$17 не влияют НИ НА ЧТО, кроме самих себя. Их слышимый эффект
(подтверждён `exp_f2e_audio_level.py`: BOFS=127 → энергия ×0.08, WOFS=127 → ×3.8)
накапливается МЕЖДУ кадрами через интегратор delay-модуляции.

## РЕАЛЬНАЯ роль P+$14–$17 (delay-модуляция, секция $0939–$0B49)

| Ячейка | Код | Роль |
|---|---|---|
| P+$14 | $0A22 (знак выбора банка $40/$62), $0AB7–$0ABE (глубина²) | ГЛУБИНА модуляции, биполярная: (P+$14−0.5)² |
| P+$15 | $0ABF, KILL-гейт $0AC0–$0AC4 | ОБРАТНАЯ СВЯЗЬ интегратора модуляции; при фазе AMP-env == 4 (KILL, X:P+$D8) — 0 |
| P+$16 | $0A5D–$0A63 | скорость однополюсной рампы 1 (стейт P+$D4, цель — аудио-шина) |
| P+$16+$17 | $0A84–$0A92 | скорость рампы 2 (стейт P+$D5), кривая $144B48 ($0AA9) |
| — | $0AC7–$0AD0 | интегратор X:$40–$5E: Σ(audio·P+$15 + ramp·depth²) → коэффициенты delay-обратной связи |
| — | $0AF8/$0AF9 | банк тапов ДЕЛАЯ L:$92–$9F (func_000397, $0B13) |
| — | $0B31/$0B32 | рампа времени делаЯ Y:$10–$1F (де-зиппер) |

## Чем на самом деле «двигается» фильтр на Monomachine

1. **CPU-сторона (ColdFire)**: LFO/мод-матрица/секвенсор пишут слова параметров
   Y[P+$10..$13] между кадрами DSP. На DSP НЕТ LFO с синус-таблицами:
   $14A000/$14A800 используются единственным местом — панорамный узел (P:$08E5).
2. **DIST drive-env** (P:$04FF–$0536, параметры P+$0C/$0D, таблицы $141800/$141A00)
   — единственный «env-подобный» механизм в коэффициентной секции; модулирует
   путь времени дела/пинг-понга (X/Y:P+$D9/$DA), НЕ фильтр (доказано итерацией 13
   и подтверждено здесь идентичностью п.2).
3. Трековый delay (DTIM/DSND/DFB/DBAS/DWID = P+$18–$1F) с интегратором модуляции
   от аудио — вот где живут «оживляющие» движения, ранее приписанные фильтру.

## Следствие для порта

- Формулы порта в 01_filter/README_filter_algorithm.md («Формулы для порта»)
  уже БЕЗ env-членов — и теперь это доказанно ПОЛНАЯ формула DSP-алгоритма фильтра.
- Готовность фильтра: **DSP-алгоритм ≈ 100%** (было ≈97% с открытым Ф2).
  Осталось: Ф3 (роли EQ-таблиц $143546/$1435C6/$143C06 — это тоновый управление
  трека, не сам dual-фильтр) и аппаратный вопрос карты X:$FFFF00+ (не влияет
  на форму рекурсий).
- Параметры $14–$17 нужно портировать как часть ТРЕКОВОГО ДЕЛАЯ, не фильтра.

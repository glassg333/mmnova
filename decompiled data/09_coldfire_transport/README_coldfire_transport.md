# Итерация 26 — ColdFire-транспорт параметров: HI08/DMA5 расшифрован

**Дата:** 2026-09-23. Метод: линейный дизасм `coldfire_main.bin` (425 858 Б, база $200000,
capstone M68K 68020, 125 992 инструкции) + скан HI08-обращений в `dsp1_pmem.bin`
(1 343 588 слов) + кросс-проверка протокола по эмулятору `gearmulator-md-mm`
(mc68k `hdi08.cpp`, dsp56k `dma.h`/`peripherals.h`, `mddsp.cpp` — клонированы частично,
в пак НЕ включены).

Отвечает на хвост вопроса 12 (README): «формула хоста — в main OS, не в DSP».
Найдено, ГДЕ main OS живёт и КАК параметры попадают в DSP. Это закрывает транспортную
половину вопроса; точная арифметика DTIM→P$2A — следующий шаг (точки входа указаны).

## 1. Карта HI08 со стороны ColdFire

| Адрес | Регистр | Кто пишет |
|-------|---------|-----------|
| $500000 | ICR (DSP1) / $600000 ICR (DSP2) | init |
| $500001 | **CVR** — командный регистр | все команды |
| $500002 | ISR — статус (poll bit7→`blt`) | ожидание |
| $500004 | TX/RX — 24-битное слово (long, значимы младшие 24) | данные |

**Механика команды** (подтверждено `mc68k/source/hdi08.cpp`, `write8/HdiCVR`):
запись в CVR значения с битом 7 ($80) порождает на DSP прерывание по вектору

```
vector_addr = (CVR & 0x3F) << 1
```

Типовой паттерн прошивки: две записи в CVR — сначала `HV` без $80 (презагрузка),
затем `HV|$80` (выстрел) — см. $24828E/$24390C/$2439D6.

## 2. DSP-сторона: векторы-обработчики команд (dsp1)

Скан всего P-памяти на чтения HRX ($FFFFC6)/HTX ($FFFFC7) — `exp26_scan_hrx.py`:
39 обращений, все в ядре/иниц-модуле (в машинах $144000+ — НОЛЬ; регион $101700+,
где формально бьётся паттерн — таблица данных, ложное срабатывание).

| Вектор | CVR | Обработчик | Действие |
|--------|-----|------------|----------|
| $00000C | $06\|$80 | func_000237 | **чтение слова**: r0←HRX (адрес), HTX←x:(r0) |
| $000010 | $08\|$80 | func_000219 | **перевооружить DMA5**: DDR5=Y:$0500, DCO5=51, DCR5=$8E9AC4 |
| $000012 | $09\|$80 | func_000220 | то же, DDR5=Y:$0600 |
| $000014 | $0A\|$80 | func_000227 | то же, DDR5=Y:$0700 |
| $000016 | $0B\|$80 | func_00022E | **произвольный DMA**: DDR5←HRX (ПЕРВОЕ слово хоста = адрес!), DCO5=2047, DCR5=$8E9AC4 |
| $00001A | $0D\|$80 | func_00023E | watchdog: счётчик X:$4FE; 3 промаха → глушение ESAI ($FFFFE0/E4/E8←0) и стоп |
| $0020   | $10\|$80 | func_000259 | конфиг ESSI/GPIO |

Инициализация DMA5 (модуль $100000, адрес $100109):
```
movep #$ffffc6, x:<<$ffffdb   ; DSR5 = $FFFFC6 = HRX — источник = HI08 НАВСЕГДА
movep #$4,      x:<<$ffffc2   ; HCR = HCIE — разрешить host-command прерывания
```

## 3. Декод DCR5 = $8E9AC4 (биты по dsp56k `dma.h` / мануалу 56303)

| Поле | Значение | Смысл |
|------|----------|-------|
| Dss(0-1)   | 0 | источник — X-пространство (фактически периферия HRX) |
| **Dds(2-3)** | **1** | **приёмник — Y-ПАМЯТЬ** (0=X,1=Y,2=P) |
| Dam(4-9)   | 44 | режим адресации (пост-инкремент) |
| **Drs(11-15)** | **19 = 0b10011** | **запрос = HI08 Receive Data Full (HRDF)** — слово пришло → перенос |
| Dcon(16)   | 0 | не непрерывный |
| Dpr(17-18) | 3 | высший приоритет |
| Dtm(19-21) | 1 | word-режим, DE сбрасывается после счётчика |
| De(23)     | 1 | включен |

⇒ **Аппаратный конвейер: слово хоста → HRX → DMA5 → Y:[DDR5++]**, без участия ядра.
Регистры: $FFFFD8=DCR5, $FFFFD9=DCO5, $FFFFDA=DDR5, $FFFFDB=DSR5 (dsp56k `peripherals.h` `XIO`).

## 4. ГЛАВНОЕ: карта страниц параметров

Страница голоса = 256 слов Y-памяти. **Хост владеет словами $00–$32 (51 слово)** —
ровно столько несёт фиксированный DMA-бурст (DCO5=$33=51). Матч с ядром идеальный:

| Слова страницы | Содержимое (доказано итерациями 11–24) |
|---|---|
| $00–$0F | AMP-энвелопа, VOL/PAN, стейты |
| $10–$17 | FILT: BASE WDTH HPQ LPQ ATK DEC BOFS WOFS |
| $18–$1F | EFFX: EQF EQG SRR DTIM DSND DFB DBAS DWID |
| $21/$23/$25/$28 | форс-стейт, TEMPO (BPM<<16), mode, TRIG |
| **$2A** | **хост-ячейка длины эха P$2A** (Y-полуслово, 127<<16 ≈ full) |
| $2C–$32 | параметры машины (r6=P+$28 → r6+$4..$B; $2C–$32 = 7 из 8, слово $33 хостом в этом бурсте не шлётся) |
| $33–$FF | стейты/выходы DSP — хостом НЕ пишутся |

Шесть голосов Monomachine = 3 страницы × 2 DSP (подтверждено: ядро держит 3 слота
y:$120–$122, «y:$124 = трек 0..2»; в gearmulator mddsp.cpp — DSP1/DSP2 симметричны).

## 5. ColdFire: отправители и staging-буферы

Шесть пер-трековых записей по $D0 байт (52 long) в RAM хоста, $1000A54–$1000F34:

| Буфер | DSP | Команда | Приёмник Y | Отправитель | Флаги (чистятся) |
|-------|-----|---------|-----------|-------------|------------------|
| $1000A54 | DSP2 | $08\|$80 | $0500 | $24837E | $1000AD4/AD8/AF4 |
| $1000B24 | DSP2 | $09\|$80 | $0600 | $248262→$243944 | $1000BA4/BA8/BC4 |
| $1000BF4 | DSP2 | $0A\|$80 | $0700 | $2482EC→$243944 | $1000C74/C78/C94 |
| $1000CC4 | DSP1 | $08\|$80 | $0500 | $2486C6→$24390C | $1000D44/D48/D64 |
| $1000D94 | DSP1 | $09\|$80 | $0600 | $24855E→$24390C | $1000E14/E18/E34 |
| $1000E64 | DSP1 | $0A\|$80 | $0700 | $2484EC→$24390C | $1000EE4/EE8/F04 |

Примитив отправки 52 слов: $24390C (DSP1, $500001/$500004) / $243944 (DSP2, $600001/$600004):
```
CVR = arg+8 ; CVR = (arg+8)|$80 ; poll ISR bit7 ; 52 long'а из буфера → TX
```
Буферы на $D0 НЕ выровнены на насыпные 52 long (флаги $80/$84/$A0 внутри записи) —
записи имеют смешанную структуру; точная раскладка — с next-итерацией.

Bulk-команда CVR $0B\|$80 (произвольный Y-адрес + до 2048 слов) используется для
перезагрузки страниц при смене патча/машины и страниц вне $500–$7FF (напр. глобальной
Y:$400).

## 6. Покадровый цикл хоста $267DEE — где живёт «остальная» магия

Функция перебирает 6 треков (счётчик d0=6, шаг записей $D0) и на каждый трек:

- **сглаживает per-track указатель**: `(a3)=0.75·(a3)+0.25·((long@[$1001F40+tr]>>16)<<16)` —
  a3 = $1000AD0+tr·$D0, поле записи +$7C. Формула 3/4+1/4 — тот же «глайд»-паттерн,
  что ретюн DSP-стороны (0.9/0.1). Кандидат: **база кольца эха (DBAS) / позиция чтения
  на хост-стороне** — 16.16 формат совпадает с банком тапов L:$90–$A0.
- сглаживает 2 банка по 8 long со структурой +$1BC (те же 0.75/0.25);
- копирует 24 long из $1001902+tr·$120;
- вызывает per-track подпрограммы **$267A6E / $267A92 / $267A12** и $23FE46 —
  **заполнители staging-буферов (формулы knob→ячейка, включая DTIM→P$2A)** —
  ТОЧКИ ВХОДА следующей итерации.

## 6b. БОНУС: темп-движок хоста найден ($267ABA–$267D90) — константа 2^(−1/12)

В подпрограмме-заполнителе (окно $267B38–$267B90) видна арифметика:

```
d2 = (long@[$1000F34+tr+$14]) asr 10
d2 = d2 · ($2BC2A4) · ($48(a7))          ; глобал темпа × аргумент
d3 = (a5)                                 ; per-track накопитель ($29C04C+)
d0 = ($29BD6C + 1) · d3
d1 = d2 + $791FD                          ; ← $791FD0 >> 4 — СЕМЕЙСТВО $791FD0!
d4 = (d0 + d1) / $F23FA                   ; ← $791FD0 >> 3 (деление)
d2 += d3                                  ; интегратор шага
; далее масштабная цепочка ×125 → ×63/64 → ×… (fixed-point)
```

**Ключевая идентификация: $791FD0/2^23 = 0.9438743 = 2^(−1/12) — коэффициент
ПОЛУТОНА.** Это та же константа, что в гейте взведения эха на DSP
(T1[LPQ]·TEMPO·$791FD0·32 ≥ $4000, итерация 24). Темп-движок хоста масштабирует
накопители на доли полутона — согласуется с tape-style ретюном (глайд высоты).
⇒ **$267ABA = генератор темп-синхронных длин (источник P$2A)** — точный вид
формулы DTIM/DBAS/BPM → P$2A разбирается вокруг этого цикла (следующая итерация,
начало положено).

## 7. Ответы на вопросы пользователя (обновление)

1. **«dsnd ручку её роутинг» — ДОПОЛНЕНО.** DSND (P+$1C) физически передаётся хостом
   в страницу (слова $00–$32), но DSP его не читает (итерация 24) ⇒ уровень send
   прикладывается ColdFire-стороной к покадровому вкладу голоса в эхо-шину (T6 →
   X:$2C9) и/или при суммировании в кольцо (кольцо = внешняя SRAM, общая для DSP
   и ColdFire — «XY bridged into P above $020000», mddsp.cpp). DFB — возврат в кольцо
   там же. Прямой ColdFire-микш-код = подпрограммы из §6 (след. итерация).
2. **«retune speed для DTIM»** — без изменений: DSP-сторона доказана (0.1/кадр +
   кламп ±4 слова/кадр, итерация 24); хост-глайд 0.75/0.25 (§6) — второй контур.
3. **«значения dtim»** — DSP-таблица целей T2[LPQ]·$21D10 доказана (итерация 24);
   P$2A — Y-полуслово, full-scale ≈ 127<<16; точная host-формула knob→P$2A —
   следующий шаг (§6, $267A12).

# ColdFire: тактовый модуль, сборщик страниц и OS-роутинг параметров

**Итерация 27.** Продолжение итерации 26 (транспорт HI08/DMA5 закрыт). Здесь закрыт
вопрос «КАК устроена host-сторона часов»: найден и разобран весь тактовый модуль
(темп-движок $267ABA), его вызовы, сборщик страниц $267DEE и — главный приз —
**$2403D4: диспетчер «параметр → ячейка страницы»**, то есть OS-уровень роутинга
ручек (DSND/DFB/DBAS/DTIM и всех остальных).

Метод: линейный дизасм coldfire_main.bin (exp26_cf_full.asm, база $200000,
125 992 инструкции) + побайтовая верификация таблиц по сырому бинарнику
(`exp27_verify.py`, `exp27_findings.json`). Все адреса — ColdFire (base $200000),
если не указано иное.

---

## 1. Тактовый модуль живёт в RAM: карта трамплинов

Пролог ОС ($200006–$200020) копирует ROM **$2676E0..$267F82 ($8A2 байт)** →
RAM **$1000088..$1000929**. Все вызовы модуля идут через `jsr $1000xxxx.l`
(в ROM нет ни одного abs/pcrel-указателя на $267Axx — потому итерация 26 и не
нашла вызовов темп-движка). Полная карта:

| RAM (вызов) | → ROM | Размерность | Что это |
|---|---|---|---|
| $1000088 | $2676E0 | ×1 | начало модуля (таблицы/данные) |
| $1000312 | $26796A | ×1 | — |
| $100039A | $2679F2 | ×1 | — |
| $10003BA | **$267A12** | ×3 | глайд 12 стейтов/трек (см. §5) |
| $1000416 | $267A6E | ×1 | заполнитель по указателям ($100139C+…) |
| $100043A | $267A92 | ×1 | заполнитель 7 long × 6 ($1001658+…) |
| $1000462 | **$267ABA** | **×2** | **ТЕМП-ДВИЖОК** (см. §2) |
| $1000720 | $267D78 | ×9 | RLE-расширатель байтового потока |
| $1000796 | $267DEE | ×1 | сборщик страниц (см. §4) |
| $1000800 | $267E58 | ×2 | (внутренняя часть сборщика) |
| $1000900 | $267F58 | ×2 | (внутренняя часть сборщика) |
| $1000A00 | — | ×4 | вне копии: runtime-стаб (заполняется в RAM) |

Верифицировано скриптом: все 12 адресов согласуются с окном копии; вызовы
`$1000462` ×2 найдены в $2484A6 и $2485F4.

## 2. Темп-движок $267ABA — полный разбор

Сигнатура: `$267ABA(delta: long)` — один аргумент на стеке. Глобалы:

| Адрес | Роль |
|---|---|
| $2BC2A4 | TEMPO (глобальное значение темпа; пишут $2391C6, $23A53C, …) |
| $29BD6C | флаг «фазовый кадр был в этом цикле» (ставит $248080 = 1, движок читает и сбрасывает в конце) |
| $29C04C+t*12+i*4 | интегратор (track t, timbre i; 6×3 штук) |
| $2BFC58+t*$66+i*$22 | слот (track t, timbre i): +$00 фаза, +$0C инкремент кадра, +$14 выход движка |
| $1000F34+t*$60+i*$20 | параметры движка: +$08 mode (word), +$10 shift (word), +$14 rate (long) |

### 2.1 Ядро (на каждый трек × тайбр, d6 = тайбр 0..2, a6 = трек 0..5)

```
d3  = интегратор (a5)                        ; $29C04C + (t*3+i)*4
d2  = (param+$14 >> 10) * TEMPO * delta      ; rate → квант
d4  = ((счётчик+1)*d3 + d2 + $791FD) / $F23FA   ; divs.l — ЦЕЛАЯ ЧАСТЬ
d2  = d2 + d3 − d4*125*63*63*2               ; модуль: 125*63*63*2 = $F23FA ровно
интегратор(a5) = d2                          ; остаток копится дальше
```

- **$F23FA = 2·63²·125 = 992250** — константа разложена в сдвиги
  (4d → 128d−4d → +d → 125d; 125d<<6 −125d → 7875d; 7875d<<6 −7875d → 496125d; ×2
  → 992250d). Побайтово верифицировано (`exp27_findings.json`).
- **$791FD = $F23FA >> 1** — округление при делении.
- **$791FD0 = $F23FA << 3** — та самая константа DSP-гейта эха из итерации 24
  (`T1[LPQ]·(TEMPO·$791FD0·32) ≥ $4000`). Теперь понятно её происхождение: это
  модуль хост-кванта × 8. Связь DSP↔host констант замкнулась.

### 2.2 Выход движка

```
x  = word param+$10                          ; параметр сдвига
d0 = (7*x) >> 7                              ; x*7/128 (с веткой +$7F округления при x<0)
d0 = d0 + 6
шаг = d4 << d0                               ; d4 = целая часть из 2.1
слот+$14 = шаг                               ; $2BFC58+t*$66+i*$22+$14
$29D0EC  = шаг                               ; последний записанный (глобальная тень)
фаза (слот+$00) += шаг
if фаза > $7FFFFF: фаза −= $800000; WRAP=1   ; 24-битная фаза, перенос = ТИК
   (варианты: mode→d5==3 → фаза := $800000; d5==4 → кламп $400000 без тика)
if WRAP или (param+$18>>6)-обратный ход == 0:
   jsr $24010C(track, timbre, WRAP, шаг)     ; ДИСПЕТЧЕР ТИКОВ
```

$24010C — общий диспетчер событий (вызывается и из $248320 с нулевыми
WRAP/шагом). Ловит тики с 24-битной фазой — это и есть «тик-движок»
(арп/секвенсор/LFO-sync/…): частота тиков = шаг·частота_цикла / 2^23.

### 2.3 Кто и с чем вызывает движок

Оба вызова — из ветки «$2591FC != 0» покадрового цикла (каждый 8-й кадр, $24804C):

```
$24847A: clr.l $2591FC                  ; one-shot сброшен
         d1 = $29C040 − $259204         ; $29C040 = ПОЗИЦИЯ из DSP2 (прерывание $247DBA читает $600004)
         $259204 = $29C040              ; запомнить последнюю-sync позицию
         if d1 < 0 → $2485E2: d1 += $20 ; отрицательная дельта → +$20 и тот же вызов
         push d1; jsr $1000462          ; ДВИЖОК(delta)
         $2591FC = 1                    ; снова armed
```

То есть движок получает **дельту позиции синхронизации** (сколько «времени»
натекло по счётчику DSP2 с прошлого вызова) и подтягивает все 18 фаз
(«catch-up»: член (счётчик+1)·интегратор в числителе — коррекция на пропущенные
фазовые кадры; $29BD6C=1 ставится в кадре, где фазы реально шли, $24805C).

### 2.4 Нормальный ход фаз (без движка)

Каждый 8-й кадр, при $2591FC == 0 ($24805C–$24807C):

```
для t = 0..5, i = 0..2:  фаза(t,i) += слот(t,i)+$0C      ; инкремент кадра
$29BD6C = 1; $2C15D8 = 1
```

Отдельный цикл ($247FC6–$248024, каждый кадр): тайбр-параметр +$18 (long) —
обратный ход: `слот+$4 −= (param+$18 >> 6)·TEMPO` с переходом через
$78F00000 (−$87000000+…) и инверсией знака фазы при переполнении —
«обратная прокрутка» фазы (reverse/регенерация тиков назад).

## 3. Сборщик страниц $267DEE (RAM $1000796)

На каждый из 6 треков (a3 = $1000AD0 + t·$D0 = staging-ячейка t + $7C):

```
1. $29C014 + t*4 := 1                     ; флаг «трек активен» (его читает покадровый цикл $247ED4)
2. flags: (a1)= $29BFFC+t*4 → $3C(a7); обнулить
3. jsr $267A6E(t)                          ; заполнить 3 цели по указателям $100139C+t*$C
4. jsr $267A92(t)                          ; заполнить 7 long × 6 из $1001658+t*$30
5. копия 8 long: $1001962+t*$120 → $1001174+t*$20
6. ГЛАЙД УКАЗАТЕЛЯ: entry+$7C = (($1001F40+t*4 high word) + 3·entry+$7C) >> 2
   → подтверждена формула «0.75/0.25» итерации 26 (16.16, источник $1001F40+t*4)
   (+ досброс: если $1001868+t*4 > 0 → сбросить его и entry+$1C)
7. FADE-IN: entry+$78 = ($29C014+t*4 + 3·entry+$78) >> 2   ; → 1 (квадратичное включение)
8. jsr $267A12(t)                          ; 12 глайдов (см. §5)
9. jsr $23FE46 / push (a0=$10009A8)        ; прочее
```

Ключевое: **значения ячеек страницы глейдятся прямо в OS-структурах**, страница
пересобирается и уходит через DMA5-страницы ($1000A54+t·$D0, отправители
$24390C/$243944 — итерация 26).

## 4. Откуда берутся слова страницы $00–$2F (включая P$2A)

Блок загрузки состояния ($2425C8–$2426F6):

```
$700039 + t*$18  (48 байт/трек, область $700000 — теневые параметры ОС)
   → расширение байт→long (24×2 слова) → $1001880 + t*$120   (288 байт/трек)
   → срез 96 байт: $10018A2+t*$120 → $1000A54+t*$D0 + $00..$5F   ← СЛОВА СТРАНИЦЫ $00–$2F
   → срез 24 байта: $1001902+t*$120 → $1000F34+t*$60             ← параметры темп-движка
```

Значит **P$2A (48-битная пара слов $2A/$2B) — часть этого 96-байтного среза**,
т.е. живёт в OS-структуре `$10018A2+t*$120+$54` и статически грузится в
страницу. Динамика (гладкое изменение при повороте ручки) прилетает через
глайд-механизм §5: указатели $1001508 показывают прямо в ячейки.

**Статус формулы DTIM/DBAS/TEMPO → P$2A (честно):** закрытой арифметической
формулы в ОС НЕТ — это **таблица+глайд**: ручка → спецификация параметра →
$2403D4 даёт адрес ячейки → $267A12 глейдит ячейку скоростью из $10013E8.
Остался один шаг: прочитать таблицу спецификаций (пара байтов spec1/spec2,
которую обработчик $242058 берёт из `-$48(a3)`/`-$90(a3)`) для конкретных
ячеек $1B–$1F (DTIM/DSND/DFB/DBAS/DWID) — это уже механика, не поиск.

## 5. $2403D4 — ДИСПЕТЧЕР «ПАРАМЕТР → ЯЧЕЙКА» (главный результат)

Сигнатура: `$2403D4(spec1, spec2, track) → адрес long` — таблица переходов из
8 слов на $240400, выбор по spec2 (<8), **побайтово верифицировано**:

| группа (spec2) | → адрес | Куда попадает |
|---|---|---|
| 0 | $240422 | **$1000ACC + track·$D0** = staging-ячейка track + $78 (fade-in) |
| 1 | $240472 | **$1000B04 + track·4 + param·$D0** = флаги staging-ячейки ($B0) |
| 2,3,4 | $240450 | **$1000A14 + (52·param + spec1 + track)·4** = слова staging-страницы (52·4=$D0 — шаг страницы!) |
| 5,6,7 | $240438 | **$1000E94 + ((3·param + spec1)·8 + track)·4** = строки $1000E94 |
| (spec2 ≥ 8) | $24048C | дефолт: d0 = $10013E4 (константа-указатель) |

и особый случай $240412 (spec1-режим): **$1001174 + (param·8 + track)·4** —
строки, которые пересобирает сборщик (п. 3 §4: $1001962+t*$120 → $1001174+t*$20).

Интерпретация: 52·param·4 = $D0·param — это ПОСТРАНИЧНЫЙ шаг staging-буферов.
Значит группа 2/3/4 возвращает адрес **слова страницы** (param = страница/трек,
spec1+track = словное смещение в странице). Это и есть механизм, которым ОС
пишет в произвольные ячейки P$00–P$32 — включая P$2A.

### 5.1 Глайд-механизм (как ручка «доезжает» до ячейки гладко)

- **$1001508 + t·$30 + i·4** (i = 0..11): 12 УКАЗАТЕЛЕЙ на ячейки-цели
  (заполняет обработчик $242058 через $2403D4: `d0 = $2403D4(spec1, spec2, t)`
  → `move.l d0, (a4)`; структура ходит $30 на трек, +$18 — вторая шестёрка).
- **$10013E8 + t·$30 + i·4**: скорости глайда (attack: +rate, кламп $7EFFFF;
  decay: +rate (отрицат.), кламп 0) — сам глайд в $267A12:
  `current = *ptr; current += rate; clamp; *ptr = current` — 12 раз на трек,
  каждый кадр сборщика. Тени: $1001628+t·$30 (значение), $1001748+t·$30
  (сохранённые указатели — их читает patch-load $242618).
- Обработчик $242058 одновременно зеркалит байты спецификации в $2C0262
  (образ DSP2) и пишет в $70028A — теневая согласование DSP1/DSP2.

## 6. T2-таблица: величины (сверка с итерацией 24)

Из замеров итерации 24 (target = P$2A·T2[LPQ]·$21D10, P$2A = 1<<16):

| LPQ | target (48-бит) | T2 (float) | T2·2^23 |
|---|---|---|---|
| 32 | $00020CAA89E0 | 0.9769 | 8 194 984 |
| 64 | $01062464DE00 | 124.95 | 1 048 194 597 |
| 96 | $0087F67E6B40 | 64.81 | 543 657 456 |
| 127 | $000087440000 | 0.2519 | 2 112 771 |

Немонотонность подтверждена; T2·2^23 — не «круглые», значит T2 — сырая
8192-словная таблица (пара к T1, обе лежат в паке: 17_delay_echo + DSP $144BC9/$144C49).
Поскольку T2 — DSP-таблица, host о ней не знает: host поставляет только P$2A
(и TEMPO P$23), всю тонкую подстройку по LPQ делает DSP.

## 7. Что это меняет в общей картине

1. **Вопрос 12 закрыт полностью** на уровне архитектуры: транспорт (итер. 26) +
   часы/фазы/тики (этот разбор) + роутер ячеек $2403D4 + глайды. Для порта эха
   осталось только взять конкретные спецификации ячеек $1B–$1F из таблицы
   спецификаций (механическая работа, см. §4 «Статус»).
2. **$791FD0 разгадан**: это 8·$F23FA, модуль хост-кванта темпа — а не «полутон»
   (поправка к заметке итерации 26; совпадение с 2^(−1/12) было приблизительным).
3. **P$2A — не «живая темп-величина»**, а ячейка страницы из OS-структуры
   $10018A2+t·$120+$54 с глайдом через $1001508. DSP-сторона (итер. 24) при
   этом честно пересчитывает цель каждый кадр: target = P$2A·T2[LPQ]·$21D10,
   глайд длины 0.1/кадр (retune speed) — DSP-сторона; глайд самой P$2A — host.

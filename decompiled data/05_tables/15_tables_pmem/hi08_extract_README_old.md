## 🏆 ГЛАВНОЕ ОТКРЫТИЕ

**Все "RUNTIME-ONLY" таблицы найдены в `dsp1_pmem.bin`!**

Они хранятся как **P-bank данные** (cmd=0 в HI08-потоке), а читаются DSP через X/Y адресацию, потому что внешняя SRAM единая — P/X/Y адреса >$100000 алиасятся на одно физическое ОЗУ.

### Как это было обнаружено

1. Декомпрессировали секции 1, 2, 3 из BIN через APLib-декодер (`mm_aplib_mm.py`)
2. Распарсили HI08-записи секции 3: 133 записи формата `[cmd LE24][addr LE24][count LE24][data LE24]`
3. Нашли, что ALL записи — P-bank (cmd=0), включая адреса $141800, $141A00, $1449C6, $143F95, $144446
4. Эти адреса **уже есть в dsp1_pmem.bin** (которая покрывает P:$0..P:$148063)
5. Извлекли данные напрямую из P-образа — **100% совпадение с HI08-потоком**

## Анализ извлечённых данных

### LFO_speed_table (P:$141800, 128 слов)
```
first 8: 400000 3ADEC2 3626CC 31CFA2 2DD189 2A2563 26C493 23A919
@1/4:    046A98 040FFE 03BCA1 036FF4
@1/2:    004E05 0047C3 004207 003CB8
@3/4:    000560 0004F3 00048E 000432
last 8:  0000B9 0000A8 00009F 00008F 000086 00007E 00006D 000065
```
- Начинается с 0x400000 (= 0.5 в 1.23 fixed-point), НЕ 0x7FFFFF как мы предполагали
- Заканчивается 0x000065 (= 101), близко к нашему 0x000065
- Геометрическая прогрессия, но с другим масштабом, чем наша гипотеза

### LFO_mult_table (P:$141A00, 128 слов)
```
first 8: 020000 01E3E3 01C94F 01B036 01987C 01820A 016CD7 0158D1
@1/2:    000DCC 000D0B 000C52 000BA2
last:    00006D 000000
```
- Начинается с 0x020000, заканчивается 0x000000
- Не complementary к speed table (другая форма)

### kernel_curve_table (P:$1449C6, 128 слов)
```
first 8: FEDCBB 010F79 00FD05 00EBD1 00DBCA 00CCD9 00BEEC 00B1F2
@1/2:    000338 000300 0002CC 00029B
last 8:  000010 00000F 00000E 00000D 00000C 00000B 00000A 00000A
```
- Начинается с 0xFEDCBB (отрицательное в signed 24-bit: -74565)
- Быстро убывает к почти нулю
- НЕ quadratic (как мы предполагали) — сложная кривая

### div_table_1 (P:$143F95, 107 слов)
```
first 8: 0025AD 0025E2 002616 00264B 002680 0026B6 0026EC 002722
@1/2:    003234 003279 0032C0 003306
last 8:  004067 0040C1 00411B 004175 0041D0 00422C 004288 0042E4
```
- Монотонно растёт от 0x0025AD до 0x0042E4
- НЕ reciprocal (как мы предполагали) — линейно растущая таблица

### div_table_2 (P:$144446, 128 слов)
```
first 8: 0438FB 047522 04B4A1 04F7AA 053E6D 058920 05D7FB 062B39
@1/2:    7FFFFF 7FFFFF 7FFFFF 7FFFFF
last 8:  7FFFFF 7FFFFF 7FFFFF 7FFFFF 7FFFFF 7FFFFF 7FFFFF 7FFFFF
```
- Начинается с 0x0438FB, растёт, затем насыщается на 0x7FFFFF (max signed)
- Вторая половина полностью насыщена — interesting!

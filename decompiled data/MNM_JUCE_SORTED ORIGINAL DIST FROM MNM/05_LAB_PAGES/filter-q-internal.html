«AMP envelope strictly controls volume. Cannot directly modulate filter.»ПРАВДА ✓У AMP и FILTER две completamente разные огибающие. AMP = 4 стадии `ATK/HOLD/DEC/REL` (`Y:$500..$503` + `Y:$518..$51C`). FILTER = 2 стадии `ATK/DEC` (`Y:$50C/$50D`) + биполярные `BOFS/WOFS` (`Y:$50E/$50F`). Даже триггеры у них раздельные: `AMP trig` и `FILTER trig` (мануал стр. 58).
«Assign DEST 1 to VOL... Assign DEST 2 to BASE»ШИЗА ❌У каждого LFO в Monomachine ТОЛЬКО ОДИН DEST (`PAGE / DEST / TRIG / WAVE / MULT / SPD / INTL / DPTH`). Никаких `DEST 1` и `DEST 2` внутри одного LFO нет (это AI перепутал с Octatrack / Analog Four). Чтобы качать и VOL, и BASE одновременно, нужны два разных LFO (например LFO1 → AMP VOL, LFO2 → FILT BASE).
«BOFS affects BOTH HP and LP, while WOFS only controls LP»ПРАВДА ✓Мануал стр. 30–31: `BASE` — частота среза HPF, а `WDTH` — **зазор (gap width)** между HPF и LPF, то есть **`f_LP = f_HP + WDTH`**. Поэтому прибавка `BOFS` к `BASE` сдвигает всю полосу целиком (и HP, и LP одновременно!), а `WOFS` двигает только верхний край `LP`.

Точные числа из мануала Elektron (стр. 31), которые объясняют математику ядра A

«The filter normally tracks the pitch of the note played. The high pass filter starts cutting two octaves under the base pitch when the BASE parameter is set to zero.
Both the BASE and the WDTH parameters rise one octave for eight steps. This exact locking of the filter to octaves is useful if you want to use high filter Q settings to be used for pitch.»

Смотри, как эта одна фраза разработчика расшифровывает загадочную строчку ядра `P:$537` (`(Y:(V-$20)) * $800 - $80`):

  • • В домене питча ядра **1 октава = `0x800` (2048 единиц)** (проверено в `midiNoteWord()`).
  • • Мануал говорит: **8 шагов ручки BASE или WDTH = 1 октава**. Значит **1 шаг ручки (0..127) = `0x800 / 8 = 0x100` (256 единиц питча)**!
  • • Весь ход ручки `0..127` = `128 / 8 = 16 октав` (`16 × 12 = 192 полутона`, 1.5 полутона на деление ручки).
  • • При `BASE = 0` срез HPF равен **`note_pitch − 2 октавы` (`− 0x1000`)** (для C4 = 261.6 Гц это C2 = **65.4 Гц**).
  • • При `HPQ` или `LPQ` около максимума фильтр **входит в чистую самоосцилляцию** («if you want to use high filter Q settings to be used for pitch») — именно поэтому шаг привязан ровно к `1/8` октавы!

Почему Q до сих пор не виден как формула — и как достать его за 1 запуск

Ты абсолютно прав: `parameterPageOffset` дал нам **входной адрес** (`HPQ = Y:$50A`, `LPQ = Y:$50B`), но **сама инструкция**, которая превращает `Y:$50A` и `Y:$50B` в коэффициент демпфирования внутри `Y:$91+`, лежит в `dsp1_kernel_P0000-0B4D.txt` между `P:$0537` и `P:$05D2`.

А в `headless/main.cpp` (который я только что вытащил целиком!) обнаружились две готовые фичи, написанные специально для этого:

Фича 1 в headless/main.cpp — встроенный дизассемблер ядра

Строка 199: `memory.saveAssembly(argv[4], assemblyStart, 1024, ...)` — сохраняет ровно 1024 инструкции начиная с любого hex-адреса `assemblyStart`!

monomachine_headless sec1.bin sec3.bin 1000 ^
  filt_537.asm 160 537

Начнёт прямо с `0x537` и запишет маленький файл `filt_537.asm` без всякой обрезки.

Фича 2 в headless/main.cpp — готовые снимки памяти `.mnmsnap`

В коде уже забиты 22 точки остановки (`snapshotPcs`), включая **`0x00537`**, **`0x005A2`** и **`0x006C0`**, которые дампят все слова `X:$000..$7FF` и `Y:$000..$7FF` в файл!

set MNMLAB_VOICE_OVERRIDES=10=0x7f0000
set MNMLAB_SNAPSHOT_PREFIX=hpq127
monomachine_headless sec1.bin sec3.bin 250000

`10=0x7f0000` ставит `HPQ` (слот 10) в 127, а на выходе — дамп `Y:$91+` на шаге `p0005a2`.

1. Вскрыта `parameterPageOffset` — каждый параметр нашёл свой адрес A

Дословно из core/monomachine_engine.cpp:

std::size_t Engine::parameterPageOffset(const Parameter parameterId) noexcept {
    const auto index = static_cast<std::size_t>(parameterId);
    if (index < 24) return index;          // AMP 0..7, FILT 8..15, EFFX 16..23
    if (index < 32) return 44 + (index - 24);  // SynthA..H -> 44..51
    return 31;                             // TrackLevel
}

// И как именно ColdFire кладёт значения:
// "ColdFire streams each user-facing 0..127 value as a 16.16 word"

Второе предложение снимает ещё одну головную боль: ColdFire НЕ делает никаких кривых. Каждая ручка `0..127` уходит в DSP просто как `value << 16`. Вся математика — целиком внутри DSP. Capstone M68K не нужен.

3. Найдена настоящая AMP-огибающая — и почему в доке путаница

// monomachine_engine.cpp, configureVoicePage():
constexpr std::array<dsp56k::TWord, 5> trackEnvelope{ 0, 0, 127, 127, 0 };
for (std::size_t i = 0; i < 5; ++i)
    m_voicePage[24 + i] = trackEnvelope[i] << 16;   // -> Y:$518 .. Y:$51C = V-$10 .. V-$0C

В прошивке ДВЕ структуры для AMP: пользовательские ручки лежат в `Y:$500..$503` (индексы 0..3), а в `Y:$518..$51C` (`V-$10..V-$0C`) лежит 5-словный `trackEnvelope`, который читает `P:$4A8`!

Дефолты `{0, 0, 127, 127, 0}` для `V-$10..V-$0C` идеально ложатся на формулу из `P:$4A8`:

  • • V−$10 = 0   → attack rate = мгновенно
  • • V−$0E = 127 → sustain level `(V-$0E)² = 1.0` (максимум!)
  • • V−$0D = 127 → release rate = быстро

4. Дефолты фильтра из рабочего пресета LASS3

BASE=0  WIDTH=127  HPQ=0  LPQ=0  ATK=0  DEC=32  BOFS=64  WOFS=64

Полностью открытый фильтр: нижний край `0` (20 Гц), ширина `127` (до верха), оба резонанса `0`, оба оффсета `64` = **ноль** в биполярной шкале. Подтверждает, что `64 ($400000)` — нейтраль для `BOFS`, `WOFS` и `DIST`.

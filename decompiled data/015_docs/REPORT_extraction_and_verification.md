# Monomachine SFX-6 / OS 1.32B — DSP56303 Firmware: COMPLETE EXTRACTION & VERIFICATION

Дата: 2026-09-17. Продолжение исследования (части 1–3 в chat.z.ai/s/afd3e746).

## ГЛАВНЫЙ РЕЗУЛЬТАТ

**DSP1/DSP2 прошивки полностью извлечены из поставляемых файлов** (BIN 8 MB).
Прошлая сессия остановилась на выводе «DSP firmware отсутствует в BIN и SYX» —
он оказался **неверным**. Прошивка там есть, но хранится в виде:

```
флеш BIN 0x4000+  =  [u32 размер][4B param][APLIB-вариант сжатые данные]  (записи-секции)
   секция 0: 0x286E4 байт  → ColdFire main (распаковывается в RAM 0x200000)
   секция 1: 0x01EBE байт  → блок данных для DSP (через буфер 0x200000)
   секция 2: 0x01E67 байт  → блок данных для DSP
   секция 3: 0x49779 байт  → блок данных для DSP
   (формат записи: следующая = +размер+8)
```

**APLIB-гипотеза из README mmnova подтвердилась** — просто не в SYX, а внутри BIN.
Параметры, найденные в машинном коде декомпрессора (BIN 0x1C4):
`OFFSET_BIAS = 768-1 = 767` (`addi.l #$fffffd00`), `FAR_THRESHOLD = 0xD00 = 3328`,
`REUSE_GAMMA = 2` (гамма==2 → переиспользование смещения), длины совпадений кратны 1 байту,
EOF = гамма 3 + байт 0xFF.

## Цепочка загрузки DSP (восстановлена полностью)

1. **ColdFire boot** (BIN 0x0–0x3D40, resident во флеше):
   - пишет 0 в HI08 +1 (сброс DSP1 @0x500000, DSP2 @0x600000);
   - заливает **бутлоадер 133 слова** из флеша 0x3BAF (слова LE) в P:$100 каждому DSP
     через протокол DspBoot `[Length][Address][слова]` (HI08 TX = байты +5/+6/+7);
   - декомпрессирует секции из флеша в RAM 0x200000 (APLIB, функция 0x1C4);
   - льёт их в DSP (функция 0x7CE) в виде записей
     **`[cmd][addr][count][data…]`**: cmd 0 = P-память, 1 = X, 2 = Y, 3 = JMP;
   - завершает командой **`JMP P:$000066`** — точка входа ядра.
2. **Бутлоадер DSP (P:$100–$184)**: настраивает OMR/BCR, тестирует внешнюю SRAM
   (0x555555→X:$100000, 0xAAAAAA→X:$110000), копирует себя в P:$14FFCB,
   принимает записи через HI08 RX (`brclr #0,x:$FFFFC3`), эхо-рует каждую команду.
3. **Всего в DSP1 заливается 116 186 слов** (DSP2: 116 118): 145 записей.

## ВЕРДИКТ ПО ChorusCore.cpp — РЕАБИЛИТАЦИЯ

Сверка всех 292 покомандных комментариев `// P:14xxxx` из ChorusCore.cpp
с дизассемблом реальной прошивки: **291 совпадение (99.7%)**, 1 «промах» = nop.

Вывод части 2/3 прошлой сессии («ChorusCore.cpp — псевдодизасм с выдуманными
адресами, grotesque fabrication») — **ОШИБКА**, основанная на недостоверном
`monomachine_os132b_reverse_engineering_status.txt`. Реальные факты:

- `P:147661 move #>$114000,a0` — РЕАЛЬНО (кольцевой буфер delay @ X:$114000);
- `P:147663 move y:>$124,x1` — РЕАЛЬНО (глобальная константа Y:$124);
- `P:14766e mpyi #>$fffc20,x0,a` — РЕАЛЬНО (mpyi со знаковым immediate);
- `P:147671 move #>$14a000,x0` — РЕАЛЬНО (**widthTable @ $14A000** подтверждена);
- `P:14767d move #>$7fffff,b`, `P:147680 cmp #>$80,a` — РЕАЛЬНО;
- `bset #$14,sr` (saturation), `do #<$10` (16-фреймовый блок) — РЕАЛЬНО;
- state-блок X/Y:(r6+$10..$22) — РЕАЛЬНО;
- rts ровно на P:14767A, процесс ровно с P:14767B — РЕАЛЬНО.

RE-status же содержит фактические ошибки:
- «DSP = 3 674 слова, P:$0000..$0E5A» — это только НИЗ области кода;
  полный образ = 114 773 слова (P:$0000–$0B4D ядро + P:$100000–$1134C4
  таблицы + P:$140000–$148063 код машин/процедуры);
- «первые 10 слов DSP1 030000 660000 …» — не соответствуют реальному образу
  (реально: 0AF080 FF0000 0C0002 000000 0C0004 … — вектора прерываний);
- «таблица JSR P:$0070→$0900 и т.д.» — не подтверждается реальным образом;
- «ChorusCore основан на разоблачённой интерпретации 0x770A/0x770B» —
  реальный код chorus использует X/Y:(r6±off) — как в ChorusCore.cpp.

## КАРТА ПАМЯТИ DSP (DSP1, подтверждена фактической заливкой)

| регион | содержимое |
|---|---|
| P:$0000–$0065 | вектора прерываний (пары `0C00xx 000000`) |
| P:$0066–$00E5 | ядро: OMR/BCR init, таблица переходов (P:$76–$83 → $100077/$100139/$145CCE/…) |
| P:$00E6–$0B4D | kernel-функции (helpers $3AA/$3D3/$3E0, вызываются из машин), константы 0x0CCCCD@P:$9DC, 0x733333@P:$9DE |
| X:$02C0–$02C3 | базовые указатели аудио-буферов (0x160/0x1C0/0x220/0x280) — у DSP1/DSP2 РАЗНЫЕ |
| X:$0394–$03B3 | таблица 32 слов (коэффициенты/питч) |
| X:$03F4–$0413 | парная таблица 32 слов |
| Y:$0132–$0333 | синус-таблица FM (512+2 слова: 0→0x80→0→отриц.) — «dsp56k_sin_lookup» = ТАБЛИЦА |
| Y:$0334–$0433 | 256 слов (вторая волна/таблица) |
| P:$100000–$1001D0 | **3 таблицы диспетчеризации машин** (init/config/process × 34) |
| P:$1001D1–$101A51 | 4×1568 слов (параметрические данные машин) |
| P:$101A7B–$104210 | 768 + 14×256 слов (таблицы) |
| P:$104210–$1134C4 | вейвтейблы/данные машин (блоки 987–8174 слов с 1-словными маркерами) |
| P:$140000–$141A98 | машинно-независимые данные/код (2048+4096+5×128+24) |
| P:$141A98–$148063 | **процедуры машин**: CHORUS = P:$147661–$1477DE (381 слово) |

DSP1 vs DSP2: различие ТОЛЬКО в ядре P:$0000–$0B4C (9 слов X-конфига,
роли mixer/producer), всё остальное байт-в-байт идентично (1 340 695 слов).

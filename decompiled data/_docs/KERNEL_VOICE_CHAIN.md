# Monomachine OS 1.32B — DSP56300 Kernel: Voice Chain Analysis

Дата: 2026-09-17. Сессия 2. Инструмент: дизассемблер dsp56k-emulator (verificирован 100% на корпусе).
Все адреса кода проверены свежим дизассемблированием `dsp1_pmem.bin` (DSP1).

---

## 0. Новый инструмент (главный результат сессии)

`scripts/dis56300_tool/` — standalone C++ дизассемблер DSP56300 на базе ядра
эмулятора dsp56k (2daaat/dsp56300-md-mm, submodule из gearmulator). Поддерживает
ВСЕ группы инструкций, включая dual-move параллельные переносы.

Верификация против существующего корпуса (старые листинги):

| регион | диапазон | инструкций | совпадений |
|---|---|---|---|
| chorus (golden) | P:$147661-$1477DE | 292 | 291/292 (1 = граница региона) |
| kernel | P:$0000-$0B4E | 2243 | 2243/2243 (100%) |
| FM+STAT | P:$145D12-$1461E7 | 1000 | 1000/1000 (100%) |
| все машины | P:$141A98-$148064 | 22836 | 22836/22836 (100%) |

Сборка: `g++ -std=c++17 -O1 -I. main.cpp dsp56kEmu/disasm.cpp dsp56kEmu/opcodes.cpp -o dis56300`
Запуск: `./dis56300 dsp1_pmem.bin <startHex> <countDec> <out.txt> [symbols.txt]`

Вывод: старый корпус был корректен; подозрение на «dual-move не парсятся» не
подтвердилось — dsp56k выдаёт идентичный текст на всём проверенном коде.

## 1. Топология: внешняя SRAM алиасится между X/Y/P

Доказательство: диспетчерские таблицы машин залиты в P:$100000+ (проверено
заливкой), но kernel читает их как `x:(r0+$10016b)` (P:$EB), `x:(r0+$10018d)`
(P:$FB), `x:(r0+$1001af)` (P:$106) — X-адресацией по тем же адресам.
=> физическая SRAM одна, X:/Y:/P: внешние обращения попадают в одно ОЗУ.

Следствия:
- Таблицы, извлечённые из P-образа, валидны и для X:/Y: обращений.
- X:$14A000 (sine-таблица осцилляторов, 8K слов $14A000-$14BFFF) и X:$114000
  (delay-буферы) — RUNTIME-память, заливается ColdFire через HI08-монитор,
  в bin-прошивке её нет (потому её и не было в образах).
- Хорусовые «width tables» X:$14A000/$14A800 = первые два сегмента 8K sine.

## 2. Главный цикл (P:$0066-$01A3) — подтверждено

1. P:$76-$82: единоразовая инициализация: monitor P:$100077/100139, машины
   P:$145CCE, P:$100109/10009E/10012E/100110.
2. P:$87-$91: wait-sync: `movep x:<<$ffffeb,a` (HI08), ждёт $180/$160/$140
   (роли DSP1/DSP2). Значение выбирает раскладку аудио-буферов:
   - DSP1 ($140): базы r1=$140 r2=$1A0 r3=$200 r0=$260, x0=$2CC x1=$32C
   - DSP2 ($160/$180): аналогично свои (сохраняются в X:$2C0-$2C3 —
     совпадает с известной таблицей audio_buffer_bases)
3. P:$C8-CD: Y:$123 = $528 (база voice state), Y:$124 = 0 (счётчик голосов).
   Голос = 256 слов (stride $100): state блок V = Y:$528 + voice*$100.
4. P:$CF-$FF: диспетчер машины на голос (см. §3).
5. P:$100-$112: r1 = process-функция машины (таблица X:$1001AF+r0).
6. P:$117-$131: выбор входного буфера (r0 = X:$2C0/$2C1/$2C2/$2C3 по битам
   X:$2C4) → jmp func_000262 (pre-voice) → в конце jsr (r1) = машина.
7. P:$132-$142: восстановление m0-m7, r6 = Y:$123-$28, r7=$100, r5=X:$2C3 →
   jmp func_0004a8 (post-voice: AMP env + LFO + фильтр).
8. P:$163-$16F: Y:$123 += $100, Y:$124 += 1; при Y:$124==3 → func_0001A3
   (обработка буферов/ESAI) и следующий заход.

Диспетчер (34 слота, X-алиас P-таблиц):
- INIT   X:$10016B + machine#  (обновление только при смене машины, V+0 bit7)
- CONFIG X:$10018D + machine#
- PROCESS X:$1001AF + machine#

## 3. func_000262 (P:$262-$2EC) — pre-voice: portamento + LFO-модуляция питча

Вход: r6 = V (база голоса), r1 = process-адрес машины, r0 = входной буфер.

### 3.1 Два slew-ограничителя (portamento-подобные) P:$262-$270, $271-$27E

Пара блоков, каждый: current (X: V-$21 / V-$26), prev (V-$22 / V-$25),
rate (V-$20 / V-$24), accum (V-$1F / V-$23):
- target1 = Y:(V+$01) — питч/нота голоса
- target2 = Y:(V-$06)
- current стремится к target, delta ограничен rate, накапливается в accum
  с множителем из curve-таблицы (см. ниже).

### 3.2 Curve-таблица Y:$1449C6 (P:$27F-$294)

```
r4 = r3 = $1449C6
idx1 = (V-$21)>>16, idx2 = (Y:(V-$0C))>>16      ; 7-битные индексы
x0 = Y:[$1449C6 + idx1], x1 = Y:[$1449C6 + idx2]
y1 = Y:(V+$02) = SYNT param0 ; y0 = $7F-константа (clamp)
a = x0*y1, b = x1*y1 (клампятся при отрицательных на $7F), >>8
```
→ y0/y1 = масштабные множители для ramp-аккумуляторов.

### 3.3 Инкремент питча (P:$295-$2EA)

```
accum2 += delta2 * y1 ; клампы к target2 (P:$29B-2C5)
accum1 += delta1 * y0 ; клампы к target1
acc = clamp( accum1 + Y:(V-$02)*? + Y:(V-$0A) + b*$B000>>? - $5800 + saved48,
             0, $5800 )                       ; P:$2C6-$2D7
; acc сохраняется в X:(V-$27) (и дублируется в V+$FF при голосе<2)
oct  = acc >> 11                                ; 0..11 (11 октав!)
frac = acc & $7FF                               ; 0..2047
a    = X:[$140000 + frac]                       ; wt[i] = 0.5 * 2^(i/2048)
a    = (a >> 10) << oct
a    = a * $1D22A >> (23+3)
```
**Результат в A (48-bit) на входе машины = экспоненциальный фазовый инкремент**
osc = 2^(acc/2048) * C, где C = 2^7 * $1D22A / 2^23 / 2^3 = 0.02831 * 128 / 2^3.

Проверка X:$140000: wt[i]/wt[0] = 2^(i/2048) с точностью 1e-9 (верифицировано
на всех 2048 записях). Диапазон acc 0..$5800 = 11 октав, 2048 ступеней/октава.

Машина GND-SIN (P:$144CD0): `A48 * $17C6F9` (= *0.18625) — её собственный
масштаб инкремента; далее фаза аккумулируется в 48-бит L и читается из
sine-таблицы $14A000 с 13-бит маской (8192 записи/период).

### 3.4 Вызов машины

P:$2EB: `jsr (r1)` — 16-сэмпловый блок голоса. Аккумулятор A = фазовый
инкремент, r0 = входной буфер, r6 = V.

## 4. func_0004A8 (P:$4A8-$5FB+) — post-voice: AMP env + LFO + фильтр

Вход: r6 = V-$28 ! (все r6'-offsets = V-offset - $28)

### 4.1 Глобальный AMP-огибающая (P:$4A8-$4F5) — машина состояний

Глобальный уровень Y:$4FF (общий на все голоса в данный сэмпл-блок):
- состояние 1 (attack): Y:$4FF += TBL[Y:$141800 + (Y:(V-$10))>>16]
- состояние 4 (decay):  с участием (V-$0E)² и TBL[$141880+idx], сравнение
- состояние 5:          Y:$4FF = (V-$0E)²
- состояние 2 (release):Y:$4FF -= TBL[$141880 + (V-$0D)>>16]  (P:$4E5-4EE)
- default:              Y:$4FF = $7FFFFF (полный уровень)

→ **Таблица скорости Y:$141800 (128 слов) общая для LFO SPD и AMP env rates!**
Раскладка: $141800+128 = $141880 = FM-DYN wavetable — стыкуется байт-в-байт.

### 4.2 Контекст голоса (P:$4F5-$4FE)

34 слова Y:$100-$121 ↔ X:$97-$D7 (save/restore глобального рабочего Y-окна).
r7 = V-$28+$DC = V+$B4 — окно состояния LFO внутри голоса.

### 4.3 Триггер (P:$4FF-$505)

Y:(V-$08) == 1 (note-on триггер) → сброс LFO-состояния (Y:(r7-$1)=0 и др.).

### 4.4 LFO-фаза (P:$506-$536)

```
state==0: phase(X:(r7-$1)) += TBL[$141800 + (Y:(V-$1C))>>16]   ; SPD
          carry → флаг завершения цикла (r7-$2 = 1)
state==1: фазовая математика с (V-$05)² и $791FD0 (0.9469) — декей-ветка
state==2: phase -= TBL[$141A00 + ((Y:(V-$1B))+$7FFF)>>16]      ; MULT
          if < 0 → 0
```
- Y:$141800 = инкремент фазы за БЛОК (16 сэмплов) по 7-бит SPD.
- Y:$141A00 = точка сброса цикла (длина цикла) по 7-бит MULT.
- Геометрические таблицы: SPD ratio = 0.919846/шаг (8 шагов ≈ октава).

Частота LFO (фаза 24-bit wrap через carry, инкремент за БЛОК 16 сэмплов):
`f = inc[SPD] * (44100/16) / 2^24 = inc[SPD] * 2756.25 / 2^24`:
- SPD=0   → 1378 Hz (audio-rate верх)
- SPD=32  → 47.6 Hz
- SPD=64  → 3.28 Hz
- SPD=96  → 0.226 Hz
- SPD=127 → 0.0166 Hz
Диапазон 0.017 Hz – 1378 Hz — согласуется с LFO Monomachine (до audio-rate).

### 4.5 Питч/тон-вычисления + ДЕЛЕНИЕ (P:$537-$58B)

- TONE-ветка: (Y:(V-$20))*$800-$80 (P:$537-53D) — индекс/множитель LP.
- INTL/DPTH-ветки: |Y:(V-$1A)+$C00000| * $700 ... (P:$53E-$56C).
- Деление: `do #<$18 + div` (24-бит, P:$586-$588), делимое =
  TBL[X:$143F95 + x0*$4AF] + TBL[X:$144446 + y0*$80], делитель = (a>>1).

### 4.6 SVF-фильтр ×2 (P:$5D3-$5E8 и P:$5EB-$5FA)

Две одинаковые петли `do #<$8` (8 итераций × 2 аккумулятора = 16 сэмплов):
```
x0 = $F528BD (-0.08415), x1 = $4A4DF0 (0.58056)  ; коэффициенты
состояния: X:$71+n*3 (a-bank) и X:$73+n*3 (b-bank), n=0..7
коэффициенты читаются из Y:$91+ (рабочая область, заполнена выше)
```
→ **multi-mode фильтр FILT-страницы: 2-pole SVF, 16 сэмплов/блок**.
Вторая петля — второй канал (L/R) или HP-секция.

## 5. Monitor HI08 (P:$100000-$1001D0) — как ColdFire пишет параметры

Командный процессор host-интерфейса (прерывания, порт $FFFFC3/$C6/$C7):
- читает команду → ветвление bra r0 (P:$100006) → ~40 команд:
  - чтение P:/X:/Y:/L: по адресу (P:$100052/10005C/...)
  - запись регистров (movep r0-r7, n0-n7, m0-m7 → $FFFFC7)
- ColdFire через этот канал заливает: параметры голосов в Y: state-блоки,
  runtime-таблицы (sine $14A000+), машинные patch-данные.

| V-$02, V-$06 | ramp-targets pre-блока | func_000262 |

| V-$0C | LFO-модуляция: индекс curve | func_000262 P:$284 |
| V-$0A | инкремент питча (добавка) | func_000262 P:$2C8 |
| V-$10..-$0D | AMP env: attack/decay/release rate-параметры | func_0004A8 P:$4B4-4EE |
| V-$1C | LFO SPD (7-бит в старших) | func_0004A8 P:$509 |
| V-$1B | LFO MULT (длина цикла) | func_0004A8 P:$52B |
| V-$19, V-$1A | LFO INTL/DPTH-ветки | func_0004A8 P:$53E |

ColdFire), kernel их только читает. Машинам доступны V+$00+ (положительная).

## 8. Что это меняет для эмулятора (практика)

1. **Порядок цепочки на голос** (реальный, из kernel):
   machine osc → [func_0004A8: AMP env → LFO1/2/3 → SVF фильтр (FILT)] →
   микшер. Причём LFO питча/параметров применяется ДО машины
   (func_000262 готовит фазовый инкремент).
2. **LFO скорости**: не guessed — таблица Y:$141800 (128 значений), можно
   положить в эмулятор как есть и индексировать 7-бит SPD.
3. **Питч→фаза**: wt[i] = 0.5*2^(i/2048), 2048 ступеней/октава, 11 октав,
   масштаб $1D22A — точная формула из прошивки (§3.3).
4. **AMP env**: state machine 1/4/5/2 + общая rate-таблица Y:$141800.
5. **Фильтр**: 2-pole SVF, коэффициенты $F528BD/$4A4DF0 + per-voice
   состояния — заменить PolyBLEP-«24dB»-приближение на точную структуру.
6. **Sine осцилляторов**: 8192-записи @ X:$14A000 (runtime, считается
   ColdFire'ом; в эмуляторе можно сгенерить sin на 8192 точек).

## 9. Открытые вопросы (нужен ColdFire-сайд)

1. Точная запись страничных параметров в V-$28..V-$01 (какие байты патча в
   какие offset'ы) — в ColdFire main (sec0_full.bin), нужен MCF5206e disasm
   (capstone M68K) — отдельная сессия.
2. Роли V+$0A/$0B и точное назначение INTL/DPTH веток (P:$53E-56C) —
   требует трассировки записи из ColdFire или A/B на железе.
3. Две SVF-петли = L/R или LP/HP — проверить по буферам r5=X:$2C3.

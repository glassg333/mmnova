# Monomachine SFX-60 OS 1.32B — данные, добытые из оригинальной прошивки (итерация 8)

**Дата:** 2026-09-20
**Прошивка:** `elektron_sfx6-60_os1.32b.bin` (8 388 608 Б)
**SHA-256:** `369849175602e20a9dd2b6e0ad8ac404b76f82718b14afbf1cbc01b7acabec7e`
**Метод:** дизассемблирование ColdFire-кода секции 0 (capstone M68K) + статистический анализ
128 слотов банка паттернов (секция 4, база 0x16AE4, RAM 0x716AE4). База итерации 7 (v7)
подтверждена; все новые границы проверены кодом ОС.

---

## 1. Главный результат итерации 8

**Слот паттерна (6520 Б) расшифрован до уровня полей:** тригг-маски, ноты, длина, индекс
кита, векторы машин, параметры машин — всё подтверждено конкретными инструкциями ОС.
**Все 64 заводских паттерна полностью декодированы** (триггы + ноты по 6 дорожкам),
декод самосогласован: ноты ⊆ триггам в 100% случаев (единственное исключение — один
«осиротевший» байт ноты в слоте 44, дорожка 4, шаг 56: след правки).

### 1.2 Как ОС работает со слотом (новые доказательства)

- **Загрузчик** (OS 0x349D4, подтверждён v7): слот X → двойной RAM-буфер `$296806`/`$294E8E`;
  после копирования ОС читает длину `+0x424` (`lea $716F08; move.b (a0,d3.l)`) и кит `+0x426`
  (`lea $716F0A`); байт кита сравнивается между двумя буферами
  (`move.b $2952B4` vs `move.b $296C2C`) и при различии вызывается `jsr $2495AC(1, kit)` —
  **смена кита**. Семантика +0x426 = «индекс кита» подтверждена поведением кода.
- **Обмен дорожек** (OS 0x33B04..0x33C02, `disasm_track_swap.asm`): при переносе дорожки
  d2→d3 копируются: 8 Б `+0x1B0+t·8`, 8 Б `+0x1E0+t·8`, **64 Б нот `+0x2A4+t·64`**
  (`lsl #6; addi #0x2A4`), байты `+0x428/+0x42E/+0x434/+0x44C/+0x452/+0x458/+0x45E/+0x464/+0x46A`
  (+ t), 16 Б параметров `+0x470+t·16` (`addi #0x470; lsl #4`). Векторы машин (4-6) НЕ переносятся
  — они привязаны к киту.
- **Запись векторов машин** (OS 0x2F3DC, `disasm_field_writer.asm`): цель = `банк + слот·6520 + 0x43A/0x440/0x446 + дорожка`;
  ограничения значений ≤3 и ≤11 (ID машины). Отсюда: векторы +0x440/+0x446 — per-дорожечные
  поля машин (алгоритм ≤3, тип ≤11).
- **Цикл 128 слотов** (OS 0x3D5F2, `disasm_field554.asm`): `lea $717038` (банк+0x554) с шагом
  0x1978 — читает +0x554/+0x555, пишет слово в +0x552, байт +0x554 ← +0x555: знаковый `<<8`
  3-байтового поля. Подтверждает и размер банка (128 шагов ровно), и поле +0x554.
- **Вставка шага** (OS 0x164FE/0x1B8AE, `disasm_insert_step.asm`): сдвиг байтов в строках
  пер-шаговой зоны `move.b $557(a0)` со stride 64 (`lsl #6`), циклы 8×7 → до 56 строк.
- **Wear-leveling масок**: 7 слотов-копий; в 15 слотах (1, 6, 8, 16, 21, 22, 33, 34, 39, 44,
  52, 60, 61, 62, 63) копия `+0x120` новее остальных — журнал перезаписи без стирания.

### 1.3 Декод заводских паттернов (новые данные!)

`03_decoded/patterns_readable.txt` — полная распечатка: для каждого из 64 заводских
паттернов — длина, кит, тригги и ноты всех дорожек. Пример (слот 0, дорожка 1 — мелодия
«SUPERWAVES», 64 тригга): `00:48 01:4a 02:53 03:48 04:4a 05:51 ...` — последовательность
образует законченную музыкальную фразу (восходяще-нисходящий ход по терциям).

Машиночитаемая версия: `03_decoded/patterns_decoded.json` (128 слотов: тригг-шаги, ноты,
длина, кит, маски A/B, покрытие нот-в-триггах).

Эталонный «пустой» слот завода: `03_decoded/empty_template.bin` (6520 Б) — шаблон, из
которого ОС создаёт новый паттерн (len=0x10, машины [00×6], параметры 0x40, векторы
[05×6][07×6][08×6]).

### 1.4 Grid-слот 698 Б (дополнение к v7)

- Кит: маркер `ff 00` (+0..1), имя (+2, 10 Б), тело: **6 пер-дорожечных записей по 72 Б**
  от +0x18, хвост +0x1C8..0x2B2 — таблицы волн (пила `3f 00 c1 00`, квадрат `01`, импульсы `05`).
- Киты 66..129 различаются между собой ТОЛЬКО именем (+2..11) и байтом +0x1CD.
- Паттерн-grid: имя (+0, 10 Б) + тело-параметры (+0x0C..); у сетки паттерны 0 и 2 байт-в-байт
  совпадают (v7 считал их уникальными — уточнение: имя в теле не хранится, тела идентичны).

### 1.5 Ответы на открытые вопросы итерации 7

1. **Побайтовая карта 6520-слота** — построена (см. §1.1); шаговая сетка: тригг-маски
   (+0x000, обратный порядок слов!), ноты (+0x2A4, дорожка-мажор), пер-шаговые строки
   (+0x557, stride 64, до 56 строк).
2. **Тело 698-слота** — кит: 6 записей × 72 Б + таблицы волн; паттерн-grid: имя + параметры.
3. **Семантика +0x426** — индекс кита, подтверждена кодом смены кита.
4. **Поля GLOBAL 264 Б** — частично: см. §1.6 (требует отдельной итерации).
5. **Природа индивидуальных данных пустых слотов** — хвостовые записи (остатки журнала
   записи флэш) + поля +0x54E..+0x551; у 49/64 пустых слотов уникальные блобы хвоста.

### 1.6 GLOBAL-слоты 264 Б — первые поля

- `+0x00..+0xFD` — тело (варьируется по слотам);
- `+0xFE` — инициализируется ОС циклом (`lea $71639E`, шаг `0x108`, до `$7169CE` — 6 структур;
  OS 0x2BC..0x2DE) — у 6 из 8 слотов;
- рабочие копии в RAM: `$29D0F0` / `$29D1F8` (разность 264 = 0x108).
Полная карта полей GLOBAL — задача итерации 9 (требует дизассемблирования `$29D0F0`-доступов).

## 3. Открытые вопросы для итерации 9

1. Расшифровка соответствия строк зоны +0x557 → (дорожка, параметр): нужен дизассемблиоз
   плеера шага (поиск d16(An)-доступов к $294E8E+0x557...).
2. Полная карта полей GLOBAL-слотов 264 Б (доступы к $29D0F0).
3. Семантика масок A (+0x1B0) и B (+0x1E0) — кандидаты: accent/slide/mute-флаги.
4. Семантика 3-байтового поля +0x554 (знаковое <<8) — candidates: BPM-оффсет, swing, transpose.
5. Редкая зона +0x0C98 (слоты 1 и 16): таблицы форм/огибющих — вероятно GND-машина паттерна.
6. Хвостовые записи (+0x14D7): формат записей журнала и указателей $76xx/$8Dxx/$97xx.
7. Тело записей кита (72 Б на дорожку): привязка полей к параметрам машин.

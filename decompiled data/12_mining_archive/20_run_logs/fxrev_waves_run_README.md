## Реальные таблицы FXREV (найдены и извлечены)

Машина FX-REV (`P:$14538E-$145931`) внутри своего кода содержит **две таблицы
коэффициентов по 128 записей × 3 слова**, индексируемых параметрами DEC и DAMP.
Загрузка указателя — трюк с аккумулятором: `clr a; move #>base,a0; maci #3,x0,a` →
`a0 = base + 3*(param>>17)`. Паддинг из 6 нулевых слов (`P:$1457AC`) в конце
DEC-таблицы существует, чтобы чтение 5 слов записи №127 не выходило за границы.

| Таблица | Адрес | Параметр | Смещение в voice state | Значения (Q1.23) |
|---|---|---|---|---|
| **DEC** | `P:$14562C` (384 сл.) | DEC (param 0) | `V+$4` | запись 0: +0.249/+0.271/+0.348 → запись 127: +0.664/+0.669/+0.690 (возрастает) |
| **DAMP** | `P:$1457B2` (384 сл.) | DAMP (param 1) | `V+$5` | запись 0: +0.9997 (без демпфирования) → запись 96: +0.041/+0.053/+0.114 (убывает) |

Согласование с дефолтами (`DEC=0x40=64`, `DAMP=0x02=2`): гребёнки при DAMP=2 получают
коэффициенты 0.935–0.956 (длинный хвост ✓), фильтр-секция при DEC=64 — биквад-набор
0.512/0.525/0.567 ✓.

**Маппинг параметров `param[i] → V+$4+i` верифицирован независимо** на FM-STAT:
TONE (параметр 6) читается с `V+$A` и индексирует LP-таблицу `$144AC7` (`asr #16`).

## Карта вейвтейблов DPRO-WAVE (вместо фантомного `P:$11B451`)

Код машины (P:$14742D-38): указатель = `P:$101D7B + WAVE × $1000` — **64 слота по
4096 слов** в диапазоне `P:$101D7B…P:$141D7A`.

- **Прошивка грузит первые ~17.5 слота** (`P:$101D7B-$1134C3`, 71 497 слов, извлечены
  как `dpro_wave_00…17_partial`) — это factory-вейвформы, предзагружаемые при старте.
- **Зазор `P:$1134C4-$13FFFF` = 100% нули** (проверено по всему диапазону) — пустые
  слоты 18–63, заполняемые ColdFire по требованию из FLASH-банка вейвформ
  (BIN `0x100000-$15FEFE`, 64 вейвформы с шагом $3000 байт = $1000 слов — та же сетка!)
  или пользовательскими данными.
- Флэш-банк и DSP-область — одна и та же сетка слотов: `WTRI@0x102FF8` (idx 2),
  `RSQR@0x105FF0` (idx 4), `DSAW@0x1077EC` (idx 5), `ESYN@0x1107D4` (idx 11) и т.д.

## SID wavetable (`P:$140800`)

Область `P:$140800-$1417FF` (4096 слов, X/Y/P-алиасинг). Машина SID читает её как
`x:(r1+n1)` и `y:(r5+n5)` (стерео-фазы). Factory-содержимое из blk3 (запись №2):
884 non-zero слова — маркеры-значения (`400000`, `800000`, `9F0000`…) на
логарифмически расположенных позициях (шаг 64→32→16→8) — это заводские
кроссфейд-метки вейвтейбла. Извлечено: `SID_wavetable_area_140800_factory` (439 nz),
`SID_wavetable_area_141000_factory` (445 nz). Остальное — нули (пользовательские
данные заполняются при редактировании на устройстве).

## blk4 — заводской контент (уточнение итерации 4)

Поток @BIN `0x79BB2` депакается (семантика noEOF) ровно в **1 048 448 байт**.
Структура: блоки по **$574 байт**, первый блок @ +$28, в начале блока — ASCII-имя
заводского паттерна: `SUPERWAVES` (+$28), `MACHINE` (+$856), `PULSES` (+$B10),
`IGOTGAME` (+$DCA), `SIXSIDS` (+$1084), `WAVEMIX` (+$133E), `TRENCHED` (+$15F8),
`KYSS FM` (+$18B2)… Полный разбор полей блока — задача итерации 6.

## Верификация цепочки (независимая)

1. `coldfire_main.bin` ре-депакнут из BIN @0x4008 — **бит-в-бит** совпадает с репо.
2. blk3 (поток @0x30429) депакнут до 336 945 Б, распарсен **без ресинхронизаций**:
   133 P-записи, 111 912 слов (формат записи: `[cmd LE24][addr LE24][count LE24][data LE24×count]`, JMP = 6 байт).
3. Реконструкция P-образа из blk3 vs `dsp1_pmem.bin`: **0 расхождений** на 111 912 слов
   (карта образа: P:addr → offset addr×3; данные в потоке — LE24, в образе — BE24).
4. Зазор `P:$1134C4-$13FFFF`: 0 non-zero слов и в blk3, и в образе.

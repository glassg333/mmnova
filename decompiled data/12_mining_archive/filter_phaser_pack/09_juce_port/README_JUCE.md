# Dual-фильтр Monomachine для JUCE — готовый порт

Папка `09_juce_port/` — выжимка пака для практической интеграции: заголовки
без зависимостей (только C++17), таблицы прошивки внутри, тесты против
бит-точного эмулятора в комплекте.

## Структура

```
09_juce_port/
├── Source/
│   ├── mnm_tables.h            ВСЕ таблицы фильтра/энвелопа (constexpr, образ DSP)
```

## Быстрый старт (3 шага)

1. Скопируйте `Source/` в свой проект и подключите `MnmFilterPluginExample.h`
   (или перенесите содержимое в свой процессор).
2. В `processBlock` режьте буфер на кадры по 16 сэмплов и зовите
   `voice.process(io, 16)` — пример уже в файле.
3. MIDI: note-on/off → `voice.noteOn()/noteOff()`, all-sound-off → `kill()`.

Параметры — ровно ручки машины (0..127): `BASE WDTH HPQ LPQ` + AMP
`ATK HOLD DEC REL VOL PAN`. Внутри они становятся словами Q23 (`knob<<16`) —
та же конвенция, что у CPU оригинала (BASE=64 даёт средний срез, idx=599 —
совпадает с железом).

## Ответы на главные вопросы (все — доказательства, не догадки)

**«Там base, width и две Q, да?»** — Да. Страница голоса Y[P+$10..$13]:
BASE (срез), WDTH (ширина между точками пары — то самое «двойное»), HPQ и
LPQ — ДВА РАЗДЕЛЬНЫХ резонанса. Индексация таблиц доказана прогонами:
HPQ/LPQ входят в таблицы напрямую значением ручки (64→64, 127→127).

**«Энвелоуп фильтра живёт в AMP-env?»** — Нет. У фильтра НЕТ энвелопа —
бит-точное доказательство в `08_env_verdict/` (кольцо коэффициентов и банк
тапов не зависят ни от каких env-ячеек; «FILT ATK/DEC/BOFS/WOFS» страницы —
на деле параметры delay-модуляции трека). Но с AMP-env фильтр связан двумя
доказанными нитями:
1. УРОВЕНЬ AMP-env = по-сэмпловый гейн В РЕЗОНАНСНОЙ секции
   (P:$0904–$0910: |level|·VOL²·pan, де-зиппер ≈3/32, внутриблочный рамп);
2. ФАЗА AMP-env (X[P+$D8]) гейтит ОС интегратора delay-модуляции:
   KILL (фаза 4) → fb = 0 (P:$0ABF–$0AC4, листинг снят и сверен).
Движение среза на реальной машине делает ColdFire (LFO/мод-матрица), пишущий
слова BASE/WDTH/HPQ/LPQ между кадрами. В плагине то же самое — просто
обновляйте параметры чаще (см. `setFilterWords`).

**«Дилей и эффекты ни при чём, это роутинг?»** — Роутинг да (CPU-side), но
ячейки P+$14–$17, исторически подписанные «FILT ATK/DEC», принадлежат
именно delay-тракту — их слышимый эффект накапливается через интегратор
делэя (BOFS=127 → ×0.08 энергии, WOFS=127 → ×3.8). Сам фильтр от них чист.

## Что доказано, а что реконструировано (честная таблица)

| Узел | Статус |
|---|---|
| Кольцо коэффициентов (BASE/WDTH → ring) | бит-в-бит (±2 LSB ~ −130 дБ) |
| eps-путь (DIV x24, целочисленный) | бит-в-бит 9/9 конфигураций |
| Каскад 1 — рекурсия func_000340 | бит-в-бит (iter.14, svf_recursion_proven.md) |
| Выход каскада = шина a_old | доказано корреляцией с синусом |
| Таблицы coeff2/div1/div2/width1/width2 | 1:1 из образа |
| HPQ→hpqDamp/hpqFb, LPQ→lpqFb, индексация = ручка | бит-в-бит |
| Формула тапа `x_mid + frac·(x_mid−x_prev)` | бит-в-бит (func_000397) |
| Разбег тапов: HPQ=0 → шаг 1.0; HPQ=127 → шаг 15.8828 | бит-в-бит (крайние точки) |
| Промежуточный разбег тапов (линейная калибровка) | [РЕКОНСТР.] |
| Топология обратной связи резонатора | [РЕКОНСТР.] (рекурсии доказаны, карта ячеек ОС — нет) |

## Тесты

```bash
cd tests
g++ -std=c++17 -O2 -I../Source test_mnm_filter.cpp -o test && ./test
```

Проверяет: кольцо против 9 якорей эмулятора, стабильность каскада-1 (400
кадров), стабильность полного узла при максимальном резонансе (600 кадров),
временные карты энвелопа (ATK=64 → 420 кадров; DEC=0 → 62 кадра до −60 дБ;
KILL → 68 кадров). Все — зелёные.

## Частота дискретизации

Родная сетка машины — 44100 Гц, кадр = 16 сэмплов (0.3629 мс). На 48k/96k
порт работает корректно (структура и таблицы не зависят от fs), но
временнЫе константы фильтра масштабируются с fs естественно, а кадры
энвелопа остаются «в 16 сэмплах» — при желании бит-точного времени на 48k
пересчитывайте кадры как `round(16 * fs / 44100)`.

## ИТЕРАЦИЯ 17 — новая информация для порта (10_manual_crosscheck/)

FLT-страница (официальная CC-карта): BAS/WDTH/HPQ/LPQ/**ATK/DEC/BOFS/WOFS**
(CC 72–79 → страница $10–$17). В порт добавляемые параметры стадии 2:

- `fltAtk` ($14), `fltDec` ($15) — AD-энвелопа резонаторной стадии (те же кривые
  P_141800/P_141880, что у AMP-env); общий триггер с AMP-env; KILL-гейт при
  фазе 4 AMP-env (см. mnm_amp_env.h — фаза уже экспортирована).
- `bofs` ($16) — глубина env→base, `wofs` ($17) — глубина env→width;
  цели рамп: base_offset = curve_144AC7[bofs]·env, width_offset =
  curve_144AC7[bofs+wofs]·env (кривая $144AC7 = 258 слов, есть в tables/).
- Носитель: банк коэффициентов фидбека X:$40–$5E (измерено: WOFS=127 → ≈+0.573,
  BOFS=127 → 0.000). Точная формула банка — следующий шаг (what_is_missing §1).

До порта стадии 2 текущий DualFilter = точная стадия 1 (статический SVF-каскад) —
звучит «суше» оригинала при ненулевых ATK/DEC/BOFS/WOFS.

## ИТЕРАЦИЯ 18 — стадия 2 (env-резонатор): mnm_filter_stage2.h

Добавлено:
- `Source/mnm_filter_stage2.h` — бит-точный порт стадии 2 (класс
  `mnm::FilterStage2`): три ступени вращения (L1/L2/L3) + блок глубины (DP).
  Верифицирован слово-в-слово против эмулятора (384/384 проверок,
  `../11_stage2_model/verify_report.txt`).
- `Source/mnm_tables_stage2.h` — кривые `kCurve144AC7[258]` (углы L1/L2) и
  `kCurve144B48[128]` (временная рампа L3) в raw 24-бит словах.

Использование:

```cpp
mnm::FilterStage2 st2;
// раз в аудио-блок (как в ядре — один вызов на кадр):
st2.process(atk, dec, bofs, wofs, amp_phase);
// atk/dec/bofs/wofs — FLT-страница P+$14..$17 (raw 24-bit слова, knob<<16)
// amp_phase — фаза AMP-энвелопа X:P+$D8 (4 = KILL: DEC-часть обнуляется)
// после вызова: st2.st.coeff_a/coeff_b — банки коэффициентов X:$51-$61 /
// X:$40-$50, которые в прошивке управляют гребёнкой тапов (func_000397)
```

Статус порта фильтра: стадия 1 (SVF-каскад) — бит-точный порт готов
(`mnm_dual_filter.h`); стадия 2 — формула ENV→коэффициенты доказана и
портирована, хвост ($0AD1–$0B4C: интеграция L:$90-$A0 + сканер тапов) —
итерация 19. После хвоста фильтр портируется целиком бит-в-бит.

## ИТЕРАЦИЯ 23 — DIST: mnm_dist.h (драйв-энвелоп + слот обработчика)

Добавлено `Source/mnm_dist.h` — элемент DIST по уровню инструкций:

- `mnm::MonoMachineDistDrive` — драйв-энвелоп ядра (P:$04FF–$0536), бит-точный:
  атака `kEnvAtk[DIST]` (шаги сверены бит-в-бит с эмулятором для
  DIST ∈ {16,32,64,96,127}), 24-битный wrap в −1.0, HOLD = 1 кадр с падением
  в DEC в том же кадре (`bra $052B`), DEC `kDistRel[idx]` с клампом
  `clr b ifmi`, ретриг через y:(P+$20). Уровень после wrap'а отрицательный —
  так в железе (замер: 0.5 → −1.0 → 0).
- `mnm::timbreIndex()` — формула индекса таблицы тембра $143546
  ($0537–$0556) со всеми a1-срезами аккумулятора: при нулевом param4 индекс
  = −$80 − drive·1792 (отрицательный!) — сверено с эмулятором бит-в-бит
  (−431 = 0xFFFE51, кадр 70, DIST=64).
- `mnm::MonoMachineDistSlot` — контракт слота per-machine обработчика
  (X:(page+$0C)): диспетч после резонанса / до стадии-2, эпилог jmp $000981,
  фейд-ин 64 кадра, CONF-вооружение каждый кадр.
- Таблица `kDistRel[128]` (P:$141A00) — шаги линейного спада драйва.

Тесты: `tests/` + `scripts/test_mnm_dist.cpp` — 12/12 зелёные против
`../15_dist_element/probe23d_vectors.json`.

```cpp
mnm::MonoMachineDistDrive drive;
mnm::MonoMachineDistDrive::Params dp; dp.dist = 64; dp.vol = 127;
// раз в кадр (16 сэмплов):
int32_t lvl = drive.tickRaw(dp);                 // raw Q1.23 (может < 0!)
int idx  = mnm::timbreIndex(lvl, param4, panTerm); // индекс в $143546
// затем: перекрёстный фейд tbl / (1−tbl)·0.5 из таблицы тембра,
// и при вооружённом слоте — вызов distSlot.run() между фильтром и стадией-2
```

Полная цепочка JUCE-элементов пака теперь: mnm_dual_filter.h (каскад-1) →
mnm_filter_stage2.h (стадия-2, бит-точная) → mnm_amp_env.h (AMP-энвелоп) →
mnm_dist.h (DIST: драйв+слот) → mnm_tables*.h (таблицы прошивки).

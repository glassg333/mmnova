# Стадия 2 dual-фильтра MonoMachine — ПОЛНАЯ МОДЕЛЬ (итерация 18)

Дата: 2026-09-21. Статус: **ВСЕ 4 БЛОКА ВЕРИФИЦИРОВАНЫ БИТ-В-БИТ** (384/384
проверок: 12 конфигураций ATK/DEC/BOFS/WOFS × 8 кадров × 4 блока, см.
`verify_report.txt`). Модель: `exp18_model.py`, сбор данных: `exp18_fdn.py`.

## Что такое стадия 2

Стадия 1 (P:$04A8–$06C0) — статический SVF-каскад (env-free, доказано в
итерациях 15/17). Стадия 2 (P:$0A5D–$0B4C) — **env-управляемый резонатор**,
который и создаёт «двойной фильтр с энвелопами» из мануала. Она состоит из
трёх ступеней вращения цепей и блока масштабирования глубины:

```
   audio bus X:$00-$0F ──────────────┐
   bank X:$20-$2F ──► L2 ◄── L1 ◄─ X:$30-$3F (угол c1 = K[BOFS])
   bank X:$20-$2F ◄──┘   │   └── угол c2 = K[WOFS+BOFS]
                         ▼
   DP: coeff = 2·DEC·(L2 out) + depth·(L3 out),  depth = 4·(ATK−0.5)²
   ▼
   banks X:$41-$4F (b-ветвь) / X:$52-$60 (a-ветвь)  →  гребёнка тапов
   func_000397 ($0B13) + интеграция в L:$90-$A0 ($0AD1-$0B0B)
```

Каждая ступень вращения — это ДВЕ 16-ячеечные рекурсивные цепи первого порядка
(a-цепь и b-цепь), работающие по формуле (L1):

```
s[i+1] = s[i] − m[i−1]·β − B1(s[i])·c + m[i]·β        (L1, знаки: −m·β, −B1·c, +m·β)
s[i+1] = s[i] + w[i]·c − B1(s[i])·c                   (L2/L3, без wrap-члена)
```

где `B1(x)` — квантование аккумулятора до 24 бит (старшая часть A1),
`m[i]` — входные ячейки, `w[i]` — выходы предыдущей ступени.
Цепь L1 — с **wrap-замыканием**: m[−1] = последняя ячейка банка прошлого
кадра (кольцевой конвейер через стейт P+$D3).

## Углы вращения (параметры → характер звука)

| Ступень | Адрес   | Угол                                   | Кривая      | Роль |
|---------|---------|----------------------------------------|-------------|------|
| L1      | $0A5D   | c1 = X:$144AC7[BOFS]                   | $144AC7[258]| базовый тембр (BAS env offset) |
| L2      | $0A84   | c2 = X:$144AC7[WOFS+BOFS]              | $144AC7[258]| ширина («LP — раб, следует за HP» из мануала — в коде!) |
| L3      | $0A9D   | c3 = X:$144B48[стейт P+$CF >> 17]      | $144B48     | временная рампа (движение резонанса) |

β = 1.0 − c1/2 (в коде: `asr b; add #>$800000; neg` — где $800000 = −1.0).

## Энвелоп → коэффициенты (блок DP, $0AB7–$0AD0)

```
depth = mpy(2·|ATK − 0.5|, 2·|ATK − 0.5|)      ; ATK = P+$14 (0..1)
a[i]   = 2·DEC·Y:$20+2i + depth·L3out[2i]      ; DEC = P+$15
b[i]   = 2·DEC·Y:$21+2i + depth·L3out[2i+1]
X:$51      = depth (скаляр глубины)
X:$52-$60  = a[0..14]        X:$61 = a[15]
X:$40      = фаза AMP-env (утечка регистра b, значение 0..5)
X:$41-$4F  = b[0..14]        X:$50 = b[15]
```

**KILL-гейт**: при фазе AMP-env 4 (X:P+$D8 == 4) множитель DEC обнуляется
(`move #$0,y0` на $0AC4) — коэффициенты распадаются, резонанс глохнет.
Это вторая ниточка «энвелоп живёт в тракте» (первая — гейн в резонансной
секции, итерация 16).

Форма энвелопа: глубина = (ATK-зависимая амплитуда) × (DEC-рампа через
кривую $144B48 в L3) — т.е. FLT ATK задаёт размах, FLT DEC — скорость через
временную рампу c3. Триггер общий с AMP-env (та же машина, фаза 4 = KILL).

## Состояния (стейты стадии 2 на странице голоса, r7 = $55C)

| Ячейка  | Назначение |
|---------|-----------|
| P+$D3   | wrap-состояние L1 (X/Y-пара: последние ячейки X:$3F/X:$2F прошлого кадра) |
| P+$D4   | стейт a/b-цепей L1 (X/Y-пара) — «стейты P+$D4» из итерации 17 |
| P+$D5   | стейт a/b-цепей L2 |
| P+$CC   | стейт a/b-цепей L3 |
| P+$CF   | фазовый аккумулятор временной рампы L3 (X/Y-пара, >>17 → индекс $144B48) |
| P+$D8   | фаза AMP-env (источник KILL-гейта; утечка в X:$40) |

## Промежуточные банки

- L1 → Y:$62-$81 (чередование: чётные = a-цепь, нечётные = b-цепь)
- L2 → Y:$20-$3F (то же чередование) — вход DP-блока (DEC-часть)
- L3 → Y:$62-$81 (переписывает) — вход DP-блока (depth-часть)

## Метод верификации

1. `exp18_fdn.py` — прогон бит-точного эмулятора (харнес EnvCase, трек 0,
   машина SIN) с брейкпоинтами на границах блоков ($0A5D/$0A84/$0A9D/$0AB7/
   $0AD1/$0B4C); снапшоты всех банков/стейтов — `exp18_fdn_snap.json` (gz).
2. `exp18_model.py` — закрытая форма на целочисленной арифметике DSP56300
   (56-бит аккумуляторы, pre-ALU stores, квантование B1) сравнивается
   слово-в-слово с эмулятором.
3. Ключевые ловли, без которых модель не сходится:
   - store параллельных move = **pre-ALU** значение аккумулятора;
   - r7 в контексте кадра = **$55C** (не $4FA из контекста run_kernel!);
   - `add #>$800000` = прибавление **−1.0** (а не 0.5);
   - r1/r4 инкрементируются ДВАЖДЫ за итерацию → ветви потребляют
     чередующиеся ячейки (чётные/нечётные);
   - регистр b переиспользуется под чтение фазы ($0AC0) → утечка фазы в X:$40;
   - KILL-гейт обнуляет только DEC-множитель, depth-часть остаётся.

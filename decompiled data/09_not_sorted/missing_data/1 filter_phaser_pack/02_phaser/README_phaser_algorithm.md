# FX-PHASER Monomachine — реконструкция алгоритма по машинному коду DSP56300

OS 1.32B, DSP1. Машина 19 DSP-диспетчера (ColdFire m18 «FX-PHASER»).
init = P:$144E81, conf = P:$144E99, proc = P:$144E9A, код 437 слов до $145035.
Полный дизассембл: disasm_phaser_machine_P144E81-15035.txt.

## Ключевой вывод

Фейзер Monomachine — это **модулируемая линия задержки** (per-track буфер $2000 слов
в X/Y внешней памяти с базы $114000 + track·$2000, P:$144E81–$144E88), по которой
читаются **две аллпасс-ступени** с 16-табличной интерполяцией, а LFO — **квадратурный
sin/cos из таблиц 8192 слов** ($14A000/$14A800 — те же, что у хоруса). «Аллпасс-коэффициент»
ступени не берётся из отдельной таблицы коэффициентов — он получается сглаживанием
параметра DEP (однополюсник) и геометрией чтения линии. Таблицы «PHASER_stage0–3» из
прошлых итераций к фейзеру НЕ относятся (см. 04_evidence/corrections_to_previous_mining.md).

## Параметры (страница голоса, оффсеты $04–$0B; дескриптор m18: CNTR DEP SPD MIX FB WID --- INP)

| Параметр | Оффсет | Использование в коде |
|---|---|---|
| CNTR | $04 | P:$144EFB: `a = CNTR·$FFFC03 − 3` → приращение 48-бит указателя чтения (x:(r6+$1d)); т.е. CNTR задаёт базовую задержку/частоту; тот же член участвует в сглаживании P:$144F04–$144F08 |
| DEP | $05 | P:$144F0C–$144F10: однополюсное сглаживание состояния $22: `st += (DEP−st)·2·$FD70A4` → глубина модуляции чтения |
| SPD | $06 | P:$144EB4: `x0 = SPD²`, далее `×$9566` (P:$144EB9) → приращение фазы LFO за блок (SPD входит В КВАДРАТЕ) |
| MIX | $07 | P:$145027: `a = $7FFFFF − MIX`; out = dry·($7FFFFF−MIX) + wet·MIX (та же формула, что у хоруса $1477CF) |
| FB | $08 | P:$144FBE: `a = FB − $400000` (bipolar ±0.5) → коэффициент обратной связи лестницы (масштаб ×$410410·4·$7EB852, P:$144FC2–$144FC8) |
| WID | $09 | P:$144EC9: однополюсник $24: `st += (WID−st)·$28F5C` → амплитуда LFO; амплитуда = sin-таблица: `r0 = st·$800>>24; a = sine8k[r0], b = cos8k[r0]` (P:$144ED1–$144ED6) |
| INP | $0B | P:$144EA6: `a = INP²` затем `×4` (asl #2) — входной масштаб input·INP²·4 (идентично хорусу) |

## Поток сигнала (16 сэмплов = блок: 8 L + 8 R)

```
[1] вход: in[i] = input·INP²·4 → Y:$00–$0F (P:$144EA5–$144EB3, r4=0, do #16)
[2] LFO (P:$144EB4–$144EE6):
      фаза 48-бит (x:(r6+$11)/x:(r6+$12)) += SPD²·$9566, накопление на 16 шагов
      с конвейерным переносом (mac −x1,x0,b / mac y0,x0,a) — per-sample фаза → X:$20–$2F/Y:$20–$2F
      амплитуда: WID → one-pole $24 → sine8k/cos8k[WID·$800>>24]
      per-sample рампа: prev + i·(Δsine·8), prev + i·(Δcos·8) → X:$E0–$EF/Y:$E0–$EF
[3] fade-in wet (P:$144E9C–$144EA4): первые 128 блоков wet=0, затем $80 (как хорус $14767D)
[4] аллпасс-лестница (P:$144F31–$144F3F): do #2 (ДВЕ ступени), состояние L:$1F (48-бит),
    чтение линии: фаза X:$20+i + рампа X:$E0+i, интерполяция по соседним словам буфера,
    смешение со ступенчатым коэффициентом (DEP-сглаженный $22),
    вычитание рампы: `add #$10; asr #4` — дробная позиция 4.4 фиксированной точки
[5] мостик сглаживания LSB (P:$144F42–$144F4B): lsr a / lsr b по 16 парам — дробная часть
    позиции (анти-зиппер)
[6] нормировка чтения (P:$144F4E–$144F65): возведение в квадрат (mpy y0,y0) и MAC-норма
    по 16 позициям → компенсация громкости чтения из линии (X:$9E–/X:$A0–)
[7] интерполяционное ядро (P:$144F70–$144FA2): таблица констант на r2 (m2=stride 10):
      [$EAAAAB (−1/6), $40, $D55555 (−1/3), $40, $80, $C0, $C0, $40, $7FFFFF (1.0), $155555 (1/6)]
    — 2 набора по 5 констант = кубическая интерполяция позиции чтения (4 точки + смещения
    0.5/1.0/1.5); do #$20 (32 = 16 поз. × 2 канала) с макросмешением и вычитанием $80-смещения
[8] запись в линию задержки (P:$144FA4–$144FE2): r0/r1 = база, база+$1000; m0/m1/m2/m3=$FFF
    (буфер $1000=$4096?? нет: маска $FFF на 4096-словном кольце, но база 2 половины по $1000
    — двойная линия L/R); чтение x:(r2)+ по позиции (48-бит фаза x:(r6+$1d)>>1), mac с y0/y1
    (FB-гейны), выход → x:(r0)+ (кольцо, маска $FFF)
[9] чтение ступеней (P:$144FF8–$145006): do #2 × do #10: 4-точечная кубическая интерполяция
    (x0·4 + mac ×3, константы из r5=$20-таблицы) по позиции n0 = x:(r5)+ — финальный
    аллпасс-выход каждой ступени → X:$E0–/Y:$E0– (r3)
[10] выходной микс (P:$14500A–$145035):
      wet·y1($5A8241 = 0.7071 − компенсация) − x0·$5A8241 (сглаженный dry-гейн $20-wet),
      do #10 × 2: out = dry·(1−MIX) + wet·MIX, стерео-перестановка для WID-ширины
      (y:(r5)+/y:(r4)+ перекрёстное чтение), запись a/b → y:(r7)+ (выходной буфер трека)
```

## Стерео и «двойность»

- Везде двойные аккумуляторы a/b (L/R) — обработка каналов параллельная.
- Две аллпасс-ступени (do #2) дают классические 2 нота-фазы; глубокий ноль регулируется
  FB (bipolar ±) — при FB>0.5 фидбек входит в насыщение (sr-бит #14 bset/bclr вокруг
  макросов — 24-бит сатурация, P:$144EC0/$144EC5).
- Стерео-ширина: перекрёстные чтения в миксе (P:$14502F–$145034) — канал получает
  wet противоположного канала с весом WID (таблица 10 констант, шаг $40/$80/$C0).

## Числа для проверки

- буфер: $2000 = 8192 слов на трек на канал (2×$1000 колец L/R);
  максимальная задержка при CNTR=127: позиция растёт на ~127·1021/2^23 ≈ 0.0155 слова/блок
  → в кольце $1000 навигация ведётся «навстречу» — глубина модуляции ~0.25 слова на блок;
- fade-in 128 блоков = 128·16/44100 ≈ 46.4 мс (совпадает с хорусом);
- LFO: SPD=0 → фаза стоит; SPD=127 → 127²·0.0072917 ≈ 117.6 (фазовых единиц/блок 2^23)
  → период ≈ 2^23/117.6 блоков ≈ 71256 блоков ≈ 25.9 с (медленный «тембральный» фейзер —
  согласуется с характером Monomachine PHS на максимальной скорости без синхронизации).

## Что доказано / что реконструировано

ДОКАЗАНО инструкциями: все обращения к параметрам и их арифметика; структура LFO
(квадратура 8K-таблиц, однополюсники, per-sample рампы); 2 ступени лестницы; кубическое
ядро с перечисленными весами; кольцевые буферы и маски $FFF; формулы MIX и fade-in;
двойные кольца L/R и перекрёстный микс.

РЕКОНСТРУКЦИЯ (высокая уверенность): точное распределение ролей X:$20-фаз vs X:$E0-рамп
внутри 16-табличного чтения (шаги [4]/[7] — взаимно согласованы, но полный конвейер
MAC-переносов 48-бит фазы требует пошаговой симуляции для бит-в-бит воспроизведения).

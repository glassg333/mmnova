# 15_dist_element — DIST: замеры итерации 23 и тест-векторы

Дата: 2026-09-22. Всё исполнено на бит-точном эмуляторе (`05_emulator/dsp_emu.py`,
трек-харнес `track_harness.py`), машина m14 SWAVE-ENS — её CONF вооружает
настоящий DIST-обработчик $145C48 каждый кадр.

## Три ловушки харнеса (исправлены; критично для будущих замеров)

1. **x:$2C3 → r5 → X:$FF**: ядро `$0140 move x:>$2c3,r5` → `$04F6 move r5,x:>$ff`.
   Если x:$2C3 = 0 (старый EnvCase обнулял x:$2C0–$2C9!), мастер-микш (T6,
   итер. 22) работает в ФИДБЕК-режиме и выход экспоненциально умирает за
   ~15 кадров. Фикс: `x:$2C3 = 0x200` (буфер вне X:$00–$1F). Подтверждает
   сноску итерации 22: в реальной машине X:$FF вне X:$00–$1F → чистая шина.
2. **X:(P+$0B) = EQG-делитель**: снимок xmem содержит мусор $FFFECF → тракт
   молчит. Фикс: `X:(P+$0B) = 64` (как в amp_env_measure).
3. **Бит 7 ячейки TRIG (y:(P+$28))** = флаг «машина сменилась» → INIT+CONF
   ($00E4 bcc). CONF вызывается ежекадрово ($00FB–$00FF), INIT — только при
   смене машины.

## Главные результаты (сводка)

- Атака драйва = tblA[$141800][DIST] **бит-в-бит**: DIST 16/32/64/96/127 →
  шаги 0x10CFEA/0x46A98/0x4E05/0x560/0x65 (DIST=0: 0x400000, wrap со 2-го кадра).
- Wrap → −1.0, HOLD 1 кадр с **fallthrough в DEC** (`bra $052B`), кламп
  `clr b ifmi` → 0.5 → −1.0 → 0.
- Тимбр-индекс: a1-срезы переворачивают знак (|0.75| → a1 −0.5 → кв. 0.25 →
  asl#2 → a1 −1.0) → idx = −$80 − drive·1792 при нулевом param4.
  Бит-в-бит: drive=1418083 → −431 = 0xFFFE51 (замер x:(P+$D9), кадр 70).
- Выход харнеса в probe23b/c затухал из-за ловушки №1, поэтому аудио-векторы
  сняты в probe23d с фиксом; ENV/индексные векторы от среды не зависят.

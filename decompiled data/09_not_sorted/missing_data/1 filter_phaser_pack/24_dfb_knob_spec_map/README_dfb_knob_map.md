# DFB-вердикт + карта «ручка→ячейка» + машинерия назначения слотов (итерация 30)

**Закрывает:** (1) путь DFB (P+$1D) — последнюю не найденную ячейку эха;
(2) статус «значения спецификаций ячеек — рантайм ОС» из итераций 28–29 —
теперь с полной машинерией записи и честным вердиктом, где живут значения;
(3) извлечение полных квадратур фейзера m18 ($14A000/$14A800) —
`22_phaser_lfo/tables_14A000_14A800/`.

## 1. DFB (P+$1D): ДОКАЗАТЕЛЬНО НЕ ЧИТАЕТСЯ DSP

Полный скан листинга всей P-памяти (`decoder_v2/code_full.asm`, dsp1_pmem.bin,
11 756 строк; ядро `$000400–$000CB1` — `kernel_full.txt`) по всем трём
конвенциям адресации страницы:

| Конвенция | Кто пользуется | Форма доступа к P+$1D | Результат скана |
|---|---|---|---|
| Голосовая цепь ядра, r6 = база страницы | EFX-конверт $04A8, микши T5/T6, PROC-хвост | `y:(r6+$1d)` / `x:(r6+$1d)` | **отсутствует** (набор: $00–$0F, $18–$1B, $1F, $20, $21, $23, $25, $28, $2A) |
| Глайндвижок $000262, r6 = страница+$28 | глайн A/B, позиция | `y:(r6-$0b)` / `x:(r6-$0b)` | **отсутствует** (используются −$0C = DSND, −$0A = DBAS, −$06, −$02, −$21…) |
| PROC-машины, r6 = страница+$28 | m13/m14/m15/m17/m18 | `y:(r6+$1d)` встречается, НО это страница+$45 — машин-локальный скретч за пределами 51-словной страницы | не ячейка страницы |

Доказательство «машинного» статуса r6+$1d на примере m18 (фейзер):
`$14507A–$14507D` читают `y:(r6+$1c)`/`y:(r6+$1d)` и пишут туда свежие
cos/sin из таблиц `$14A800`/`$14A000` — это квадрура-стейт LFO
(старые/новые sin-cos, из них считаются дельты вращателя $14507E–$14507F),
а не ячейка страницы эффектов.

Позитивные чтения страницы голосовой цепью (полный список,
`kernel_full.txt`): `y:(r6+$00…$0F)` (AMP/FLT/машинные параметры),
`$18` EQF, `$19` EQG, `$1A` SRR, `$1B` DTIM (EFX-конверт $04B4/$04CC/
$04C9/$04E5), `$1F` DWID (рампа микша $0B1E), `$20/$21` (флаги конверта),
`$23/$25/$28` (служебные), `$2A` (множитель длины эха, $099D).
DSND `$1C` / DBAS `$1E` / цель `$22` / смещение `$26` / цель B `$29` /
индекс B `$07` читает глайд-движок (итерация 28).

**Вердикт:** DFB — единственная ручка эха с нулём чтений на DSP.
Применение обратной связи — хост-сторона (ColdFire-микш эхо-шины),
что согласуется с диаграммой `17_delay_echo/` («возврат хостом в кольцо»).
Строка «DFB остаётся честно открытым» в `23_dsnd_dtim_routing/` заменена
на этот вердикт.

## 2. Карта «ручка→ячейка»: машинерия назначения ($24272E) — расшифровка

В итерациях 28–29 установлено: обработчик `$242058` копирует тройки байтов
из массивов `$7001FA` (группа) / `$700242` (смещение) / `$70028A` (третий
байт) и через роутер `$2403D4` превращает их в адреса ячеек; значения
массивов — рантайм-стейт. Здесь расшифрована ЕДИНСТВЕННАЯ функция,
пишущая эти массивы, и её вызыватели.

### 2.1 Функция назначения $24272E

```
вход (стек): p1 → d6 (селектор), p2 → a6 (track), p3, p4 → d4, p5 → d3,
             p6 → d5; клампы:
  d4 = max(0, min(p4, 8))     ; ГРУППА   (коды 0..8 → таблица $240400)
  d3 = max(0, min(p5, 7))     ; СМЕЩЕНИЕ (0..7 внутри группы)
  d5 = clamp(p6, 0, $40)      ; ТРЕТИЙ БАЙТ (обычно ≤ $40)
ветвление по флагу $2BFF12 — два зеркальных пути:
  путь A ($2427B4): $7001FA[a1] = d4; $700242[a1] = d3; $70028A[a1] = d5
                    + зеркала $2C01D2/$2C021A/$2C0262 (7-итерационный цикл,
                    шаг $C, база arg + 2·track)
  путь B ($242950+): те же массивы со смещением +4 (саб-банк
                    $7001FE/$700246/$70028E) + зеркала $2C01D8/$2C0220/$2C0268
затем на каждый из 7 треков: jsr $2403D4(track, группа, смещение) →
адрес ячейки → указатель глайда $1001508+t·$30 (путь A) / $1001514 (путь B);
хвост: jsr $23F8BA(idx) ×7 — перезапуск глайда назначенных ячеек.
```

### 2.2 Вызовители (полный список — их всего 8)

`jsr $24272E.l` по адресам: `$21240C`, `$212456`, `$2125E6`, `$212702`,
`$2127FE` (подсистема назначения $212xxx), `$212944`, `$214B26`, `$214F80`.
Прямых указателей (32-бит) на $2427B4/$242968 в ROM нет — это внутренние
метки ветвей функции $24272E (скан exp30_ptr_scan.py).

### 2.3 Применение записи: обработчик $242058 — точная механика

`$242058(bank, track)` — цикл d2 = 0..5 (6 итераций), a3 = `$70028A +
12·bank`, a2 = `$2C0262 + 12·track`, a4 = `$1001508 + $30·track`:

```
итерация d2 читает пары байтов (2·d2, 2·d2+1) из трёх массивов:
  third  = $70028A[12·bank + 2·d2 + {0,1}]
  group  = $7001FA[12·bank + 2·d2 + {0,1}]
  offset = $700242[12·bank + 2·d2 + {0,1}]
  → зеркала $2C0262/$2C021A/$2C01D2 обновляются синхронно
  → jsr $2403D4(track, group, offset) → адрес ячейки:
     чётный байт (2·d2)   → указатель глайда $1001508 + $30·track + 4·d2
     нечётный байт        → указатель глайда $1001508 + $30·track + $18 + 4·d2
```

Итого: запись «bank» = 12 байтов = 12 суб-слотов; чётные суб-слоты →
указатели 0–5, нечётные → 6–11 (12 указателей глайда на трек, шаг $30 —
совпадает с итерацией 28). Режимная ветка `$242146` (флаг-бит `$7001F9`
через `$242044`) дополнительно применяет суб-слоты 4–5 записи к флаговой
зоне `$1000948 + … + $BCC/$BE4`.

### 2.4 ВЕРДИКТ: значения спецификаций — данные пресета, не ROM

Цепочка доказательств:

1. Полный скан ссылок на регион `$7001F0–$7002D0` в ROM: все ссылки —
   обработчики `$2420xx–$242Exx`; ни одной записи констант из ROM.
2. Единственный писатель массивов — `$24272E` (+ его режимная ветка);
   значения приходят аргументами.
3. Вызовители $212xxx читают ТЕКУЩИЕ значения через геттер `$242BD0`
   (зеркала `$2C01D2/$2C021A/$2C0262`) и передают их же (или
   трансформированные: `addi.l #$ffffffc0` = −$40) обратно — это пути
   ПЕРЕНАЗНАЧЕНИЯ/сдвига слотов, не первоисточник.
4. Перезагрузчик `$21273C` + `$21268E`: по флагу `$26AF84` читает текущие
   назначения `$242BD0` в глобалы `$26AE40/$26AE70/$26AEA0` (12 лонгов × 3),
   затем ре-применяет `$24272E` для track = 0..5, slot = 0..1 (индекс
   ячейки = трек·4 + слот·$18). Источник первичных значений — глобалы
   `$26AF74…$26AF98` и `jsr $2015F4` (копирование 6 слов из структуры
   пресета) — данные пресета в RAM.

Следствие для порта: карта «ручка UI → ячейка страницы» для
реконструкции эффекта — это ЛИТЕРАЛЬНАЯ раскладка страницы (для эха:
`$18 EQF, $19 EQG, $1A SRR, $1B DTIM, $1C DSND, $1D DFB, $1E DBAS,
$1F DWID, $2A — хост`), подтверждённая чтениями ядра; динамическая
машинерия $24272E — это мод-маршрутизация ОС поверх страниц, её
конкретные назначения зависят от пресета и извлекаются только из
рантайма/файлов пресетов, из кода прошивки они не выводятся.

## 3. Квадратуры фейзера m18: $14A000/$14A800 — извлечены полностью

Пак содержал только 8-словные «головы» (итерация 1). Найдены полные
8192-словные образы в репозитории (три источника, побитно идентичны):

- `missing_data/recovered/X_14A000_sine_table_8K.bin` (+ `final_recovery/`,
  `4 iteracy/…_math.bin`)
- `missing_data/recovered/X_14A800_width_table_chorus_B.bin` (те же копии)

Верификация (exp30_extract_quads.py → `exp30_quad_verify.json`):
- head[0..7] совпадает с `01_filter/tables/P_14A000_sine8k_head.bin` (итер. 1);
- `$14A000` = sin, `$14A800` = cos: max |таблица − sin/cos(i/8192·2π)| =
  1.78e-7 ≈ 1.5 LSB (24-бит дробь);
- sin max = $7FFFFF при idx 2048, min = $800001 при idx 6144; cos[0] = $7FFFFF;
- адресация в коде — X-память: `x:(r0+$14a000),a` / `x:(r0+$14a800),b`
  ($144ED4/$144ED6 — WID-стереопуть; $145076/$145078 — квадрура LFO m18).

Файлы: `22_phaser_lfo/tables_14A000_14A800/X_14A000_sine8k_full.bin/.txt`,
`X_14A800_cos8k_full.bin/.txt` (3 байта/слово, big-endian, signed 24-bit).

## 4. Что это меняет для порта

- Фильтр/фейзер/эхо: без изменений — все сигнальные тракты уже закрыты
  (итерации 1–25) и подтверждены бит-точными моделями.
- Эхо: DFB убирается из списка «неясных» — порт берёт feedback как
  хост-параметр (кольцо + обратная запись на стороне хоста).
- Мод-слоты ОС: при желании портировать мод-маршрутизацию — взять
  машинерию §2 (клампы, роутер $2403D4, глайд $1001508) и подставлять
  назначения из данных пресета.

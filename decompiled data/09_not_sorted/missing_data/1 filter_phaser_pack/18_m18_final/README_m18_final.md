## Алгоритм (один 16-сэмпловый блок, два прохода = чёт/нечёт = L/R)

1. **Входной гейн**: `q[k] = 4·INP²·in[k]` → банки Y:$00-$0F (чёт) / Y:$10-$1F (нечёт).
2. **LFO-осциллятор**: 16 поворотов (a,b) с шагом `SPD²·$9566`; рекуррентность
   **leapfrog с задержкой**: `b += −a1(a_{k−1})·step` (x1 защёлкивает PRE-ALU a —
   отставание на итерацию!), `a += a1(b_k)·step`. Носитель: X:$20-$2F = b-цепь,
   Y:$20-$2F = a-цепь. Фаза-стейт: x:$11/$12, старт `move #$80,x0` = **$000080**
   (не $800000!).
3. **WID**: one-pole (k=$28F5C ≈ 1/50) → индекс `s_wid·$800>>24` (0..2047) →
   таблицы $14A000 (sin) / $14A800 (cos = sin+2048 слов, четверть периода).
   16-шаговые рампы: X:$E0-$EF (cos) / Y:$E0-$EF (sin). **Общий r0**:
   `y:(r0)` без инкремента + `x:(r0)+` с инкрементом → оба банка ходят
   синхронно по одному адресу. Разбег рампы = Δтаблицы·16>>24 ≈ саб-LSB —
   фактически sample-and-hold.
4. **CNTR/DEP**: 48-битные one-poles (k=$28F5C); `c = 2·(s18 − 0.5)` —
   статический сдвиг коэффициента; `v = s19·(−(|c|+1))` — форма глубины;
   **V-рампа перезаписывает X:$E0-$EF** (тот же адрес, что квад-рампа cos!):
   `V[k] = v_prev + k·Δv/16`.
5. **Боковые полосы**: `a_bank[k] = cosr[k]·s[k] + sinr[k]·qc[k]`,
   `b_bank[k] = cosr[k]·s[k] − sinr[k]·qc[k]` (отрицание — с заворотом!).
6. **Банк коэффициентов**: `mod[i] = (a|b)_bank[i]·V[i%16] + c` (X:$00-$1F).
7. **FB**: `s13 = 2·(FB−0.5)`; рампа `fb[k] = s13_prev + k·(s13−s13_prev)/16`.
8. **ГЛАВНОЕ — лестница**: ДВА прохода, каждый — **6-секционная allpass-цепь**
   с собственным persistent-стейтом из 7 слов (чёт: r6+$1E..$24; нечёт:
   r6+$26..$2C — n6 переключается $1E→$26 внутри блока):
   ```
   P0 = fb·W6 + q                     (feedback-летний summers)
   R_i = W[i−1] + (R_{i−1} − W[i])·mod_k    (allpass: H=(g+z⁻¹)/(1+g·z⁻¹))
   OUT = c45·(q + R6),  c45 = $5A8241 = cos45°
   W ← [P0, R1..R6]                    (скользящее окно; writeback с r2=$30)
   ```
   Коэффициент allpass меняется **по-сэмплово** (LFO-модуляция).
9. **Микш**: `out_e = (1−M)·dry_e + M·wet1`, `out_o = (1−M)·dry_o + M·wet2`,
   где `1−M = $7FFFFF − MIX` (именно $7FFFFF!).

## Аппаратные нюансы, обязательные для бит-точности

1. **Отрицание операнда в mac — 24-битное с заворотом**: `-($800000)` =
   `$800000` (всё ещё отрицательное!). Затрагивает осциллятор
   (`mac -x1,x0,b`), head-rotator (`mac -y1,x1,b`) и все 6 секций лестницы.
2. **x1 осциллятора отстаёт на итерацию**: `a,x1` защёлкивает pre-ALU a.
3. Все записи acc→память/регистр берут биты 47..24 (a1) — усечение.
4. Параллельная запись кладёт **старое** значение acc (latch до ALU).
5. `(rN)+nN` = r += nN (без +1).
6. **DO-цикл**: la может указывать на 2-е слово 2-словной инструкции —
   цикл на железе выполняется полный счётчик.

## Поправка к эмулятору (ВАЖНО для прошлых измерений)

В `dsp_emu.py` исправлена обработка конца DO-цикла: раньше проверялось
`pc == la`, и если la = 2-е слово 2-словной инструкции (`move #imm,rN`),
цикл выполнялся **на одну итерацию меньше**. Внешний проходной цикл m18
(`do #$2`, la=$145128 = 2-е слово `move #>$70,r3` в $145127) выполнял
**1 проход вместо 2**. Исправление: проверка `pc <= la < next_pc`.

⇒ Измерения итераций 22/24 (ИР-тары 0.5562/0.5802/0.6029, нотчи,
«576.55 Гц») сняты на ОДНОПРОХОДНОМ поведении — их абсолютные значения
устарели; интерпретация «двухпроходного вращателя» была верной по коду,
но не наблюдалась. Все выводы данной итерации получены на исправленном
эмуляторе (05_emulator/dsp_emu.py синхронизирован).

Также подтверждено пробой-маркером: Y:$E1-$EF перезаписываются квад-рампой
(маркеры не выживают до $145092) — запись `a,y:(r0)` ходит синхронно с
`b,x:(r0)+` через общий r0. Мусор в этих ячейках на выход НЕ влияет
(0 LSB, 4 пробы).

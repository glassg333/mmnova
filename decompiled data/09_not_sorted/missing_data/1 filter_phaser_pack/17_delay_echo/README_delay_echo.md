## 1. Карта страницы EFFX (параметры 24–31 → ячейки P+$18–$1F)

Подтверждена дескриптором OS (05_descriptors/page_templates) и чтениями ядра:

| Ячейка | Ручка | Кто читает в DSP |
|--------|-------|------------------|
| P+$18 | EQF | EFX-конверт (атакующая кривая), $04B4 |
| P+$19 | EQG | EFX-конверт (кривая затухания), $04CC |
| P+$1A | SRR | EFX-конверт (сустейн = SRR²), $04C9/$04DE |
| P+$1B | DTIM | EFX-конверт (криваяrelease), $04E5; **длину эха DSP не получает** (см. §4) |
| P+$1C | DSND | **в ядре НЕ читается** → уровень send применяется хостом (ColdFire-микш) |
| P+$1D | DFB | **в ядре НЕ читается** → обратная связь тоже хост-сторона |
| P+$1E | DBAS | **в ядре НЕ читается** → базаdelay задаётся хостом |
| P+$1F | DWID | рампа микша T5 ($0B1E), доказано бит-в-бит (итерация 22) |

Греп полного дизасма: единственные чтения $18–$1B в ядре — блок $04A8–$04F5 и T5;
$1C/$1D/$1E в ядре не читаются вовсе (в машинных областях эти смещения — стейты
машин, т.к. у FX-машин r6 = P+$28 — конфликтов нет).

## 2. EFX-конверт ($04A8–$04F5) — «энвелоп, который дышит эхом»

Вызывается на каждый голос (r6 = база страницы, jmp из $0142), но исполняется
только при y:$124 == 0 (трек 0); аккумулятор — глобальный Y:$4FF (= P+$FF трека 0).
Стейт — x:(P+$00), форс-стейт — y:(P+$21) (одноразовый; харнес ставит 1 для атаки).

```
состояние 1 (ATK): env += tblA[$141800][(EQF)>>16]; переполнение → состояние 4
состояние 4 (DEC): env −= env·tblB[$141880][(EQG)>>16]; когда спад ≤ SRR² → состояние 5
состояние 5 (SUS): env = SRR² = (SRR)>>16 возведённое в квадрат  [P+$1A]
состояние 2 (REL): env = env − env·tblB[$141880][(DTIM)>>16]     [P+$1B]
иначе:             env = $7FFFFF (1.0)
```

Замер (exp24_echo.py, проба E, траектории Y:$4FF):
- все ручки 0: атака 0.0625 → 0.0857 (насыщение ~1/e за ~4 кадра — кривая tblA[0]);
- EQF=127 → tblA[127] = 0 → env замирает на 0 (атака «выключена»);
- SRR=127 → сустейн вне досягаемости (env держится на цели атаки);
- все 64 → env ≈ 0 (кривая tbl[64] даёт мгновенный спад к нулю сустейна).
⇒ **EQF/EQG/SRR/DTIM на странице EFFX ДУАЛЬНЫ**: это и «EQ-частота/EQ-гейн/SRR/…
UI-имена», и индексы кривых конверта, который модулирует ширину эха. Выход конверта
попадает в T5: рампа `mod[k] = (env·DWID)²` (16 значений Y:$10–$1F) — тот самый
мастер-микш T6 умножает выход гребёнки на mod[k].

## 3. Во что DTIM превращается: хост-ячейка P+$2A и взведение

Блок $0985–$09A9 (после DIST-диспетча, до стадии 2):

```
$0985:  r0 = (LPQ + $8000) >> 10          ; P+$13 (LPQ), индекс = LPQ·64
$098C:  L:P+$CD = $000001_000000          ; цель длины = 2^-24 (стартовое)
$0990:  x1 = T1[LPQ] = x:(r0+$144BC9)     ; таблица-пара 8192 слов
$0992:  x0 = T2[LPQ] = x:(r0+$144C49)
$0994:  a = TEMPO·$791FD0; asl #5         ; P+$23 = TEMPO (хост пишет BPM<<16!)
$0999:  a = T1[LPQ]·a
$099A:  if a ≥ $4000:                     ; ВЗВЕДЕНИЕ эха
$099D:    b = P$2A·T2[LPQ]                ; P+$2A — ХОСТОВАЯ ячейка (48-бит L-пара)
$099F:    L:P+$CD = b·$21D10              ; целевая длина дела (48-бит)
```

Замеры (exp24c/exp24e):
- при TEMPO, записанном как BPM<<16, взведение срабатывает: LPQ=64 → цель отвечает
  на P$2A; при LPQ=0 (T1[0]=0.0039) гейт закрыт даже на TEMPO 120<<16;
- **цель линейна по P$2A** (проверка: P$2A 1<<16 → 2<<16 → T ровно ×2.0000);
- таблица целей (P$2A = 1<<16): LPQ=32 → $00020CAA89E0, 64 → $01062464DE00,
  96 → $0087F67E6B40, 127 → $000087440000 (не монотонно — T2 не монотонна);
- DSP **никогда не читает ручку DTIM (P+$1B) для длины**: длина приходит через
  хостовую ячейку P+$2A, которую ColdFire считает из DTIM/DBAS/TEMPO.
  Формула хост-стороны в DSP-прошивке отсутствует (это main OS, не DSP).

## 4. RETUNE SPEED — глайд длины ($09CB–$09EE) и позиция чтения

Длина дела L:P+$CF (48-бит) глайдит к цели L:P+$CD однополюсником:

```
$09D7:  y0/y1 = цели/текущие (младшие половины), X-половины — старшие
$09DB:  x0 = $0CCCCD (0.05), x1 = $733333 (0.45)
$09DF–$09E6: a = 0.05·target + 0.45·current   (mpysu/macsu — младшая половина,
              dmac ss/mac — старшая; дробное ×2 даёт итог 0.1/0.9)
$09E7:  gate: X:(P+$D0) ≥ $3FF0 (ячейка хост-связана: $09FA перезаписывает её из
        глобальной позиции чтения L:$FC)
$09EC:  L:P+$CF ← a   →  **L += 0.1·(target − L) за кадр** → RETUNE SPEED = 1/10 за блок
```

Проверка одиночным кадром (exp24e, проба A): L=0, T=$40_000000 → новый L содержит
ровно $19999A = 0.1 в 24-битной дроби ✓ (α = 0.1 подтверждена байт-в-байт).

При 44.1 кГц и блоке 16 сэмплов: α=0.1/кадр ⇒ 63 % за ~7.3 мс, 95 % за ~11 мс —
это «подстройка» длины при смене DTIM: высота звука глайдит (tape-style) без щелчка.

Вторая половина retune — **позиция чтения**: глобальная 48-бит L:$FC слюсится к
(запись − длина) шагом **не более ±4 слова за кадр** ($09AB–$09C9: clamp ±4 через
cmpm #4 / #$fffffffc) — дискретный подезд тапа к новой точке кольца.

## 5. Кольцо эха и тапы

- Кольцо = **16384 слова** (маска $3FFF) в Y-памяти; публикация выхода секции дела —
  T4: 16 слов X:$71–$80 → Y:(X:$C5)+ (указатель хост-видимый, окно $4000).
- Позиции 17 тапов — банк L:$90–$A0 (X-половина = целое слово, Y = дробь для
  интерполяции func_000397); интеграция T2: шаг = Q = 1/длина — «гребёнка дышит
  вместе с делэем» (итерация 22).
- SKIP-ветвь T1: при S = (L:P+$CF asr 2) ≤ 4 (при Y:$C4 = 0.5) интеграция тапов,
  func_397 и публикация пропускаются — работают только DWID-рампа и микш
  (замер exp24e проба C: для L ≤ 2^24·4 выход секции дела пуст).
- T6 пишет 16 слов `echo[k]` в кольцо по указателю X:$2C9 (X:$300+ в харнесе) —
  это покадровый вклад голоса в эхо-шину; суммирование/возврат в кольцо — хост.

## 6. Итоговая схема роутинга эха

```
                    DSP (доказано)                      ColdFire (вне DSP-прошивки)
DTIM ──────────────→ [EFX-конверт: кривая release]       DTIM/DBAS/TEMPO → P+$2A
EQF/EQG/SRR ───────→ [EFX-конверт: ATK/DEC/SUS]                  ↑
                       ↓ env (Y:$4FF)                    (длина = P$2A·T2[LPQ]·$21D10)
DWID ──────────────→ mod[k] = (env·DWID)²  ←── L:P+$CF (глайд 0.1/кадр) ← target
                       ↓
гребёнка 17 тапов → func_397 (интерп.) → T4 → Y:(X:$C5)+ (кольцо 16384)
                                       → T6 echo[] → X:(X:$2C9)+ (хост-шина)
DSND (send-уровень) ────────────────────────→ применяется в ColdFire-микше
DFB (feedback) ─────────────────────────────→ возврат хостом в кольцо
```

## 7. Прямой ответ на вопросы

1. **«retune speed эха для dtim»**: длина глайдит на 10 % за кадр к цели
   (`L += 0.1·(target−L)`, коэффициенты $0CCCCD/$733333, блок $09CB–$09EE) +
   позиция чтения съезжает максимум на 4 слова за кадр ($09AB–$09C9). При 44.1 кГц
   = ~63 % за 7 мс.
2. **«значения dtim»**: ручка DTIM (0–127) на DSP входит только в EFX-конверт
   (индекс кривой release tblB[$141880], шаг = DTIM>>16); сама длина эха приходит
   хостом в P+$2A (линейно), масштабируется таблицей T2[LPQ] и $21D10, взводится
   гейтом T1[LPQ]·TEMPO·$791FD0·32 ≥ $4000. Числовая таблица целей — §3.
3. **«dsnd ручку её роутинг»**: DSND = P+$1C; в DSP-коде чтений НОЛЬ. Send-уровень
   прикладывается ColdFire-микшером к покадровому вкладу голоса (T4/T6 банки) —
   «delay send = параметр, НЕ отдельная шина» подтверждён на уровне «в DSP его нет».

Инструменты: `exp24_echo.py`, `exp24b_echo2.py`, `exp24c_echo3.py`, `exp24d_echo4.py`,
`exp24e_onpole.py`; сводка замеров — `echo_probe_results.json`.

# ColdFire-хост (main OS) — протокол DSP-связи и хвост блока «эхо» (итерация 26)

**Дата:** 2026-09-23. Объект: `coldfire_main.bin` (425 858 Б, декодированный SysEx-
контейнер OS 1.32B; CPU = Motorola ColdFire MCF5206e). Это первое погружение в
хост-сторону. Инструмент: capstone m68k (CS_MODE_BIG_ENDIAN|M68K_040) — декодирует
ColdFire-код корректно, включая CF-специфичный `extb.l`.

## 1. Карта памяти хоста (установлено)

| Диапазон | Что там |
|---|---|
| `$000000–$2676E0` | код+данные, исполняются из flash по месту (файловые смещения = адреса) |
| `$2676E0` | инициализированные данные → копируются в RAM `$1000088` (до `$100092A`) |
| `$2676E0–$2C1BE8` | BSS: обнуляется при старте |
| `$1000000–$2C1BE8` | ОЗУ (runtime heap/статические данные) |
| `$1000AAAA/$10005554` | флеш-командный интерфейс (запись $A0A0/$3030 и т.п.) |
| `$10100000+/$10200000+` | окна флеша с программами DSP1/DSP2 |
| `$300017`, `$300036` | GPIO/CS-регистры: `$300036.4` = линия RESET DSP |
| `$500000` | HI08 DSP1; `$600000` — HI08 DSP2; `$700000` — третий порт (читается в драйвере) |
| `$257CB0`, `$29BF68`, `$29C000`+ … | runtime-структуры ОС (очереди сообщений DSP) |

Загрузка ОС (файл 0x0): `movea.l #$300000,sp` → копия данных `$2676E0→$1000088` →
клин BSS → `jmp $22B5A4`.

## 2. HI08-драйвер DSP (файл `$4390C–$43C96`; полная распечатка — cf_driver.asm)

Регистры: `$X00001` = CVR (командный вектор), `$X00002` = ISR (статус, бит0 =
«данные готовы»), `$X00004` = TX/RX (24-битное слово, long-запись = 1 слово DSP).
Канонический паттерн: `CVR = cmd`, затем `CVR = cmd|$80` (выдача вектора),
ожидание `CVR >= 0`, поток слов в TX.

| Функция | Назначение |
|---|---|
| `$4390C` | DSP1: поток 52 слов (13×4 long) в TX после команды CVR |
| `$43944` | то же для DSP2 |
| `$4397C` | HALT/RESET DSP: `$1000070=$247DBA`, GPIO `$300017=$93`, `$300036 &= ~$10`, `$600000=$81`, дренаж RX |
| `$439D6` | ЗАПИСЬ блока в ОЗУ обоих DSP: TX = `(addr<<11)+$150000` обоим, CVR $0B обоим, затем поток 2046 слов (1023×2) из 3-байтного упакованного буфера |
| `$43A6A` | очистка ОЗУ обоих DSP (тот же протокол, данные 0) |
| `$43AF4` | запись блока в DSP2 (`$150000`) |
| `$43B4A` | ЧТЕНИЕ блока из DSP2 (`$150001`!, CVR $06, poll ISR.0, RX) |
| `$43C42` | запись одной ячейки DSP2 по адресу $4FE (`$150000`? нет: TX=$4FE, CVR $07, затем TX=значение) — служебная |

Командное слово `(addr<<11)+$150000/$150001`: `$150000` = запись, `$150001` =
чтение; 11 младших бит команды = смещение внутри блока $7FF слов.
Загрузчики DSP-программ из флеша (`$4422C–$45194`) — единственные runtime-
пользователи `$439D6`/`$43A6A`.

## 3. Сторона DSP: обработчики вектор-таблицы (ядро DSP1, code_full.asm $0000–$0026)

| Слот | Обработчик | Действие |
|---|---|---|
| 6 ($0C) | `func_000235` | **чтение ячейки ОЗУ DSP хостом**: ждать `$FFFFC3.0`; `r0 = $FFFFC6` (адрес от хоста); `x:(r0) → $FFFFC7` (HTX) |
| 7–9 ($10-$14) | `func_000219/220/227` | `$FFFFDA ← $500/$600/$700` (период таймера блока), `$FFFFD9 ← $33`, `$FFFFD8 ← $8E9AC4` |
| 10 ($16) | `func_00022E` | `$FFFFDA ← $FFFFC6` — **хост управляет периодом таймера блока DSP** (вектор слота 10 = команда темпа/частоты блоков!) |
| 13 ($1A) | `func_00023e` | почтовый ящик 2 слов: acc → X:$2C5-$2C7, счётчик X:$4FE (mod 3) — в прошивке читателей НЕТ |
| 16 ($20) | `func_000259` | настройка ESSI/таймера (`$4A5A20`, `$8A52C0`, `$2F`) |

Аудиоблок: ядро читает `$FFEB` (HRX) → заголовок `$140/$160/$180` (режимы
маршрутизации `3*STEREO+AB / 3*STEREO / 6*MONO` — строки OS!), выбирает наборы
буферов (r1/r2/r3/r0 = `$140/$160/$180`-зависимые базы), затем поллит `$FFEB`
относительно заголовка (пороги $A/$15) — поток сэмплов от хоста через HI08.

## 4. Дескрипторы OS (подтверждение карт страниц)

`05_descriptors/all_machine_descriptors.json` ↔ coldfire_main.bin 1:1 по смещениям.
Формат дескриптора машины (176 Б): `FX\0…` + счётчик + имя + 8×6-байтных имён
параметров + 8 дефолтов + 8×`$00 00 80 00` + хвост (последний байт = DSP-индекс
машины: FX-THRU = $0D, FX-REVERB = $0E).

**FX-REVERB** (0x588B5): `DEC DAMP GATE MIX HP LP --- INP`, дефолты
`40 02 7F 20 00 7F 00 40` — раскладка ручек реверба (см. 19_m13_reverb/).
Страница EFFX: `EQF EQG SRR DTIM DSND DFB DBAS DWID` — подтверждена шаблоном
страниц (`page_templates.json`).

## 5. Исправление к итерации 24 (T1/T2)

Блок взведения эха `$0985–$09A9` читает таблицы с **шагом 1** (r0 = округлённый
LPQ), а НЕ с шагом 64:

- `$144BC9` = T1[i] = **(i+1)/256** (линейная рампа, Q0.23);
- `$144C49` = T2[i] = **1/(i+1)** (таблица обратных величин, Q0.23).

Итоговые формулы:
- гейт взведения: `(LPQ+1)/256 · TEMPO · $791FD0 · 32 ≥ $4000`;
- целевая длина: `target(48 бит) = P$2A · (1/(LPQ+1)) · $21D10`.

Т.е. T1/T2 — общие арифметические таблицы, а НЕ «нотные деления» базы delay.
Дампы обеих таблиц — в 19_m13_reverb/reverb_tables.txt (метод §5) — и в
тексте ниже для T2: 7FFFFF, 3FFFFF, 2AAAAA, 200000, … (1/1 … 1/128).

## 6. Открытый лид: формула P$2A (хост)

Установлено:
- DSP никогда не вычисляет P$2A — только читает (ядро $0985/$099D);
- ColdFire имеет полный примитив записи ячеек/блоков в ОЗУ DSP (§2);
- констант `44100`, `2646000`, `60000000`, `0x791FD0`, `$21D10` в ColdFire-образе
  НЕТ (поиск точный) → длина delay либо считается через табличную шкалу,
  либо отправляется в единицах, не требующих частоты дискретизации;
- runtime-поток параметров не проходит через найденные блочные вызовы
  `$4390C/$43944` (их вызовы = служебные сообщения с буферов `$1000A54–$1000E64`,
  команды 0/1/2) и не проходит через `$439D6` (только загрузка программ) →
  существует ещё один путь записи страниц (вероятно, прямой поток TX через
  другой каркас в `$48000+` или через `jsr (aN)`-диспетчер).

Следующий шаг (итерация 27): найти записывателя страниц — поиск по коду,
пишущему в TX (`move?.? d?, $500004/$600004`) вне `$4390C–$43C96`, и трассировка
записи ячеек TEMPO (P+$23, значение BPM<<16) и P$2A.

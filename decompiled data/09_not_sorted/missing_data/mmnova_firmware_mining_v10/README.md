# Monomachine SFX-60 OS 1.32B — данные, добытые из оригинальной прошивки (итерация 10)

**Дата:** 2026-09-20
**Прошивка:** `elektron_sfx6-60_os1.32b.bin` (8 388 608 Б)
**SHA-256:** `369849175602e20a9dd2b6e0ad8ac404b76f82718b14afbf1cbc01b7acabec7e`
**Метод:** дизассемблирование ColdFire-кода секции 0 (capstone M68K, база секции 0 =
$200000 — установлена в этой итерации) + скан абсолютных ссылок + статистическая
проверка на всех 128 слотах. База — итерация 9 (v9).

## 1. Главный результат итерации 10

**Зона параметр-локов (+0x557) перерасшифрована: СТРОКА = ЯЧЕЙКА (дорожка, шаг),
КОЛОНКА = НОМЕР ПАРАМЕТРА.** Модель v9 («строка = (дорожка, параметр)») была
неверной. Полная модель:

- `+0x274..+0x2A3` (48 Б) — **маска ячеек с локами**: 6 дорожек x 8 Б, бит (дорожка, шаг)
  = ячейка имеет хотя бы один параметр-лок. **popcount масок == байт +0x556 на 128/128 слотах.**
- `+0x556` — число ячеек с локами.
- `+0x557..+0x14D6` — 62 строки x 64 Б: строка r = r-я ячейка с локом в порядке
  track-major (дорожка 0 шаги 0..63, дорожка 1, ...); байт p = значение параметра p
  на этой ячейке; `FF` = параметр не заблокирован. Хвост за popcount — FF (128/128).
- Проверка: сумма строк-ячеек с локами по заводу = 323 (совпало с числом «строк» v9),
  максимум 42 ячейки (слот 1).

Закрыты вопросы v9 №1 (номер параметра = колонка строки), №2 (+0x554), №3 (маски
+0x274), №4 (массив stride 0xA8), №5 (блок +0x4D0); вопрос №7 скорректирован.

### 1.1 Ключевые доказательства (ОС, секция 0, база $200000)

- **База секции 0 = $200000**: `jsr $224800` = смещение 0x24800 — геттер
  `tst.l $26b570; move.l $26bb94/$26bb98,d0; rts`; сеттер 0x24A84 делает `+6` при
  отрицательных и `divs.l #6` — **это селектор текущей ДОРОЖКИ (mod 6)**, а не «число
  строк», как считали v8/v9 (`disasm_track_current.asm`).
- **Распаковщик ячеек** (`$23518A` = 0x3518A, вызывается из 'COPY NOTE'/'COPY MIDI
  NOTE' — строки меню $251D69/$251D76/$251D85, `disasm_undo_menu_strings.asm`):
  фаза 1 — `d7 = Σ popcount(масок дорожек 0..T-1)`; фаза 2 — по дорожке T = текущей
  (`$224800`): для каждой установленной ячейки маски
  `выход[$29B46E + шаг] = slot + 0x557 + d7*64 + a5; d7++` (`disasm_player2_cell_unpack.asm`).
  arg a5 = индекс параметра из `$2579F0` (геттер 0x1A23E).
- **$3090C(k, track, step)**: k=0 -> FF/$FE по наличию ноты (зона +0x2A4 = тригг
  ячейки для движка); k>=1 -> поиск k-й записи (track,step) в **таблице локов**
  слота: 16-бит записи `param<<9 | track<<6 | step` от `slot+0x17F8`, счётчик =
  байт `slot+0x554` (`disasm_3090C_table.asm`).
- **$3087E** — проверка ячейки движком: наличие ноты (sne/neg) + скан таблицы.
- **$35338** — undo-удаление: `notes[t][s] = FF`, `+0x554--`, сдвиг записей таблицы
  влево (`disasm_35338_undo_delete.asm`); редактор-скан таблицы — 0x2C400.
- **+0x554 = счётчик записей таблицы локов**: аксессоры `$307E8` (чтение), `$30818`
  (**0xC0 − x = свободные слоты**, ёмкость 192 записи = 0x180 Б), `$30852` (сброс).
  «Знаковый байт» v9 — артефакт (`disasm_554_accessors.asm`).
- **$29B46E (stride 0xA8) — вопрос v9 №4**: это рабочие буферы распаковщика:
  +0x00..0x3F = per-step значения выбранного параметра (FF = нет лока),
  +0x40.. = ноты/машина ($3090C), +0xA4 = служебное (`$29B512`).
- **Блок +0x4D0 — вопрос v9 №5**: ПЯТЬ пер-дорожечных векторов шагом 6
  (+0x4D0/+0x4D6/+0x4DC/+0x4E2/+0x4E8 + дорожка) -> $29B816..0x81B (слот 4 =
  константа 7); блок параметров машин 2 = **+0x4EE + t*16** (6 x 16 Б) —
  уточнение v8 (`disasm_4d0_vectors.asm`).
- **Таблица +0x17F8 — RAM-рабочая структура**: в дампе флэша записи не
  соответствуют маскам/строкам ни у одного из 37 слотов с локами (обновляется в
  RAM, во флэш попадает частично через журнал износа). Постоянный формат хранения
  локов = маска +0x274 + счётчик +0x556 + строки +0x557.

### 1.2 Коррекция v9

- «Маски строк локов +0x274» (v9 №3) — на самом деле маска ЯЧЕЕК с локами;
  «stale-корреляция» v9 объясняется неверной моделью.
- «+0x554 знаковый, транспозиция» (v9 №2) — счётчик таблицы локов.
- «$224800 = число строк» (v9) — текущая дорожка (mod 6).
- «GLOBAL +0x3C таблица 12Бx32 с ID» (v9 №7) — байтовый шаблон-рампа
  (0x0B, 0x17, ..., 0x6B = 12k+11, затем 0x77 x N, FF x N), идентичен в GLOBAL 0..6;
  у активного GLOBAL 7 хвост отличается. См. `01_map/global_table_correction.json`.

### 1.3 Декод

`03_decoded/cells_decoded.json` — все 128 слотов: маски ячеек, ячейки
(row/track/step/trig), параметры и значения локов, таблица RAM, флаги проверок.

Открытым остаётся СЕМАНТИКА колонок-параметров (какой параметр машины стоит за
индексом 0..63 — зависит от машины дорожки, вектор +0x446) — вопрос v11.

## 3. Открытые вопросы для итерации 11

1. Семантика колонок-параметров (0..63) по типам машин: дизассемблировать
   таблицы параметров машин (дескрипторы рядом с $2BDA2E/$3090C).
2. Маски A (+0x1B0) / B (+0x1E0): пер-дорожечные флаги, семантика не найдена.
3. Природа рампы GLOBAL +0x3C (12k+11 -> 0x77 -> FF).
4. Пять векторов +0x4D0..+0x4ED: назначение каждого (машина? mute? routing?).
5. +0x552/+0x555: точная роль вспомогательных счётчиков таблицы (undo-стек?).
6. Тригг-маски +0x000 (7 копий) vs ноты: механизм wear-leveling при сохранении.

# ROUTING_BUFFER_EXACT — только доказанный фрагмент

Источник опкодов: соседний файл `decompiled data/03_listings/dispatch/dsp1_kernel_P0000-0B4D.txt`,
проверенный в commit `9dd0e6aa0c48126df1ec1cfa9a0a808a98d00307`.

Подтверждено буквально:

* `P:$013D: lua (r6-$28),r6` и `P:$013E: move #>$100,r7`; далее `P:$0142`
  передаёт управление в `func_0004A8`. Поэтому база `V-$28` и шаг voice
  `$100` доказаны для этого участка.
* `P:$0149: brset #$3,a,func_0001F3`: расширенный путь выбора записи
  включается битом 3.
* `P:$0165: add #>$100,b` и `P:$016E: cmp #<$3,a`: три голоса текущего
  прохода и шаг `$100`.
* `P:$01A3..$01C1`: сумма трёх буферов в основной буфер с коэффициентом
  `$7FFFFF` (единица в Q1.23), без деления на три.
* `P:$01F8: bsclr #$C,a,func_0001E2` и `P:$01FC: bsset #$C,a,func_0001EC`;
  аналогично для битов 13/14. В этом участке CLEAR ведёт в ADD, SET — в
  OVERWRITE.
* `P:$01E2..$01EB` — добавление, `P:$01EC..$01F2` — перезапись; оба цикла
  работают по 16 стерео-кадрам.

Не следует расширять этот proof до следующих утверждений без отдельного
доказательства: точный ColdFire-скейлинг ручек, полная последовательность
DIST/EQ/SRR/FILT/ENV, знак/раскладка каждой HPQ/LPQ-ветви и «100% wet» как
свойство MIX. В исходной папке эти вещи заявлялись шире, чем подтверждены.

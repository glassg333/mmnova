# LFO хоруса — ВЕРДИКТ: НЕ неверный (проверено 2026-09-25)

## Короткий ответ
**Нет, LFO хоруса не сломан.** Это был старый флаг из времён 1.5.x
(«у хоруса нужно проверить лфо»), закрытый ещё в 1.6.0: хорус FX-плагина
тогда был портирован из прошивки (ChorusCore) и тобой же утверждён как
«идеальный» (файл-маркер «Monomachine Nova 1.6.0 chorus mnm в этой версии
фкс плагина идеальный» в JUCE-папке). Я сверил 1.6.0 ↔ 1.7.11 побайтово.

## Доказательства
1. **Файлы бит-в-бит совпадают** между 1.6.0 (одобренная версия) и 1.7.11
   (sha256, обе копии FX/Synth):
   - `Source/dsp/ChorusCore.cpp` — SAME
   - `Source/dsp/ChorusCore.h` — SAME
   - `Source/dsp/AudioAdapter.cpp` — SAME
   - `Source/dsp/AudioAdapter.h` — SAME
2. Машина 15 (CHORUS) в FX-плагине 1.7.11 рендерится через
   `AudioAdapter → ChorusCore` (`NovaDSP.h`, `id==15`) — т.е. прошивочное
   ядро P:$147661-$1477DE, а не generic-заглушка.
3. LFO внутри ChorusCore — прошивочный, по листингу:
   - фаза = «текучий интегратор»: phase += SPD·$28f5c − phase·$028f5c
     (однополюсное сглаживание скорости, P:$1476AD-$1476B4);
   - индекс ×$800 → выборка квадратуры из таблицы $14A000 (синус) и
     $14A800 (косинус = синус+2048) — P:$1476B9/$1476BB;
   - интерполяция квадратуры по предыдущему блоку (P:$1476BD-$1476C4);
   - матрица ±0.866 ($6ED9EC/$912614 — cos30°/−sin60°) — P:$1476E6-$147701;
   - fade-in wet: первые 128 блоков wet=0 (P:$14767D-$147688);
   - сумма тапов ×1/3 ($2AAAAB), FB в линию: dry·(1+FB)/2 − FB·LP(wet)
     (таблица $144AC7, знак отрицательный).

## Три ЗАДОКУМЕНТИРОВАННЫХ отклонения порта (не LFO, но рядом)
Все три уже помечены в коде 1.7.11, звучат минимально:
1. `ChorusCore.cpp:345` — при MIX=127 ядро форсится в 100% wet; ROM оставляет
   0.78% сухого остатка (−42 дБ, неслышимо). Комментарий в коде есть.
2. `NovaDSP.h:191` — `coreParams[3]=127;coreParams[7]=64`: микс вынесен
   наружу (сухой = выровненный по латентности delayedInput, что фазово
   даже точнее), INP подаётся снаружи линейно p[7]/64 вместо квадратичного
   INP²×4 внутри ядра (разница кривой входа слышна только на краях INP).
3. OUT-сумма тапов и FB-законы в ядре не тронуты.

## Что НЕ является прошивочным хорусом
`Source/dsp/monomachine_chorus.hpp` (`MonomachineChorus`, используется в
`monomachine_voice_chain.hpp` как per-track хорус-узел SYNTH-цепочки) —
это учебный generic-хорус (синус-LFO, экспонента SPD 0.1–8 Гц, DEL
1–25 мс, линейный микс). Он НЕ прошивка и не тот «идеальный» хорус.
Это не баг — это отдельный узел цепочки; просто не путать его с машиной 15.

## Правило (из твоего же промпта 1.6.0, правило 6)
«Хорус, который уже одобрен, не трогать; альтернатива — только отдельным
режимом». Поэтому в этой поставке для хоруса НЕТ кода-патча: режим `ex`
для машины 15 не нужен — текущий mnm и есть прошивка.

## Если захочешь убрать отклонение №1 (0.78% dry) — ОПЦИОНАЛЬНО
```cpp
// Source/dsp/ChorusCore.cpp, строка 345:
// БЫЛО:
if(x0==0x7f0000u){x0=0x7fffffu;} // MIX=127 clamp: full wet, zero dry (deliberate deviation; ...)
// СТАЛО (строго ROM):
// (строку удалить — ядро оставит x0=0x7f0000, сухой остаток $FFFF/$800000 ≈ 0.78%)
```
НЕ рекомендуется без A/B на ушах: дельта −42 дБ, а «идеальность» 1.6.0
утверждалась именно с текущим кодом.

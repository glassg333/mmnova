# mmnova_stage8_fm_par_dyn_100 — FM+PAR (m9) и FM+DYN (m10) бит-в-бит

Дата: 2026-09-27. Задача: «довести DYN и PAR до полной бит-точности».
Метод: тот же протокол, что m1/m2/m3 — пословная транскрипция листинга в C++
+ векторная валидация против бит-точного эмулятора (scripts/dsp_emu.py),
0 расхождений по всем словам выхода И всего персистентного стейта.

## РЕЗУЛЬТАТ

| машина | листинг (P:) | тест | совпадение |
|---|---|---|---|
| m9 FM+PAR | $145EC9 (INIT) / $145ED4 (CONF) / $145EDB-$14619C (PROC) | 14 наборов ручек x 16 блоков | **29568/29568 слов = 100%** |
| m10 FM+DYN | $14619D (INIT) / $1461A8 (CONF) / $1461C1-$14636E (PROC) | 16 наборов ручек x 16 блоков | **33792/33792 слов = 100%** |

«Слово» = 32 выхода блока (16 моно L/R пар, Q23) + 99 слов стейта
(y:(r6+$00-$3F) страница, X:$5/Y:$5 = carrier inc48, X:$1E-$3F = окно rot-2),
снимаемые после КАЖДОГО блока. Тест: research/test_fm_par_dyn.cpp (exit 0).

Наборы ручек покрывают: середину/нули/максимумы, края индексов отношений
(0,5,11,21,32,43,53,64,75,85,96,107,117,123), границы гейтов 63/64/65,
wrap-зону ENV (80/90/110/120/127), TONE 0/127, клэмп 1FRQ ($7EFFFF/$7FFFFF),
квадратичный 2FRQ (0/127), 1FEN 0/127, 1VEN 0/63, 2ENV+2FB 0/63/127,
разные питчи A = 512..24000.

## ЗАКОНЫ ПИТЧА (замерены на векторах, см. CORRECTION)

  - Частота машины: f = A Гц (A = питч-слово на входе PROC).
    inc48 = 2*$0BE37C*A; несущая: 32 шага фазы на блок при 16 фреймах
    (внутренний рейт x2), выход = пар-суммы соседних отсчётов.
  - TUNE: аддитивен в домене питч-слова (2048 ед/октава) => в f-домене
    множитель 2^(K*5.336/2048): +3.127 цента/шаг, униполярно 0..+397 центов,
    K=64 = +200 центов (дефолт прошивки — патч по умолчанию играет на
    200 центов выше; это свойство OS 1.32, не порт).
  - В плагине: A = round(440*2^((note+bend-69)/12) * 2^(TUNE*5.336/2048)),
    клэмп 0..16744 Гц (перевод/kernel-клэмпа $5800 ед. = нота 132).

## ИСПРАВЛЕННЫЕ ОШИБКИ ПРЕДЫДУЩИХ ДОКУМЕНТОВ

См. 22_fm_machines/CORRECTION_fm_ratio_law.md (в паке filter_phaser_pack):
  1. Индекс таблицы отношений $141A80: slope 3/16, НЕ 3/32 (в README
     итерации 27 и mnm_fm_exact.hpp был пропуск `prod <<= 1`).
     Края: 0,5,11,16,21,27,32,37,43,48,53,59,64,69,75,80,85,91,96,101,107,
     112,117,123. n1@48 = 9 (0.75), не 4 (0.25).
  2. Частота f = A Гц, не A/2.
  3. Модель итерации 28 «кросс-FM DYN структурно неслышим, выход = чистая
     синусоида при любых ручках» — УТОЧНЕНА: LP коэффициент DYN =
     $400000 (0.5, короткий иммедиат left-justified), а не 64/2^23; на
     выходе DYN при ручках-64 реальная доминанта ~f/2 (замерено на
     эмуляторе И на порту — совпадает). Бит-точность важнее модели.

## ЧЕСТНЫЕ ОГОВОРКИ

  - Синус-таблица $14A000 не в дампе (заполняет ColdFire) — используется
    каноническая round(sin*8388607), та же, что в валидированных m1/m2/m3.
    Бит-точность = бит-в-бит с эмулятором в этой таблице.
  - Абсолютная калибровка «нота -> Гц» ядра (стык $02DD-$02EA) остаётся с
    открытым вопросом x1.118 из итерации 27 — здесь он обходён: порту
    скармливается A = f напрямую, законы ручек от этого не зависят.
  - FM+STAT (m8): законы ручек верифицированы (итерация 27), рендер —
    ещё float-ядро; транскрипция STAT — следующая итерация.

## 1. ГЛАВНОЕ ОТКРЫТИЕ СЕССИИ: карта ячеек стадии дилея

Стадия дилея НЕ читает FX-ячейки P+$1C/$1D/$1E (DSND/DFB/DBAS) — проверено
сканом листинга: 0 обращений. Она читает ФИЛЬТРОВУ страницу P+$10..$17:

| Ячейка | Роль в стадии дилея              | Чтение        |
|--------|----------------------------------|---------------|
| P+$13  | DTIM — индекс времени (0..127)   | $0985 y:(r6+$13) |
| P+$14  | флаг стерео-обмена (≥0.5 → swap) | $0A22 y:(r6+$14) |
| P+$15  | гейн рампы выхода                | $0ABF y:(r6+$15) |
| P+$16  | BAS — индекс коэффициента FIR    | $0A5D y:(r6+$16) |
| P+$17  | WID — индекс (BAS+WID)           | $0A84 y:(r6+$17) |
| P+$1F  | DWID — для SRR-рампы             | $0B1E y:(r6+$1F) |

Хост (ColdFire) пишет UI-ручки прямо в эти ячейки. Интегратору плагина:
ручка TIME → cell13, BAS → cell16, WID → cell17 (формат значения: v<<16).

FX-ячейки P+$18..$1B (EQF EQG SRR DTIM) обслуживают EFX-огибающую
(P:$04A8-$04F3): атака по EQF, декей по EQG, hold на SRR², релиз по DTIM.
Это ЕДИНАЯ система «SRR-огибающая» — см. MnmSrrExact.hpp.

## 2. БИТ-ТОЧНЫЕ ЗАКОНЫ (доказаны векторами эмулятора)

### 2.1 Время дилея (P:$0985-$09AD) — ЦЕПОЧКА ИНСТРУКЦИЙ БИТ-В-БИТ
```
v        = (cell13 + $8000) >> 16                    // 0..127
y0       = floor(7938000 * TEMPO * 64 / 2^24)        // mpyi $791FD0<<1, asl#5, a1
target48 = kDtim1[v] * y0 * 2                        // mpy TBL1[v],y0 (дробн. <<1)
```
kDtim1[v] = (v+1)/256 в Q23 (ROM $144BC9; ВНИМАНИЕ: [127] = 0x3FFFFF,
не 0x400000 — ROM-округление). Контрольные точки эмулятора:
target(0,120) = 0x0E310000 ТОЧНО; y0(120) = 3633; y0(60) = 1816; y0(240) = 7267.
Целевой 48-бит — Q8.24: целая часть (в словах кольца) = cell >> 24.

Путь «больших времён» (P:$099D-$09A9, $42A·TBL2·$021D10, кламп $3FF0) в
 captured конфигурациях не срабатывал — ветвь задокументирована в листинге,
в порту помечена (триггер условий ветвления зависит от ячейки P+$2A, которую
пишет ОС; в харнессе = 0).

### 2.2 Глайд (P:$09AF-$09C9) — лебёдка tape-style
```
current += clamp(target - current, ±4<<24)           // ±4 единицы за блок
коммит текущего: только если smoothed << 10 >= $3FF  // $09CF-$09D2
```
Измерено: ровно +1024.0 ед./блок в представлении /65536 (+4<<24 в 48-бит).
Это и есть фирменный «tape» глайд MNM: смена DTIM слышно подтягивается
за ~ (Δ/4) блоков.

### 2.3 Однонолюсник сглаженной цели (P:$09D7-$09EE)
```
smoothed = 0.1*raw + 0.9*smoothed     // $CCCCD/$733333 на 48-бит парах
запись smoothed только при current_hi >= $3FF0     // уточнение у полного кольца
```
raw (P+$CD) = 1<<24 (константа с $0989) либо произведение большой ветви.

### 2.4 Коэффициенты фильтров петли (P:$0A5D-$0AB5) — доказано захватом
```
BAS -> kFirPool[BAS]        // $144AC7[v]
WID -> kFirPool[BAS + WID]  // $144AC7[vB + vW]
```
Захват чтений x:(r3+n3)/x:(r2+n2) при 6 комбинациях ручек (vectors firidx2).
Сами фильтры — 16-итерационные mac-цепочки с состояниями P+$D3..$D5,
транскрибированы в MnmTrackDelayExact.hpp (basFilterL/widFilter) — семантика
56-бит, <<1, macr-округление воспроизведена по эмулятору.

### 2.5 EFX-огибающая (P:$04A8-$04F3) — фазовая машина бит-в-бит
Фазы 0/1/2/4/5, TRIG y:(P+$21) (очищается после чтения), фаза x:(P+$00):
1: env += kEnvAttack[EQF]; перенос 48-бит → фаза 4
4: a = -env·kEnvDecay[EQG]; a ≤ SRR² → фаза 5, иначе env = a
5: env = SRR²>>24  (= SRR_v²·256: SRR=48 → 0x090000… уровень hold)
2: env = -env·kEnvDecay[DTIM]   (релиз, индекс = DTIM!)
иначе: env = $7FFFFF
Замечание: ячейка env (Y:$4FF) ДОПИСЫВАЕТСЯ в конце блока квадратичным
мэппингом (P:$0B1E-$0B33) при условии соотношения времён (P:$0AE7-$0AE9:
b ≥ 16) — в захваченных конфигурациях условие не стреляло; триггер помечен
[RECONSTR.].

### 2.6 SRR-рампа Y:$10-$1F (P:$0B1E-$0B33)
```
X0 = ((env²>>24)·(DWID_v²·256))·2 >> 24      // mpy x1,x0, a1
ramp[k]   = a1(prev<<24 + (k+1)·($10·X0))     // k=0..7
ramp[k+8] = a1(prev<<24 + (1/16)·X0 + (k+1)·($10·X0))   // maci $080000
```
Рампа = 16 пер-кадровых коэффициентов СЛЕДУЮЩЕГО блока (восходящая по
блоку — глубина прореживания растёт внутри блока). При малых env·DWID
шаг < LSB целой части — рампа плоская (измерено: ramp ≈ env для
env=0x0AFB0C, DWID=64).

## 3. ТОПОЛОГИЯ (фактура, T1) — для следующей сессии полной бит-точности

- Кольцо: Y:$0000-$3FFF (L-половина) + Y:$4000-$7FFF (R-половина), маска
  $3FFF. Запись блока: 16 слов из X:$71-$80 → Y:(C5)+ ($0B15-$0B1D),
  C5 = C4 + $4000. Чтение: staging-копия Y:(r4)+ → X:$40-$61/$62-$83
  ($0A29-$0A34, r4 = C2-целая, r5 = +$4000), затем дробные тапы
  func_000397 по таблицам X:$E0-$F0/X:$81-$8F/X:$91-$A0.
- Таблицы тапов ПЕРЕЗАПИСЫВАЮТСЯ ядром каждый блок ($0A4E-$0A52: шаг =
  speed(X:$FE)·target($4CF) — «speed лебёдки» $30/$500000).
- Хост-контракт: L:$C2/$C4/$C5 и Y:$FE (фаза блока) — абсолютные ячейки,
  ОС их ко-менеджит; в харнессе без ОС цикл записи ($096E-$0973) читает
  устаревшую фазу → пишет 0. Именного этого не хватает для полной
  изолированной бит-точности записи в кольцо.
- func_000397 (дробный сканер тапов) доказан бит-в-бит ещё в итер.14
  (svf_fit.py 8/8) — примитив fracTap воспроизведён.

## 4. ЧЕСТНЫЕ ГРАНИЦЫ v5

- Бит-точно: законы времени (цель/глайд/однонолюсник), закон коэффициентов
  BAS/WID, EFX-огибающая, SRR-рампа, все 6 ROM-таблиц.
- [RECONSTR.]: челнок staging↔кольцо (документирован выше), send/feedback
  гейны (ячейки DSND/DFB хост-мапятся, в DSP не читаются), пер-сэмпловый
  дециматор SRR (потребитель рампы — стандартный hold), форма пер-сэмпла
  BAS/WID-фильтра (коэффициенты и 16-итерационная структура — из листинга).
- Путь «больших времён» P:$099D-$09A9 — не наблюдался; закодирован по
  листингу, триггер — ячейка P+$2A (хост).

# FM_EXACT_README — канонический документ по FM+ машинам (версия 1.9.8)

ЭТО ЕДИНСТВЕННЫЙ АКТУАЛЬНЫЙ ДОКУМЕНТ ПО FM-МАШИНАМ. Все предыдущие ридми
по FM устарели и не должны использоваться.

## Что сделано

Три FM+ машины (m8 FM+STAT, m9 FM+PAR, m10 FM+DYN) переписаны как
пословная транскрипция прошивки OS 1.32B (DSP56300) вместо прежних
угаданных законов. Правду брали из двух источников:

1. Листинги: `decompiled data/03_listings/machines_page_A/08..10_FM-*.txt`
2. Эмулятор `scripts/dsp_emu.py`, прогоняющий РЕАЛЬНЫЙ код прошивки

## Почему ручки не совпадали (найденные ошибки старого кода)

* **Индекс таблицы частот**: в прошивке `n = (24*(K<<16+$8000))>>23`
  (дробный MPY на DSP56300 удваивает произведение). Старый код считал
  `>>24` и терял ВЕРХНЮЮ ПОЛОВИНЫ таблицы — верхние октавы соотношений
  не были доступны вообще.
* **Таблица соотношений**: 24 записи (Y:$141A80), а не 32 самодельные.
  Эффективные соотношения: 1/64 ... 4/1 (для STAT мод-1 ещё ×2).
* **1FIN** = 1 + (K−64)/256 на соотношение мод-1 (только STAT).
* **1ENV/1FB порядок**: на странице 1ENV стоит РАНЬШЕ 1FB (1ENV=$6, 1FB=$7).
  1ENV = громкость блока мод-1 (8·K²) + затухающая огибающая уровня
  (config ставит $7FFFFF на note-on); 1FB = однохэмпловый фазовый фидбек
  на чтении мод-1, глубина K·32 единиц таблицы.
* **2VOL** = громкость блока мод-2 (8·K²) + гейт-шейпер
  `out[i] = in[i] + in[i-1]*(K-64)/256` («амплитудный фидбек» из мануала).
* **Носитель** идёт на «сырой» высоте (L5 = 2·$BE37C·pitch), а сумма
  модуляторов (веса 8·K²·уровень) фазово-модулирует его через >>12.
* **Оба мод-пути**: синус → первая разность → TONE one-pole (таблица
  Y:$144AC7, индекс = само значение ручки TONE).
* **Выход** = 16 моно сэмплов на 32-словный блок (машина работает на
  половинной частоте), L=R. Две ступени полифазных ротаторов последовательно.
* **TUNE** в процесс машины не входит вообще — ядро прибавляет её к
  питч-слову (X:$140000, 2048 шагов/октава; TUNE = (K−64)·683/128 шагов).
* **DYN**: 1FRQ = непрерывное соотношение (кламп $7EFFFF→$7FFFFF),
  2FRQ = квадратичное (x0 = A1(2·K²), inc = 8·x0·L5), 1FEN/1VEN — рекурсия
  по кривой P:$141880, LP на мод-путях фиксированный 0.5 (не TONE),
  2FB — фидбек чтения мод-2, TONE-ручки нет.

## Верификация (протокол)

Эмулятор = истина. Тест: init+config+4 блока процесса на 29 векторах
(дефолты, каждая ручка в 0 и 127, случайные комбинации, 3 питч-слова),
сравниваются все 32 выходных слова каждого блока + все слова страницы
голоса.

* **FM+STAT: 116/116 блоков бит-в-бит** (скрипты exp40..45, test_stat)
* **FM+PAR: 11/96 бит-в-бит**, остальные расходятся на ±1–3 LSB
  (~−120 дБ, неслышимо); расхождение накапливается в дробной части фазы
  носителя — вероятная причина: порядок округления в одной из операций
  второго микса, требует следующей итерации трассировки
* **FM+DYN: законы транскрибированы из листинга**, потактовая сверка
  с эмулятором не завершена (следующая итерация)

Честные ограничения:
* Синус-таблица X:$14A000 отсутствует во всех доступных дампах (область
  SRAM, не попадающая в дамп). Используется идеальный 8192-точечный синус
  S1.23 ОДИНАКОВО в эмуляторе и в порте, поэтому все сравнения остаются
  в силе. Если реальная таблица когда-нибудь найдётся — заменить через
  `mnmfm::initSineTable()`.
* Состояния $29 (STAT) и $31 (PAR) не входят в диапазон обнуления init
  ($11..$28 / $11..$30). В эмуляторе там лежит мусор SRAM
  ($061080 / $0022F800) — это воспроизведено в init() портов для
  бит-точности; на слух это первый семпл после note-on.

## Роутинг (проверено по мануалу OS 1.32)

Порядок стадий в TrackChain (NovaDSP.h, stageEQ→stageDELAY):
EQ → FILT → DIST → AMP ENV → VOL/PAN → SRR → DELAY — соответствует
схеме мануала. Фильтр страницы DELAY (BAS/WID = params[30]/[31]) теперь
включён В ФИДБЕК-ЛУПУ задержки и в режиме mnm (MnmDelay::process принимает
fbFilter; раньше фильтр в лупе был только в old-режиме).

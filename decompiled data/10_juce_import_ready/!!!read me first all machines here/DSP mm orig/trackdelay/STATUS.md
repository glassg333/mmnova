# STATUS: Track Delay (глобальный пер-трековый дилей) + SRR — добытые доказательства

Дата: 2026-09-25. Ответ на запрос: «Track Delay P:$000939/P:$000a5b, ячейки
Y:$051b–$051f (TIM/SND/FDB/BAS/WID, tape-style) + SRR — код для импорта,
идентичный прошивке».

ВЕРДИКТ: топология и ключевые константы добыты (T0/T1), но ПОЛНОЕ
бит-точное ядро требует отдельной майнинг-сессии уровня реверба (стадия
живёт в общем кернеле DSP1, а не в слайсе машины, и завязана на контекст
шедулера: r6-фрейм скользит между треками, вход приходит из стейджа ампы).
Это НЕ машинный слайс — его нельзя померить изолированно без
воспроизведения контекста вызова.

## 1. ЧТО ЭТО ТАКОЕ (уровень T0)

- Машины-дилея в OS 1.32B НЕ СУЩЕСТВУЕТ: строка «DLY» в ROM ColdFire
  встречается 0 раз (проверено по coldfire_main.bin, 425858 B).
  Имена файлов 03_listings/machines_page_A/32_FX-DLY_full.txt и
  33_FX-EXT_full.txt НЕВЕРНЫ: m32 = DPRO-DDRW, m33 = DPRO-DENS (см.
  ../machine_map_fix/README.md).
- Дилей — стадия ОБЩЕГО тракта каждого трека: Track Delay Stage P:$000939
  (send+фидбек-кольцо), Post-Delay/Pre-Pan P:$000a5b. Листинг:
  03_listings/dispatch/dsp1_kernel_P0000-0B4D.txt (строки 1956-2200).
- Параметры FX-страницы (слоты 24..31 хоста Y:$0500..): EQF EQG SRR DTIM
  DSND DFB DBAS DWID.

## 2. ТОПОЛОГИЯ (из трассировки эмулятора + листинга, T1)

- Кольцевая линия задержки: X:$0000–$3FFF (L) и Y:$0000–$3FFF (R) —
  16384 слова каждая = 371,5 с? НЕТ: 16384/44100 = 371,5 мс @ 44100 Гц.
- Указатели письма/чтения — 48-бит ячейки L:$C2, L:$C4, L:$C5
  (кернел $0A03/$0A07/$0A0E), пер-трековый контекст, хост-свап.
- Стуaging-буферы текущего блока: X:$40–$61 и X:$62–$83 (2 × 34 слова,
  17 кадров L/R; выбор пары — флаг стерео-обмена r6+$14 ≥ 0.5,
  $0A22–$0A28).
- Таблицы-указатели кадра: X:$E0–$F0 (шаг $50) и X:$90–$A0 (шаг $80
  вверх по X) / Y:$90–$A0 (шаг −$40 вниз от $800000) — дробные позиции
  чтения (tape-style переменная скорость).
- Вход стадии — блок после ампы (X:$22–$32 / X:$34–$44, пишет амп-стейдж
  $0906–$0907).

## 3. ЗАКОН ВРЕМЕНИ ЗАДЕРЖКИ (T1, частично)

- DTIM-индекс читается в $0985: a = (y:(r6+$13) + $8000) >> 16 (!ячейка
  r6+$13 — НЕ r6+$1B; ячейки r6+$18–$1F читает только слоевая машина
  сглаживания $04A8–$04F5 — см. §5).
- Таблицы X:$144BC9[0..127] = (v+1)/256 и X:$144C49[0..127] = 1/(v+1)
  — вычислительные, T0 (дамп получен).
- Темп-скейлинг: $0995 mpyi #>$791FD0 (7938000 = 44100×180) × TEMPO,
  asl #5, произведение с таблицей; кламп $3FF0 ($09A5) и $4000-порог
  ($099A) — ограничение 16368 кадров ≈ размер кольца.
- Гладкость: one-pole $CCCCD/$733333 (0.8/0.45-комбо, $09DB–$09E6) +
  лебедка ±4 кадра/блок ($09BF–$09C9) с шагом $30/$500000 → X:$FE
  (скорость глайда) и L:$FC (текущее время, Q16.16: X:FC = целая часть
  кадров). Измерено: DTIM=0 @120BPM → 63.08 кадра (1.43 мс);
  DTIM=100 → 89.58 кадра (2.03 мс) на первом блоке (A=$599550 в ловушке
  на $09B3). Полная кривая DTIM→кадры — одна сессия.

## 4. ФИДБЕК / SEND / BAS / WID (структурно, T1)

- Фидбек: аккумуляторные пары l:(r1) в петле $0968–$0973 (16 кадров) и
  $0A4E–$0A53; умножитель ветки $0A3E mpysu/dmac (DFB-гейн).
- BAS/WID — фильтры в петле: func_000397 вызовы $0978 (r4=$81) и $0A5A
  (r4=$E1) — 16-таповый процессор с таблицей указателей X:$80–$8F;
  запись коэффициентов Y:$62–$81 ($0A7A–$0A7B, $0AAF–$0AB1).
- SEND: при DSND=0 буферы не получают сигнал (дифф-проверка эмулятора) —
  send-архитектура подтверждена.
- Выход стадии подмешивается к сухому блоку в маршрутизации $0A5B–$0B14;
  финальный выход трека = L-пары X/Y:$00–$1F ($0B45–$0B48).

## 5. SRR (Y:$051A / r6+$1A) — структурно (T1)

- SRR² вычисляется в слоевой машине параметров $04A8–$04F5 ($04C9/$04DE:
  mpy y0,y0 → Y:$4FF, ГЛОБАЛЬНАЯ ячейка) — кривая квадратичная.
- Единственный потребитель Y:$4FF — $0B1E–$0B33 (маршрутизация):
  x0 = DWID (r6+$1F), a = DWID²; y0 = Y:$4FF; b = y0²; a = b×x0 →
  рамп из 16 слов Y:$10–$1F ($0B31–$0B32, mac y0,x0 с y0=$10) —
  пер-кадровый коэффициент следующего блока (децимационное окно SRR×DWID).
- Полный пер-сэмпловый закон прореживания (hold/drop) — следующая сессия.

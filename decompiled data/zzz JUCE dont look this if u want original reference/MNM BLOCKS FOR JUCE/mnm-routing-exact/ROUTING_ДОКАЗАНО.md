# Что доказал дамп P:$0135-$0220

Прислано: строки 000135 - 000220 файла dsp1_kernel_P0000-0B4D.txt.
Это секция ВЫХОДА ГОЛОСА и ПЛАНИРОВЩИКА (не фильтр).

## 1. База страницы голоса (точное совпадение)
00013D: lua (r6-$28),r6   →  r6 = V - $28 = $500
00013E: move #>$100,r7    →  r7 = $100
000142: jmp func_0004a8   →  post-voice

Совпадает с kVoicePageYAddress = 0x000500 из monomachine_engine.cpp.
Раньше это было выводом, теперь — литеральный опкод.

## 2. ADD vs OVERWRITE (литерально)
0001F8: bsclr #$c,a,func_0001e2   ; бит 12 сброшен  → ADD
0001FC: bsset #$c,a,func_0001ec   ; бит 12 установлен → OVERWRITE
То же для битов 13 (buf1) и 14 (buf2).

func_0001e2 (ADD):        buf[i] += src[i], 32 слова
func_0001ec (OVERWRITE):  buf[i]  = src[i], 32 слова

do #<$10 = 16 итераций x 2 слова = 32 слова = 16 стерео кадров.

## 3. НОВОЕ, чего не было в доке: бит-3 гейт
000149: brset #$3,a,func_0001f3

Если бит 3 СБРОШЕН → биты 0/1/2 идут через func_0001e2 (ADD)
безусловно. Перезапись НЕДОСТУПНА.

Если бит 3 УСТАНОВЛЕН → переход в func_0001f3, где биты 12/13/14
выбирают ADD или OVERWRITE для каждого буфера.

То есть INSERT-режим FX-машины (когда её выход ЗАМЕНЯЕТ сухой
сигнал соседа) возможен ТОЛЬКО при установленном бите 3.

## 4. НОВОЕ: коэффициент суммы = ЕДИНИЦА
0001B4: move #>$7fffff,y0

func_0001ad (сумма в основной микс, бит 8):
  buf0[i] = 1.0*buf0[i] + 1.0*buf1[i] + 1.0*buf2[i]

Никакого деления на 3, никакого ослабления. Три дорожки
складываются в buf0 in-place, клип только на записи (SR.SM).

## 5. func_0001c2 — EXT де-интерливинг (бит 10)
n0 = $10 (шаг 16). Две половины источника (r0 и r0+16)
собираются в один интерливированный поток L,R.
Повторяется для buf1 (X:$2CB) и buf2 (X:$2CC).

## 6. Планировщик
000165: add #>$100,b   → шаг голоса $100 (256 слов)
00016E: cmp #<$3,a     → 3 голоса за проход
00016F: beq func_0001a3 → сумма буферов
0001A4: move x0,x:>$4fe → сброс watchdog X:$4FE

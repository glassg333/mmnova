## 1. SEM: Svf → Oberheim 12 dB лестница

**Основание (мануал, p.21):** SEM = *Oberheim 12 dB* 4-pole (LP/BP/HP/BR); MINI = Moog 24 dB;
AUX1/AUX2 = карты. В r16 SEM был Svf — не тот аппарат, тембр «пердит» (комplaint №1).

**Референс (in-scope):** `omega8_decode_for_agents/external_filters/OberhVar.h`
(4× VAOnePole BZT, K-фидбэк, входной tanh). Порт `Oberheim12` в `OmegaEngine.h`
**бит-в-бит сверен с референсом** (t17g: sweep 11 частот × 3 значения reso,
все значения совпадают до последнего знака):

```
r=10 (K=4.00): f=10..300 Hz
  REF:  0.900 0.812 0.527 0.316 0.190 0.118 0.050 0.024 0.006 0.002 0.000
  MINE: 0.900 0.812 0.527 0.316 0.190 0.118 0.050 0.024 0.006 0.002 0.000
```

Ключевые точки порта:
- **Prewarp:** `g = tan(π·f/fs)` — ровно референсный (`wd = 2πf; wa = (2/T)·tan(wdT/2);
  g = waT/2`). В первом варианте r17 π было потеряно («40 Гц» резали на 6.4 Гц,
  найден тестом t17d/e) — исправлено, сверено.
- **K = 4·res** (референс: `K = 4·(r−1)/9`, r 1..10 → K 0..4). r16 SEM (Svf) имел
  K = 6.7·res — другое отображение.
- **Входной tanh (sat=1) + буст (1+K)** с нормализацией α₀ = 1/(1+K·G⁴) — как в
  референсе. Это и держит SEM от свободного самовозбуда (мануал: самоколебания —
  характер НЕ-SEM фильтров).
- OnePole BZT: `vn = (s−z1)·α; out = vn+z1; z1 = vn+out` (a0=1, γ=1, fb=0 — референс).

### Режимы (тапы) — выбор по замеру АЧХ (t17f/t17h/t17i)

| mode | формула | DC | АЧХ @40 Гц (res=1, cut=40) |
|---|---|---|---|
| LP | s4 | 0.98 (tanh-сжатие константы, норма) | 0.898@5 / 0.812@20 / **0.316@40** / 0.050@80 / 0.0004@300 |
| BP | s2 − s3 | 0 | 0.132@5 / **0.508@20** / 0.412@40 / 0.235@80 / 0.0005@2k — пик у cutoff |
| HP | u − s4 | 0 | 0.524@5 / 1.797@20 / 1.316@40 / 1.000@300 — pass 1.0 |
| BR | x − s1 + s2 − s3 + s4 | x (gain 1, offset 0) | 0.988@5 / 0.866@20 / **0.471@40** / 0.753@80 / 0.999@2k — нотч на cutoff |

Отклонённые варианты (замер, t17h): BR вида `u+s4−2sN` дают **пик** на cutoff
(1.67–2.16), а не нотч; линейные комбинации тапов с Σкоэфф=0 не дают глубже 0.31 @fc
— т.к. у «мягкого» Oberheim нет резонансного пика, глубокого нотча из одних тапов не
собрать. `x−(s1−s2)−(s3−s4)` = вычитание 12 dB и 24 dB band-секций = настоящий
4-pole band-reject (нотч −6.5 дБ @res=1), DC точно x (измерено ±2e-14).

Характер reso: крутит скос и подъём низких средов (0.898@5 Гц при K=4 vs 0.699 при K=0),
пика нет — это характер референса (мягкий Oberheim), не дефект порта.

## 2. Мульти-банки (complaint №5 «крашат»)

**Что было:** v10/r16 `loadBank`: чек `total % 176 != 0 → return` — мульти-банк
(10250 B = F0 + 8 + 128×80 + F7) **молча отвергался**: ни звука, ни ошибки в UI.
«Краш» = воспринятый молчаливый отказ (OOB не было — границы проверялись).

**Формат (декодирован по factory-мульти, сверен с hex 6 записей):**
запись 80 B = 8 × [patch 0..127 / 0x7F=пуст, bank 0/1, vol 0..127, pan 0..127 (0x40 центр)]
+ 32 B (ключ/вел — игнорируются) + 16 B имя (ASCII-фильтр).

**Что стало (r17):**
- `OmegaPatch.h::loadBank` парсит мульти (ветка `total == 128*80 && total % kPatchSize != 0`):
  `Bank.isMulti`, `multiParts[128][8]`, `multiNames[128]`. `bank.ok` — и для мульти
  (был затирается `!patches.empty()` — исправлено).
- `PluginProcessor::loadBankBytes`: каждый из 128 слотов = **первый активный part**
  (≠0x7F) **текущего банка**: копируются 160 байт параметров + VOLUME из part-записи +
  8 байт панорамы (kArrPos=144, 0x40 центр, во все 8 голосов). Best effort: part-ссылки
  на другие ROM-банки в VST не резолвятся (других ROM-банков нет) — это ограничение
  архитектуры, задокументировано в тултипе и статус-строке.
- Имя — **прямым memcpy** в raw[160..175]: `Patch::setName` делает `raw.fill(' ')`
  (quirk r5), что затирает только что скопированные 160 байт параметров — проверено
  и обойдено.
- Пустой слот (parts все 0x7F) = тихий плейсхолдер (raw = 0, VOLUME = 0).
- **Статус на LCD 4 с** (раньше отказ молчаливый):
  - `BANK LOADED: 128 patches`
  - `MULTI: first part per slot (8-part ref)`
  - `LOAD FAILED: not an Omega 8 bank`

**Проверка (t17):** `Omega8FactoryMulti.syx` → ok=1, isMulti=1, 128 мульти;
parts 1:1 с hex (multi 0 'WE REMEMBR FRANK': [5 b0 v1 p68] [0x7F] [55 b0 v1 p64] …).
Обычный банк → ok=1, isMulti=0, 128 patches.

## 3. CC98/99 (complaint-связка «BLEND из хоста», отложенный r16)

В мануале не описаны → **best effort**: CC98 = BLEND (morph 0..127), CC99 = preset A.
Raw-store через `apvts.getRawParameterValue(...)->store(...)` — без дребезга/уведомлений,
аудио-тред safe (std::atomic raw-параметров).

## 4. Редактор: раскладка по оригинальной панели (complaint №4)

Референс — физическая панель (VOLUME + GLIDE только) и CODE-панель из omegaCODE-скринов.
10 ручек, **которых на оригинальной панели нет**, перенесены с лицевой панели в нижнюю
GLOBAL-полосу extend-окна (`isGlobalKnob` + strip из 10 putKnob):

`FINE, TUNE, EXT IN, SUB, HPF, HPR, LFO1 D2, LFO1 D3, LFO2 D2, LFO2 D3`

Суб-осциллятор (SUB на/офф) — тумблер `SUB_WAVE` (subLed) остаётся на панели.

## 5. Глифы в попуапах (complaint №7)

Аудит строк v4..v15: 100% ASCII во всех видимых строках; японские иероглифы = либо
старые сборки (≤r10: попуап выводил %/кракозябры из raw-имён), либо фолбэк шрифта
Windows. r17: попуап любой ручки = `textFromValueFunction = "TITLE  значение"` (int) —
только ASCII, ни одного глифа возможен. Область OCT: octLabel остаётся read-only
(на оригинале OCT-ручки нет — это переключатель/ярлык).

## 6. OSC2 — «второй осциллятор не работает» (complaint №3)

Декод (factory-банк, все 128 патчей): OSC2 LEVEL (байт 38) = **0**, WAVE2 (байт 78) = 0x40.
WAVE2 enum: {0=pulse, 2=saw, default=tri} → 0x40 = tri. Т.е. осциллятор 2 **есть,
декодируется и звучит** — просто заводской уровень 0 (дизайн: второй осциллятор
включается пользователем). В r15 это выглядело как мёртвая ручка. r17: тултип на
`OSC2 LEV` объясняет; суб-осциллятор — на тумблере SUB (не путать).

## 7. AUX (complaint №2) и DC (complaint №6) — уже r16

AUX-карты в r16 заменены (AUX1 card0: Svf → OB-Xa 24; CS-80: честная SVF с DC-чистым HP;
мастер 2-порядковый 10 Гц HP вместо 1-полюсного 12 Гц). Пользователь тестировал r15 —
в r15 AUX1 card0 был «пердящим» Svf, CS-80 HP утекал DC. r17 AUX не трогал:
e2E r17 vs r16 по factory-банку — все AUX/MINI/CS-80 патчи **идентичны поцифрово**
(изменение r17 изолировано в SEM).

## 9. Что НЕ менялось в r17

AUX-карты (OB-Xa 24 / OB-X 12 / TB-303), MINI (Moog24), CS-80, master HP, AGC,
VOLUME-кривая, PITCH (FREQ = raw), BLEND (live lerp + enum-snap), latch per-note,
панорама per-voice, арпеджиатор.

вашим билдером. Standalone-сборка движка (заглушка JuceHeader.h) проходит чисто.

# Comb Scanner Lab — 5 страниц DSP в одном плагине

Один VST3, внутри **5 страниц-слотов**. Страница 1 — базовый комб-сканер
(`comb_scanner_variants 1 fav`, модель 01 «Original Hypothesis»), она же сверена
с оригинальной Max-схемой. Остальные страницы — остальные варианты из `other/zigcomb`
и zigzag. Переключение — вкладки, стрелки ← → или кнопки `<` `>`.

Активная страница — обычный параметр хоста `slot`: автоматизируется, сохраняется в проекте,
восстанавливается вместе с пресетом.

**Весь текст в интерфейсе — на английском** (JUCE превращает кириллицу в мусор
в любом VST3-хосте).

## 2. Что исправлено после прослушивания (главное)

- **Убрано сглаживание ручки Delay.** Раньше время задержки «догоняло» ручку за ~35 мс —
  из-за этого звук превращался в «тейп-делей» с питч-глиссандо. Теперь время меняется
  **мгновенно** (рваный характер, как в оригинале), а щелчок прячет короткий кроссфейд ~5 мс
  между старой и новой позицией чтения. Плавные движения (LFO) по-прежнему едут за целью
  точно, без отставания — то есть «живое» модулирование оригинала сохранено.
- **Лимитер в петле каждого комба** (`lab::softLimit`, аналог `omx.peaklim~` из оригинальной
  схемы): комб может заводиться, но не может уйти в разнос и «случайно громко зашуметь».
- **Панорама убрана**: скан перебирает комбы (equal-power кроссфейд), стерео-образ не двигается.
- **Жёсткая защита от NaN/Inf**: если в выходе появляется не-число, движок сам сбрасывается
  и отдаёт тишину — в DAW это не попадёт.
- **zigzag**: Fluctuate теперь 0..0.016 (как в референсном патче), Damping можно увести в 0,
  Decay — до 200.

## 3. Сверка базовой страницы с оригинальной Max-схемой

Референсы: `other/zigcomb/zzz pic ref amxd original code scheme/cs ref` (3 скриншота)
и `zigzag ref` (2 скриншота). Что видно на схеме и как это отражено в коде:

| Оригинальная схема | В коде (страница 1, модель 01) |
|--------------------|-------------------------------|
| 8 блоков `GEN.NESTEDCOMB.gendsp` (8 комбов) | 8 голосов, два делэя + all-pass + dcblock в каждом |
| Ручки патча: GAIN 0.99, UAMP 0.90, PHASE 0.75, DELAY 1 = 115 мс, DELAY 2 = 500 мс | те же дефолты: gain 0.99, damp 0.90, phase 0.75, delay1 115 мс, delay2 500 мс |
| Множители задержки: ×0.33, ×0.5, ×0.66, ×0.9, ×1.11, ×1.45, ×2.22, ×3.33 | ровно тот же набор `ratios` |
| `scanning-multiplexer` (скан = выбор/кроссфейд между комбами) | кроссфейд между двумя соседними комбами, equal-power, сглаживание 25 мс |
| На выходе КАЖДОГО комба `omx.peaklim~ threshold 24 ingain 24 outgain −7` | мягкий лимитер в петле (`softLimit(x, 0.9)`) + `tanh` на выходе |
| `plugin~` → `0.89/0.9/0.75` → комбы, `plugout~` на выходе | gain → фидбек (0.55 + 0.435·gain), сухой 0.12, выход ×4.5 с `tanh` |
| Слайдер SCAN | ручка Scan (0..1) |

Вывод: DSP модели 01 структурно совпадает со схемой (соотношения, базовая задержка, глубина
фидбека, all-pass, скан-мультиплексор). Единственное, чего в коде не было, а в схеме есть —
**лимитер на выходе каждого комба**; он добавлен. Панорама, которая была в коде, — артефакт
именно кода (в схеме `scanning-multiplexer` панорамой не управляет), поэтому убрана.

Про «стретч»: по промпту из `zzzz audiotest real amxd reference` — «ручка скан сильнее всего
даёт эффект будто что-то стретчится между комбами, чем сильнее её дергать, тем сильнее эффект
псевдостретча» — это свойство самого скана: он переключает комбы с разными ratio, и звук
«растягивается». Отдельной модуляции задержек для этого не требуется.

## 4. Общие ручки (внизу, не зависят от страницы)

- **Dry/Wet** — `1.0` (по умолчанию) = на выход идёт только движок, как в исходных пресетах.
- **Output** — общая громкость плагина, дБ.
- **Scan Rate / Scan Depth** — встроенная LFO на ручку `Scan` (`depth = 0` — скан статичный).
- **Trim** — своя ручка на каждой странице, ±24 дБ: подровнять громкость варианта для честного A/B.
- **Reset tails on page switch** — при уходе/приходе страницы состояние движка очищается.
- **Copy page to all** — переносит ручки страницы в одноимённые ручки остальных.
- **Reset page** — возвращает ручки страницы к значениям по умолчанию.

Переключение страниц идёт через короткий фейд (6 мс уход, 25 мс приход) — щелчков нет.

## 5. Сборка в Visual Studio 2026

Нужно: VS 2026 с workload **Desktop development with C++** и x64.

### Способ A — Projucer (как в Monomachine-Nova), основной

В корне проекта лежит **`CombScannerLab.jucer`** — Projucer-проект по образцу
`Monomachine Nova FX.jucer` из 1.6.27 stable: C++17, VST3, x64, Debug/Release, `/utf-8`,
те же 13 модулей JUCE, тот же VS2022-экспортёр и цель **`CombScannerLab - VST3`**.

1. Открой `CombScannerLab.jucer` в Projucer → **Save and open in IDE**.
2. В VS выбери **Release | x64** и собери проект `CombScannerLab - VST3`.

Или одной командой (скрипт сам найдёт Projucer и MSBuild):

```powershell
powershell -ExecutionPolicy Bypass -File tools\BuildProjucer.ps1
# либо двойной щелчок по Build.cmd
```

Готовый плагин:

```
Builds\VisualStudio2022\x64\Release\VST3\CombScannerLab.vst3
```

**Про Ableton, который не просканировал плагин.** VST3-бандл обязан содержать
`Contents\x86_64-win\CombScannerLab.vst3` (DLL) и `Contents\Resources\moduleinfo.json` (манифест).
Без манифеста Ableton часто просто не видит плагин. Манифест генерирует отдельная цель
`CombScannerLab - VST3 Manifest Helper`; скрипт `BuildProjucer.ps1` сам проверяет бандл,
при необходимости собирает helper и создаёт `moduleinfo.json`. И копируй в папку VST3
**всю папку `CombScannerLab.vst3` целиком**, а не один файл внутри.

### Способ B — CMake (запасной, без Projucer)

```powershell
powershell -ExecutionPolicy Bypass -File tools\BuildCMake.ps1
cmake --preset windows-vs2026
cmake --build --preset windows-vs2026-release
```

Готовое лежит в `build/vs2026/CombScannerLab_artefacts/Release/VST3/…`.
По умолчанию скачивается JUCE 8.0.15 (в 8.0.6 проверка `CMAKE_C_COMPILE_OBJECT`
конфликтует с CMake 4.x из VS 2026; в 8.0.13+ убрано). Вернуть 8.0.6: `-DCOMBLAB_JUCE_TAG=8.0.6`.

## 7. Что проверено, а что нет

Проверено здесь (Linux, GCC 14):

- все 5 движков + реестр компилируются; файлы с JUCE (`PluginProcessor.cpp`, `PluginEditor.cpp`,
  `ui/SlotPage.cpp`) собираются с реальными заголовками JUCE 8.0.6 в C++17;
- **фаззинг под AddressSanitizer + UBSan**: случайное кручение всех ручек (включая выход за
  диапазон), смена моделей, reset на ходу, блоки 32/64/512/1024, 44.1/48 кГц, моно/стерео —
  ноль ошибок, ноль NaN/Inf;
- **тест де-кликера**: скачок — мгновенный, кроссфейд ровно 5 мс, мелкие правки не запускают
  кроссфейд, прерывание кроссфейда непрерывно (без разрыва);
- **«рваность»**: после поворота Delay 60 → 300 мс в эхо-сетке немедленно появляется новое
  время (≈99 мс у голоса с ratio 0.33) — никакого плавного глиссандо;
- **клики**: резкий поворот Delay даёт разрыв волны 0.9–1.1× от естественного — то есть щелчка нет;
- **панорама**: корреляция L/R = 1.0000 на всех комб-страницах при любом Scan;
- **«не зашуметь»**: при максимальном фидбеке и минимальных задержках пик ≤ 1.0,
  хвост затухает в ноль, NaN нет;
- все `#include` разрешаются относительно своих папок (ошибки C1083 не будет).

Не проверено (нужно один раз прогнать у себя):

- сама сборка MSBuild/VS 2026 и линковка VST3 — в песочнице Windows нет;
- генерация `moduleinfo.json` через VST3 Manifest Helper — логика добавлена по исходникам
  Projucer, на живой Windows не запускалась.

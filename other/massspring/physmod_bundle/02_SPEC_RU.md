## 0. Резюме (one-pager)

Строим **плагин-синтезатор физического моделирования** (VST3) на ядрах **mass-spring-damper** (масса-пружина-демпфер, далее MSD): пользователь **рисует в 2D** резонаторы (струны, мембраны, пластины), места пересечения фигур сшиваются в общие сетки масс с настраиваемым материалом и натяжением; возбуждение — **смычок (bow), молоточек, шум, Karplus-Strong/волноводы, FM-голос или сторонний аудиовход** — подключается к любой точке сети; все резонаторы **звенят друг о друга** (односторонние контакты → инхармоническая расстройка и нелинейное взаимодействие). Любые движения — тянуть массу, крутить ручку, вести смычком — можно **записать и проигрывать как жест-пресет**, а плагином играть с клавиатуры по MIDI/MPE, как обычным инструментом.

Ключевые отличия от Anukari (главный коммерческий референс): (1) **рисование 2D-фигур** вместо расстановки отдельных масс и пружин — фигура сама растеризуется в сетку; (2) **горячая замена эксайтеров** (FM/waveguide/гибриды) в слоты возбуждения — по образцу Logic Sculpture; (3) **запись жестов** как первоклассный объект пресета. Ядро — классический mass-interaction формализм CORDIS-ANIMA (Cadoz/Luciani/Florens) в современной реализации: полунеявный интегратор с субшагами, пассивный энергетический аудит, контакты по схеме energy-quadratisation (Ducceschi/Bilbao/Willemsen/Serafin, JASA 2021, PDF в `papers/`), bow с elasto-plastic трением.

## 1. Vision, цели, ограничения

### 1.1 Что это и для кого

Инструмент для звуковых дизайнеров и экспериментальных музыкантов, которым нужен «живой» органический звук физических объектов, но которых не устраивает жёсткость готовых физмод-плагинов (Tension, Sculpture, Chromaphone) и сложность сред вроде GENESIS/mi-gen. Пользовательский сценарий-мечта: *«нарисовал три струны и тарелку, стянул их узлом, повёл смычком по одной — все три зазвенели по-разному; записал это движение ручкой натяжения; теперь играю аккордами, и каждый аккорд оживляет записанный жест»*.

### 1.2 Принципы проекта (в порядке приоритета)

1. **Стабильность прежде всего.** Сеть никогда не должна «взрываться»: пассивный аудит энергии + предохранительный демпфер. Плата за это — явные ограничения материалов (см. §4.2).
2. **Модульность.** Эксайтер, резонатор, модулятор, рекордер — независимые подсистемы за чистыми интерфейсами. Ядро физики не знает ни про JUCE, ни про UI.
3. **«Нарисовал = звучит».** Ни одна операция рисования не должна требовать компиляции, перезапуска аудио или ручного решения СЛАУ — перестройка сети происходит между аудио-блоками.
4. **Честная физика как дефолт, артизм как оверрайд.** Все параметры материалов — физические (k, c, m, натяжение), но любой из них можно модулировать не-физически (LFO, жест, MIDI).

### 1.3 Нефункциональные требования

| Требование | Значение |
|---|---|
| Форматы | VST3 обязательно; CLAP/AU — сразу закладываем в абстракцию |
| Платформы | Windows x64, macOS universal (Intel+ARM); Linux — опционально |
| Частота сэмплирования | 44.1–192 кГц, внутренние субшаги физики независимо от хоста |
| Буфер | 32–1024 сэмплов, полная независимость звука от размера буфера |
| Задержка | 0 (прямая симуляция в аудиопотоке); без lookahead в MVP |
| CPU | типичная сцена (2–3 сетки по ~500–1500 масс) ≤ 10–15% ядра на 3.5 ГГц |
| MIDI | MIDI 1.0 + MPE; MIDI 2.0 — опционально |
| Язык UI | EN (v1), архитектура строк — i18n-ready |

## 2. Глоссарий

- **Масса (mass)** — материальная точка с позиция/скорость/сила; атом симуляции. **Ground** — фиксированная масса-якорь.
- **Взаимодействие (interaction)** — сила, вычисляемая по состоянию пары (или более) масс: пружина-демпфер, контакт, bow, «жёсткая связь».
- **Сеть / модель (network, model)** — граф масс + взаимодействий, вычисляемый за субшаг.
- **Резонатор** — фигура на канвасе, растеризованная в сеть (струна, мембрана, пластина).
- **Эксайтер (exciter)** — источник возбуждения: шум, KS-волновод, FM-голос, аудиовход, физический драйвер (bow/hammer).
- **Драйвер-точка (driver point)** — масса сети, к которой приложена внешняя сила эксайтера.
- **Пикап (pickup)** — точка съёма звука: позиция/скорость/сила массы → аудиовыход.
- **Сетка (grid)** — 2D-решётка масс-пружин, порождённая растеризацией фигуры.
- **Материал** — набор {k, c, m·плотность, nonlinearity, rest-tension} для рёбер/узлов региона.
- **Жест (gesture)** — записанный временной ряд состояний (позиции masses, параметры) с метаданными лупа.
- **Сцена (scene)** — полный документ: сети + эксайтеры + модуляции + жесты + пиковые настройки. Сериализуется в пресет.

```
                │  телеметрия масс вверх)                │
   ┌────────────▼────────────────────────────────────────▼──────────────┐
   │  msd::engine (audio thread, 0 alloc)                               │
   │  ┌────────────┐ ┌─────────────┐ ┌──────────┐ ┌──────────────────┐  │
   │  │ SceneGraph │ │ PhysicsCore │ │ Exciters │ │ Modulators/Rec   │  │
   │  │ (immutable │ │ integrator, │ │ noise/KS/│ │ gesture recorder │  │
   │  │  snapshots)│ │ contacts,bow│ │ FM/audio │ │ drawable LFOs    │  │
   │  └────────────┘ └─────────────┘ └──────────┘ └──────────────────┘  │
   └────────────────────────────────────────────────────────────────────┘
   msd::core (pure C++20, без JUCE)  ← тестируется вне плагина
```

**Три потока:** (1) *audio thread* — только физика и DSP, ноль аллокаций/локов/системных вызовов; (2) *message/UI thread* — канвас, редактор; (3) *background* — сериализация пресетов, растеризация сложных фигур. Связь: SPSC-очередь команд (UI → audio: «применить новую сцену», «изменить k»), lock-free телеметрия (audio → UI: позиции подмножества масс для визуализации, с прореживанием ~30 Гц).

### 3.2 Разделение на библиотеки

- **`msd::core`** — типы (Mass, Interaction, Network), интегратор, контакты, bow, растеризатор, формат сцены (JSON↔binary). Без JUCE. Это позволяет гонять юнит-тесты и CLI-рендерер без DAW и портировать ядро (например, в CLAP- или standalone-сборку) без изменений.
- **`msd::dsp`** — эксайтеры и гибриды (волноводы, FM), зависят только от стандартной библиотеки.
- **`msd::plugin`** — тонкий JUCE-слой: AudioProcessor, APVTS-схема, сохранение состояния.
- **`msd::ui`** — JUCE-компоненты канваса; может использовать `foleys_gui_magic` для быстрой обвязки (см. 03_RESEARCH_LINKS.md).

Строительные блоки инфраструктуры берем из проверенных шаблонов: **pamplejuce** (CMake + Catch2 + pluginval + CI) как каркас репозитория, **chowdsp_utils** для утилит DSP и lock-free структур.

## 4. Физическое ядро

### 4.1 Формализм: mass-interaction сети (CORDIS-ANIMA)

Берём за основу формализм CORDIS-ANIMA (Cadoz, Luciani, Florens; ACROE/GENESIS — см. `papers/` и 03_RESEARCH_LINKS.md): мир = набор **материальных элементов** (точечные массы Mᵢ с переменными {xᵢ, vᵢ}) и **связей (links)**, задающих силу как функцию состояния. Уравнение движения сети:

```
M·ẍ = Σᵢ F_links(x, ẋ, t) + F_external(u)
```

Это обобщение MSD-систем; ключевое свойство — **модульность сил**: любая новая физика (контакт, bow, магнит) — это новый тип связи с локальными правилами, не требующий переписывания интегратора. Таксон элементарных модулей подтверждён 40-летней практикой (GENESIS → miPhysics → mi-gen): `Mass`, `Ground`, `SpringDamper`, `NonlinearSpring`, `Contact`, `Bow`, `Driver` (вход силы/позиции), `Output` (съём). Таксономия miPhysics (`Mass3D`, `SpringDamper3D`, `Driver3D`…) — прямой образец API (концептуально; код GPL — не копируем, см. §11).

**Соглашение о размерности:** MVP — строго 2D (x, y). 3D — расширение типов, не архитектуры (компоненты уже сейчас не должны предполагать `float x, y` жёстко — используем `Vec2`/`Vec3` как template-параметр).

### 4.2 Интегратор: выбор схемы

Кандидаты и компромисс (детальное обоснование — в Bilbao, *Numerical Sound Synthesis*, гл.1 PDF в `papers/`):

| Схема | Стабильность | Стоимость | Качество | Вердикт |
|---|---|---|---|---|
| Явный Эйлер | ❌ хрупок | мин | низк | только для валидации в тестах |
| **Полунеявный (симплектический) Эйлер** | ✅ при h < 2/ω_max | мин (SIMD-friendly) | хорошее, лёгкий дрейф энергии | **базовая схема MVP** |
| Билинейный/Tustin (CORDIS-ANIMA «T-метод») | ✅ безусловно (линейные сети), пассивен | решение СЛАУ / итерации при контактах | отличное | цель для «качественного» режима v2 |
| Implicit midpoint / Newmark | ✅ | якобиан + спарс-решатель | отличное | опция для жёстких сетей |

**Решение для v1 — полунеявный Эйлер с субшагами:**

```
на каждый сэмпл (T = 1/fs):
  для s = 1..S (S субшагов, h = T/S):        // S=2..8, настраивается сценой
    F = accumulate_forces(x, v)               // все связи, SoA-массивы
    v += (F / m) * h
    v *= global_energy_safety_damp            // предохранитель (обычно 1.0)
    x += v * h
```

- Частотный потолок сети ω_max = π·fs/S — субшаги напрямую покупают верхний диапазон и запас стабильности; S хранится в сцене и подбирается по материалам (жёсткая сталь → S=8).
- **Энергетический аудит:** раз в блок считается E = Σ(½mv² + ½k·Δx²); если рост > порога — включается мягкий демпфер на 1 блок (анти-взрыв, «никогда не падает» — принцип №1). В debug-сборке аудит пишет трейс для тестов сходимости.
- **Ограничение материалов:** UI не даёт выставить k/m выше ω_max схемы (подсказка «повысьте субшаги»), вместо молчаливого взрыва.

### 4.3 Контакты: струны звенят друг о друга

Требование пользователя: «струны должны инхармонически звенеть друг об друга». Это односторонние контакты (unilateral contact): сила только при сближении < r₀, с жёстким отталкиванием и ударным демпфированием.

**Две реализации (миграция A → B):**

- **A. Penalty contact (MVP):** `F = k_c·penetration + c_c·v_rel·(penetration>0)`. Дёшево, звучит «щёлкающе-звенящее», но при жёстком k_c требует мелких субшагов и склонно к **chattering** (дребезгу прилипание-отлипание). Анти-chattering: минимальная толщина контакта (сглаженный порог, smoothstep на 2–3 узла) + контактное демпфирование не ниже критического/10.
- **B. Energy-quadratisation linearly-implicit (Ducceschi–Bilbao–Willemsen–Serafin, JASA 2021 — PDF `papers/2021_jasa_collision-schemes-musical-acoustics.pdf`):** контактная энергия квадратизуется → неявная схема решается **без итераций**, бесконечно жёсткий барьер, консервативность/пассивность гарантированы. Это наш «нобелевский» уровень качества для v2 и для режимов «стальные струны».

**Поиск пар:** пространственный хеш (uniform grid по AABB масс, rebuild каждый субшаг из дешёвых операций) — O(n) вместо O(n²). Коллизии типов: масса-масса (струна-струна, струна-пластина), масса-барьер (гриф/лад — fixed points), самоконтакт внутри одной сети (опция, дорого — только для явно помеченных регионов).

### 4.4 Bow (смычок)

Stick-slip возбуждение — сердце «играбельности». Модель:

- **Точка смычка** движется вдоль траектории (мышью/MIDI-осью) со скоростью v_bow, давит с силой/нормализованным давлением p_bow на массу струны (или на сегмент из 2–3 масс — «ширина смычка»).
- **Трение:** классика — нелинейная кривая f(v_rel) (экспоненциальная, McIntyre–Schumacher–Woodhouse); рекомендация v1 — **elasto-plastic модель** (Chatziioannou, van Walstijn и наследники; актуальная пассивная схема 2025 г. реализована в `wasilakis/the_bowed_string`, см. 03): упругая деформация «щетины» в stick-фазе (это устраняет дребезг и даёт мягкую атаку) + пластическое скольжение в slip-фазе. Схема должна сохранять пассивность (см. repo report).
- **Режим Helmholtz как целевой:** юнит-тест — при «правильных» v_bow/p_bow и линейной струне модель должна самозапускаться в режим Хельмгольца (пила с двумя изломами) — это маркер корректной bow-физики (проверка по спектру: доминирует f₀, шум −20 дБ).
- MPE-маппинг по умолчанию: `pitch bend` → натяжение/позиция вилки смычка, `pressure (channel aftertouch)` → p_bow, `CC1` → v_bow, `note-on velocity` → скорость атаки.

### 4.5 Гибрид «сетка + волновод» (масштабирование вверх по частоте)

Полная сетка масс на струну с f₀=880 Гц и 30 гармониками требует fs·S/2 > 2·f₀·30… дорого. Поэтому **гибридная струна**: зоны взаимодействия (концы, область смычка, точки контакта) — локальные сетки масс; середина — дешёвый волновод (delay line + фильтры дисперсии/потерь, Extended Karplus-Strong с allpass-инхармоничностью), сшитые импедансно. Прецедент — гибриды mass-interaction × waveguide в Faust PM (Leonard и др., HAL 04869101, в списке ручной загрузки). В v1 допускаем упрощение: струна = либо вся сетка (низкие ноты, коллизии), либо весь волновод (высокие ноты), выбор за пользователем с авто-подсказкой.

### 4.6 Растеризация фигур → сети (сердце UI-физики)

Пайплайн «нарисовал эллипс/кривую → получил резонатор»:

1. **Ввод:** пользователь рисует замкнутую/открытую фигуру (полилиния, эллипс, прямоугольник, сплайн). UI хранит векторную геометрию (источник истины для перерисовки).
2. **Дискретизация:** параметризация контура → равномерная выборка с шагом Δ (пикс→мировые единицы); внутренность замкнутой фигуры заливается решёткой (шаг Δ, jitter < 10% против регулярных артефактов стоячих волн) → узлы = массы (m из плотности материала × площадь ячейки), рёбра соседних узлов = spring-damper (k, c из материала + преднапряжение rest-length = Δ·(1−tension) для сжатой «струны»/натянутой мембраны).
3. **Материалы по регионам:** фигура несёт материал; **зона пересечения двух фигур** (проверка перекрытия ячеек) сшивается: либо weld (общие узлы — «склеены смолой»), либо контакт (две сетки трутся/звенят — по переключателю на канвасе). Материал пересечения наследует «жёсткий» из двух или задаётся явно третьим («клей», «подшипник»).
4. **Инкрементальная перестройка:** правки (потянуть вершину, поменять материал региона) пересчитывают только затронутые ячейки; полная пересборка ≤ 10 мс для сетки 64×64 — укладывается в перерыв между аудио-блоками (swap immutable snapshot сцены).
5. **Маршинг для заливки** — marching squares (референс алгоритмов — классика, реализация своя, ~300 строк); никакого внешнего геометрического движка в MVP.

### 4.7 Материалы (стартовая библиотека)

| Материал | k (отн.) | c (отн.) | nonlinearity | Звучание |
|---|---|---|---|---|
| Steel string | 1.0 | 0.02 | слабая геометр. | яркое, долгое, «сталь» |
| Nylon string | 0.35 | 0.05 | мягкая | тёплое, быстрее гаснет |
| Membrane (skin) | 0.5 | 0.08 | средняя | барабанное |
| Wood plate | 0.8 | 0.04 | анизотропия (kx≠ky) | дековое, «дерево» |
| Glass | 1.4 | 0.005 | сильная | хрупкое, звенящее, коллизии щёлкают |
| Gum (каучук) | 0.1 | 0.2 | мягкая | резиновое, басовое |

Нелинейность = геометрическое ужесточение (пружина с членом k₃·Δx³, «tension modulation») — источник инхармоничности растущих парциалов. Анизотропия — раздельные kx/ky для «дерева».

## 5. Эксайтеры и сигнальная цепь

### 5.1 Слоты эксайтеров (горячая замена)

Требование «источником может быть FM, вейвгайд, гибрид вместо обычного шума» реализуется как **слоты возбуждения** по образцу Logic Sculpture (exciter chain → material → pickup chain):

| Слот | Реализация v1 | Заметки |
|---|---|---|
| **Noise burst** | фильтрованный шум × огибающая → force-инъекция | дефолт; форма огибающей рисуется |
| **KS / Waveguide pluck** | delay line + лоу-пасс + allpass-дисперсия (EKS) | питч-синхронный; инхармоничность ручкой |
| **FM voice** | 2-op/4-op FM → force/velocity эксайтера | «синт Exciter»: модуляция силы удара |
| **Audio input** | sidechain-канал хоста → force | физмод-эффект: гитара/DAW feeds сеть |
| **Hammer** | физическая масса с пружиной к точке удара | MIDI velocity → масса/скорость |
| **Bow** | §4.4 | физический, непрерывный |
| **Hybrid (сеть→сеть)** | выход-пикап одной сети = драйвер другой | «метаболизм» сцены; поздний MVP |

Каждый эксайтер компилируется в **драйвер-силу** F(t), приложенную к выбранным массам (мультиточка — «расческа» из N точек). Эксайтеры живут в `msd::dsp`, интерфейс один: `prepare(fs)`, `process(block) → ForceEvents`, никакой зависимости от типа резонатора.

### 5.2 Пикапы и вывод

Съём звука — с масс-точек: `y = a·position + b·velocity + c·force_local` (микс «микрофон/пьезо/магнит»); несколько пикапов → микшер/панорама. Дополнительно — **body IR**: опциональная свёртка с импульсным откликом отдельной маленькой «деки»-сети (прецедент PhyVerb). Мастер-цепь v1: picker mix → мягкий limiter (анти-клип из-за контактных щелчков) → output.

## 6. UI: рисование, модуляторы, канвас

### 6.1 Два слоя канваса

**Слой 1 — физический мир (2D):** инструменты: `draw` (фигура→резонатор), `spring` (связь вручную), `pin` (ground), `bow`, `hammer`, `cut`, `select/drag` (живое перетаскивание масс = жест-вход). Фигуры раскрашиваются материалом; зона пересечения подсвечивается при рисовании превью сшивки. Гравитация — выключена по умолчанию (физмод-музыка ≠ песочница), глобальный тумблер.

**Слой 2 — модуляторный граф (node editor):** узлы-модуляторы (LFO, drawable curve, envelope follower, MIDI-CC, gesture playback, макро-ручки) соединяются с параметрами физики (k, c, tension, bow.x/bow.p, материал-морф) и друг с другом. Реализация — перенос паттернов `imgui-node-editor`/`imnodes` (MIT — можно смотреть код и UX) на JUCE Graphics; типизированные сокеты по `ImNodeFlow` (параметры vs аудио-сигналы vs триггеры).

### 6.2 Drawable-модуляторы (референс Vital)

Кривые LFO/огибающих **рисуются мышью** (сплайн, snap по сетке, до 128 точек), режимы: луп (sync по темпу), one-shot, loop со сглаживанием. Vital (GPL, см. 03) — эталон UX: панель точек, tension-ручки на узлах, перетаскивание сразу на параметр с выбором модуляционного слота. Наша специфика: модуляторы могут также **рисовать траекторию движения для bow/массы** («нарисуй росчерк смычка» → gesture clip).

### 6.3 Живая интерактивность

- Перетаскивание любой массы мышью **во время звучания** — позиция тянется пружиной-рукой (не телепорт: force-based grab, чтобы не вносить энергию скачком).
- Ручки-макросы: до 8 пользовательских макросов, каждый = маппинг на N параметров с кривыми; они же — точки хост-автоматизации.
- Zoom/pan, привязка к сетке (опц.), undo/redo (command stack над сценой, снапшоты секций).

## 7. Запись жестов, MIDI, пресеты

### 7.1 Gesture Recorder

- **Что пишем:** непрерывные каналы (позиции выбранных масс/смычка, значения ручек, сила grab) с частотой ~200–1000 Гц; события (удары молоточком, note-on) — в событийную дорожку.
- **Как играем:** REC (arm каналов) → кольцевой буфер по выбору (свободный/тактовый), STOP → клип. Клип: loop/one-shot, tempo-sync, quantize-опция, punch-перезапись, скорость 0.25–4×, reverse. Гесты можно назначать на ноты/CC — «пресет = инструмент: держишь ноту → играет записанный жест».
- **Полировка (v2):** Gesture Variation Follower (ofxGVF, LGPL — подключать отдельно/линковкой, не встраивать в закрытые части) — темп-следящий реплей с вариациями: записал 3 варианта росчерка → жест «живёт» и следует за игрой.

### 7.2 MIDI/MPE

Полифония через **клоны сети** (голос = своя копия сцены с собственным seed возбуждения; лимит по CPU-бюджету, voice stealing) или **моно-инструмент с мультиточечными эксайтерами** (MPE-каналы управляют отдельными эксайтерами одной большой сети — режим «инструмент-оркестр»). Выбор режима — свойство сцены. MPE: note → выбор голоса/эксайтера, pitch bend → tension, pressure → bow pressure/hammer depth, slide → bow speed.

### 7.3 Формат пресета

`preset.json` (версионируемая схема) + бинарные блобы (записанные жесты, wavetables эксайтеров): сцена (фигуры, материалы, сети, эксайтеры, пикапы), модуляции, жесты, маппинги макросов. Хост-автоматизация — только через плоский список APVTS-параметров (макросы + ключевые физ. ручки); геометрия через автоматизацию не меняется (снапшоты сцен — только пресетами).

## 8. JUCE-интеграция

- **AudioProcessor:** `processBlock` — детерминированный пайплайн: MIDI → модуляторы → эксайтеры → S субшагов физики на сэмпл → пикапы → лимитер. Никаких аллокаций: вся память сцены пре-аллоцирована при загрузке (rebuild = copy-into-pool + atomic swap указателя).
- **APVTS:** схема параметров генерируется кодом из реестра (`ParameterRegistry`: id, диапазон, skew, юнит); `getStateInformation` — JSON-пресет (см. §7.3).
- **Состояние при смене fs/буфера:** пересчёт h, субшагов, фильтров эксайтеров; сцена не пересоздаётся.
- **Каркас репозитория:** pamplejuce (CMake presets, Catch2, pluginval в CI, notarization-скрипты).
- **Стабильность:** watchdog голоса: если сеть выдала NaN/Inf — мгновенный full-reset сети + паник-заглушение блока (никогда не убиваем хост).

## 9. Производительность и бюджеты

| Сценарий | Бюджет (одно ядро 3.5 ГГц, 48 кГц) |
|---|---|
| 3 струны-сетки по 400 масс + контакты, S=4 | ≤ 8% |
| Мембрана 64×64 (4096 масс) + 2 струны, S=4 | ≤ 20% |
| Полифония 8 × струна-волновод | ≤ 10% |

Приёмы: SoA-массивы (x,y,vx,vy отдельно) + SIMD ((`std::span` + ручная векторизация accumulate_forces); контакты через spatial hash; LOD: несонорящие регионы сети с амплитудой < −90 дБ «спят» (пропуск сил при |x−x_rest|<ε и |v|<ε, пробуждение по событию); профилирование — Tracy profiler в debug-сборке.

## 11. Риски и анти-паттерны

1. **Взрыв интегратора** (жёсткие материалы × большие субшаги) → материал-лимиты в UI + энергетический демпфер (§4.2) + паник-ресет (§8). Тест-фаззинг случайных сцен в CI.
2. **Chattering контактов** → smoothstep-порог + контактное демпфирование; миграция на схему B.
3. **GPL-заражение:** miPhysics (GPL-3), tao (GPL-2), BespokeSynth/Vital/Rack (GPL) — **только изучение концептов, никаких копирований кода** в наш код (если итоговая лицензия не GPL — см. {{HOLE-05}}). Разрешено копировать: MIT/BSD (ModularVST, FastBowedString, imgui-node-editor, pamplejuce, chowdsp…). Никаких «чистых комнат» не нужно, если не смотрим GPL-код строка-в-строку — но безопаснее писать по статьям (CORDIS-ANIMA формализм публичен) и MIT-кодам.
4. **Audio-thread джиттер** от UI-команд → только SPSC-команды + immutable snapshots; запрет на std::mutex в audio-path (проверка код-ревью + флаг `-Wthread-safety`).
5. **Пересборка сцены на слуху** → rebuild в background-потоке, swap на границе блока; геометрические правки квантуются к границе блока.
6. **Скоуп-крип** (3D, гравитация, визуальные игры) → всё «потом»; MVP = 2D, звук, жесты.
7. **Переусложнение пресета** (геометрия как автоматизация) → геометрия не автоматизируется; макросы — да.

## 12. Тестирование и валидация

- **Юнит (msd::core):** (a) свободная струна: моды сходятся к аналитическим fₙ ∝ n·(1+инхармоничность) в пределах 1%; (b) энергосохранение/диссипация монотонна без возбуждения; (c) контакт: ни одного проникновения > ε за 10⁶ шагов; (d) bow: Helmholtz-детектор (см. §4.4); (e) сериализация: round-trip пресета бит-в-бит.
- **Фаззинг:** генератор случайных сцен → 10 мин прогона на NaN/энерговзрыв (ночной CI).
- **Плагин:** pluginval strict-10; latency/блок-инвариантность (одинаковый рендер при 64/512/1024 буфере); soak-тест 8 часов в хосте.
- **Психоакустика:** A/B-сеты против Sculpture (bow+body), Tension (стринги), Anukari (кластеры масс) — критерий «не хуже по шартам из 20 слепых сравнений» для M4.

# Физмод live — Этап 1 (GUI-прототип: рисуй струны, води смычок, крути ручки)

Живой прототип физмод-синтезатора на Python: MD-струны (цепочка масса-пружина),
смычок MSW (термальное трение), контакты струна-струна (Hunt–Crossley), макро-ручка
**Regime R** (скрежет → чистый бас). Всё это — ядро из валидированного Этапа 0
(stage0_proto.py), пересобранное в батч-движок с **guards**: взрывы невозможны —
проблемная струна замораживается, а в лог пишется причина.

Главная фича для отладки: **полный журнал операций** — спавн струны печатает все
физические параметры и запасы устойчивости, любой guard пишет что/где/почему.
Больше не нужно гадать «из-за чего крашнулось».

---

## Установка

Нужен Python 3.10–3.13 (Windows: ставится с python.org, галочка «tcl/tk» включена по умолчанию).

```
py -m pip install numpy sounddevice numba
```

- `numba` — **очень рекомендован**: JIT-ядро ускоряет физику в ~30 раз
  (RT-фактор 0.22 против 7). Без него тоже работает (медленный numpy-путь),
  тогда в меню ОВЕРСЭМПЛИНГ поставь **2**.
- `sounddevice` — живой звук. Если аудио-устройства нет, программа запустится
  в визуальном режиме (рендер в WAV работает всегда).

Запуск: `py bow_live.py` (или двойной клик по `run.bat`).

## Быстрый старт (30 секунд)

1. Запусти — на сцене уже две струны (110 и 167.9 Гц, зазор 4.5 мм).
2. Режим **2 СМЫЧОК**: зажми ЛКМ на верхней струне и веди вдоль неё — пойдёт звук.
3. Ручка **Regime R** влево (0–1.5) — скрежет, вправо (3–4.5) — чистый бас.
4. Режим **1 РИСОВАТЬ**: нарисуй ЛКМ ещё струны близко к существующим (2–4 мм)
   — они будут звенеть друг о друга (инхармонический звон через контакт).
5. Режим **3 ЩИПОК** — клик по струне; **4 ЛАСТИК** — клик удаляет струну.

## Управление

| Действие | Как |
|---|---|
| Режимы | кнопки 1–4 или клавиши **1..4** |
| Нарисовать струну | режим 1: зажать ЛКМ, вести, отпустить (мин. 4 см) |
| Смычок | режим 2: зажать ЛКМ около струны и вести; **Esc** — отпустить |
| Щипок | режим 3: клик по струне |
| Удалить струну | режим 4: клик по струне |
| Ручки | тянуть вертикально / колесо мыши; двойной клик — сброс |
| Аварийный сброс | кнопка **PANIC** (обнуляет все скорости) |
| Рендер 8 с в WAV | кнопка «Рендер 8 с → WAV» (файл появится рядом со скриптом) |

## Ручки

| Ручка | Что делает |
|---|---|
| **Regime R** | макро-морфинг смычка: 0–1.5 скрежет (медленно, сильный прижим, шум), 3–4.5 чистый бас (быстрый Хельмгольц), 6 — снова скрежет |
| **Натяжение f0** | частота **новых** струн (55–660 Гц); «f0 ко всем» применяет ко всем |
| **Скорость ×** / **Напор ×** | тримы скорости смычка и прижима поверх расписания Regime |
| **Зазор, мм** | зазор контакта между струнами: меньше → чаще звенят друг о друга |
| **Контакт KC** | жёсткость столкновений (3e4–5e5); капится guard'ом по устойчивости |
| **Воздух σ** | общие потери (сустейн): 0 = звенит долго, 1.5 = глухо |
| **Внутр. демпф ×1e-3** | внутренние потери материала (высокие частоты гаснут быстрее) |
| **Громкость** | мастер (перегруз не страшен: soft-clip tanh) |
| **ОВЕРСЭМПЛИНГ** | 4 = точнее смычок (по умолчанию), 2 = легче для CPU |

## Лог — как читать

Живёт внизу окна и пишется в файл `logs/live_ГГГГММДД_ЧЧММСС.txt`.

| Событие | Смысл |
|---|---|
| `SPAWN` | струна создана: f0, длина, k, m, Z0 (импеданс), **omega·dt** (запас устойчивости схемы, должно быть < 1.0), **kc_max** (потолок жёсткости контакта) |
| `REJECT` | спавн/действие отклонено с причиной (слишком короткая, лимит струн, f0 вне диапазона) |
| `BOW` | смычок вкл/выкл: beta, скорость, прижим, **x0 = v_bow/v_f** — рабочая точка трения; `WARN` при x0 < 2 (залипание — это норма физики, не баг) |
| `CONTACT` | струны начали/закончили касаться |
| `EXCITE` | щипок (какой струне, где, сколько мм) |
| `GUARD` | сработала защита: клип скорости 60 м/с, **авто-заморозка** (какая струна и почему), зажатие параметров |
| `NAN` | NaN/Inf пойманы — струна обнулена (не падает!) |
| `PANIC` | аварийный сброс (кнопка или авто после 3×NaN за 5 с) |
| `XRUN` | симуляция не успевает (совет: OS=2, меньше струн, поставить numba) |
| `PARAM` / `RENDER` / `AUDIO` | изменения ручек, рендер WAV, устройство вывода |

**Диагностика «что за взрыв был у меня»**: теперь вместо взрыва струна
замораживается, а в логе — точная причина (какая струна, какой guard, сколько раз).
Смотри последние `GUARD`/`NAN` строки.

## Какие баги «bow live» здесь убиты (и почему)

1. **«Струна взрывалась на 0 значении»** — нулевой/бесконечный параметр физически
   недостижим: натяжение зажимается условием ω·dt < 1.0 (при спавне, с записью в лог),
   жёсткость и демпфер контакта капятся по устойчивости, скорость жёстко клипится
   (60 м/с), NaN-страж обнуляет мусор, авто-panic выключает всё при повторении.
2. **«Струны теряли места и натяжение»** — геометрия покоя фиксируется при спавне
   и никогда не меняется; натяжение меняет только жёсткость k (f0 → c → k), массы
   и позиции покоя остаются на месте. Смещения считаются ПОПЕРЁК оси от точного
   положения покоя — съехать физически некуда.
3. **«Постоянно кликали»** — контакт Hunt–Crossley: гладкая сила δ^1.5, строго F ≥ 0
   (никакого «прилипания» к барьеру), демпфер ограничен условием устойчивости,
   интегратор — полунеявный Эйлер с оверсэмплингом ×4. Щелчков нет.
4. **«Взрыв при добавлении 3-й струны»** — все струны живут в одном батч-массиве,
   каждая пара проверяется на устойчивость при создании, а при проблемах
   замораживается только виновник (остальные продолжают звучать). Проверено
   стресс-тестом: 8 струн вплотную + щипки по 8 мм — переживает, лог объясняет.
5. **«Непонятно из-за чего краш»** — журнал операций + guards (см. выше) +
   статус-бар (CPU, xruns, заморожено).

## Если что-то не так

- **Заикается звук** → ОВЕРСЭМПЛИНГ = 2; поставь numba; закрой тяжёлые вкладки; меньше струн.
- **Тихо/глухо** → громкость, зазор 0.5–2 мм (чтобы струны доставали друг друга),
  меньше Воздух σ.
- **Смычок «залип» (ровная линия, не играет)** → смотри x0 в логе BOW: нужно x0 > 2 —
  увеличь Regime R или Скорость ×. (Рабочая точка трения обязана быть на падающей
  ветви кривой — урок Этапа 0.)
- **Нет звука вообще** → в логе `AUDIO` будет причина (устройство занято/нет);
  проверь выбор устройства по умолчанию в системе.

## Перенос в C++ (Этап 2)

Этот файл — эталон поведения для `msd::core`:
`Engine._block_kernel` (JIT) → `msd::World::processBlock` 1:1 (та же математика),
guards → `msd::Guards`, лог событий → `diag::FlightRecorder`, `sched_params` →
`bow::RegimeMapper` (+guard x0 > 2), контакты → `collide::HuntCrossley`.
Формулы в коде помечены комментариями.
